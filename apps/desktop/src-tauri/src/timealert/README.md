# TimeAlert 백업·사진 이동

설정의 학교 자료에서 **사진 포함 이동·TimeAlert 백업**을 펼쳐 사용한다. 공통 JSON 복구는 사진 파일을 담지 않으며 이 기능은 암호화한 `.teacherbackup`에 저장 자료와 사진을 함께 담는다. 변환은 PC 안에서 처리한다.

## 사용 순서

1. 원작 TimeAlert v1 / DB7 백업을 가져와 암호를 확인한다. 표 구조와 사진을 검증한 뒤 명부·시간표 미리보기를 표시한다.
2. 기존 학생을 다음 학기에 연결하려면 대상 master를 직접 고른다. 이름이 같아도 자동 합치지 않는다. 확인한 자료 추가를 누르기 전에는 저장하지 않는다.
3. 원작 연결을 유지한 상태에서 사진 포함 백업 저장을 누르면 원작의 연락처·생일·메모·출결·상담 등 미편집 표도 함께 보존한다. 연결을 닫거나 앱을 종료한 뒤에는 다음 백업에 그 비공개 원작 기록이 포함되지 않는다. 저장된 공통 자료와 사진은 남는다.
4. 백업 저장은 현재 저장 자료만 사용한다. 화면의 미저장 초안은 포함하지 않으며 새 파일을 게시하고 원본을 덮어쓰지 않는다.

사진명렬표 XLSX는 별도 버튼에서 명부와 사진 대응을 함께 검토한다. 유일한 위치가 확인된 사진만 자동 선택한다. 겹친 사진·동명이인·위치가 불명확한 표는 직접 확인하고 사진을 선택한다. 기존 독립 사진 추출 도구도 사용할 수 있다.

## 정확한 지원 범위

- 원작 공식 DB7 / TIMEALERT v1 구조만 읽는다. Room 식별자뿐 아니라 모든 표·기본값·숨김/생성 열·외래키 대상/작용·인덱스 열/순서/고유성/부분 여부와 현재 데이터 무결성을 검사한다. 미래/구버전 DB와 구조가 변형된 입력은 거부한다.
- 실제 담긴 사진의 과거 절대 참조 경로는 출력 DB에서 basename으로 재배치하여 원작의 고정 photos 디렉터리에서 읽게 한다. 행 식별자·thumbnailVersion·source와 누락 사진 참조는 유지하고 원본 OS 경로를 열지 않는다.
- SQLite WAL의 정상 커밋을 snapshot DB에 접어 최신 기록을 보존한다. 출력 ZIP에는 WAL에 의존하지 않는 단일 DB를 담는다.
- 이름·학적·수업·주간표·수업 교시 시각·요일 대체·부분 일과 시작 교시·날짜를 넘긴 MOVE/CANCEL/ADD를 공통 자료로 투영한다. 쉬는 시간·점심·원작 사적 필드와 수업별 교실·표별 추가 설정은 원작 DB에 보존한다. 원작이 공통 자료 상한으로 표현되지 않으면 자르지 않고 거부한다.
- DB7에 대응 필드가 없는 날짜별 주간표 선택은 출력을 거부한다. 원작에 연결된 학생·학기·학적·수업·수업 학생 연결·일과·주간표·변경 기록 삭제도 역사 기록의 cascade 삭제를 막기 위해 거부한다. 요일 대체/임시 일과 중 한 종류의 취소는 해당 변경 행에 반영한다. 주간표와 담임 그룹의 사용자 지정 표시 이름은 원작 표현으로 돌아온다.
- 동시 원작 세션 하나, 사진 세션 하나다. 실패에는 재검토할 세션을 유지하며 성공한 적용은 반복하지 않는다. 선택기 대기 중 화면을 떠나 늦게 생성된 세션도 즉시 닫는다.

암호 UTF-8 1~1,024바이트, 백업512MiB, 실제 해제1GiB, 사진 한 장16MiB/합계256MiB이다. XLSX는32MiB·XML 합계16MiB·사진 대응1,000개 이하이다. 셸에는 원본 DB·OS 경로·사진 원본을 전달하지 않고 불투명 key·공통 자료·최대8KiB 사진 PNG 미리보기만 공개한다. 자세한 규범은 [계약](../../../../../docs/spec/timealert-portability.md)과 [ADR-0026](../../../../../docs/adr/0026-timealert-portability.md)을 따른다.

## 검증 한계

합성 데이터로 인증·구조·WAL·사진 왕복·명시적 학생 연결·revision 경합과 세션 수명을 검사했다. 원작과 동일한 JDK17 PBKDF2/AES-GCM API로 한국어·공백·보조평면 문자를 포함한 암호를 Java→Rust / Rust→Java 양방향 검증했다. 이는 Android 기기에서 Room 복원과 새 PC 이동을 끝냈다는 뜻이 아니다. 두 실기 검증과 전체 배포 검증은 별도 결과가 필요하다.
