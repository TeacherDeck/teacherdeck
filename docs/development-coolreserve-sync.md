# CoolReserve 원작 동기화와 실패 복구

TeacherDeck의 쿨 예약실 모듈은 검토한 CoolReserve 커밋의 소스를 그대로 소비해요. 원작 코어 ZIP과 모듈의 파일 목록·크기·SHA-256은 `tools/checks/coolreserve-source.allow.json`에 함께 기록해요. 원작 작업은 해당 저장소에서 먼저 커밋하고, 작업 트리가 깨끗한 상태에서 가져와요.

```powershell
pwsh -NoProfile -File tools/scripts/sync-coolreserve.ps1 -SourceCheckout D:/chatgpt_work/CoolReserve
pnpm gen
pnpm verify
```

동기화는 원작의 커밋된 파일을 읽어요. 경로·링크·기존 관리 파일의 해시를 먼저 검사하고, 같은 커밋의 ZIP이 있으면 내부 파일 목록과 바이트가 일치하는지 확인한 뒤 재사용해요. 모듈 파일을 교체하고 원작에서 삭제한 기존 관리 파일을 정리한 뒤 검증 목록을 마지막에 확정해요.

중간에 파일 잠금 등으로 실패하면 `vendor/coolreserve/.sync-state.json`에 진행 중인 커밋과 이전·새 검증 정보를 남겨요. 잠금을 풀고 **같은 원작 커밋으로 명령을 다시 실행**하면 완료해요. 성공하면 이 진행 기록을 제거해요. 미완료 상태에서는 `pnpm verify`가 실패할 수 있으므로 빌드·커밋하기 전에 동기화를 끝내세요. 복구용 진행 기록과 원작 ZIP을 임의로 삭제하지 마세요.

다른 커밋으로 바꿔 재실행하거나, 동기화 도중 모듈·검증 목록을 별도로 수정하면 복구를 중단해요. 원작이 삭제한 파일도 이전 검증 목록에 있고 기존 해시가 일치할 때만 지워요. 관리되지 않은 파일·로컬 수정 파일·링크는 보존하며, 해당 자료를 따로 옮기거나 이전 검증 상태로 복구한 뒤 진행해야 해요. `node_modules`·`dist` 같은 생성 폴더는 원작 소스와 구분해 유지해요.

같은 경로를 파일에서 폴더로, 또는 폴더에서 파일로 바꾸는 원작 변경은 자동 처리하지 않아요. 산출물을 게시하기 전 경로 충돌을 안내하고 중단하므로, 별도로 검토해 경로를 정리한 뒤 가져와야 해요.

이 절차는 개발 저장소의 원작 갱신이에요. 실행 중인 사용자의 메모·예약 자료·첨부 파일을 삭제하거나, 실제 쿨메신저 예약을 등록하지 않아요. 실제 메시징 검증 범위는 [ADR-0023](adr/0023-managed-messaging.md)과 [예약 메시징 명세](spec/messaging.md)를 따르세요.
