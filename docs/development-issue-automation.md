관리하고, 변경한 내용은 운영 보고에도 반영한다.

## 공동작업자의 사용 방법

1. 지정된 작성자가 새 이슈에 목표, 현재 문제, 원하는 결과와 완료 조건을 적는다.
   재현 절차나 관련 화면이 있으면 함께 첨부한다. 별도 라벨은 필요하지 않다.
2. 필요한 우선순위, 선행 작업, 보류 또는 취소를 이슈에 명시한다.
3. 자동화가 제출한 PR과 실제 검증 결과를 확인한다. 병합은 공동작업자가 수행한다.

기존 이슈 #12와 #15, 다른 작성자의 이슈, PR 자체와 운영 보고 이슈는 신규 구현
지시에서 제외한다. 자동화가 이미 시작한 작업의 미완료 항목과 같은 범위의 PR
피드백은 다음 실행에서 이어서 처리한다. 대상이 없는 날에는 새 일을 만들지 않는다.

## 한 번의 실행

1. 연결 계정, 저장소 접근, 이전 보고와 기존 작업 브랜치·PR을 확인한다.
   쓰기가 거부되면 결과를 제출한 것처럼 보고하지 않고 원인을 대화에 남긴다.
2. 최신 `main`, 작업 경로의 지침과 관련 규격을 읽는다.
   검색 결과뿐 아니라 개별 이슈의 작성자, 생성 시각, 상태와 최신 댓글을 확인한다.
   조회 한도가 있으면 페이지 또는 날짜 구간을 나눠 누락을 확인한다.
3. 보류·취소·다른 사람이 수행 중인 항목을 제외한다.
   명시한 우선순위가 없으면 오래된 미완료 작업부터 하나씩 처리한다.
4. 기본 브랜치 이름은 `codex/issue-<번호>`로 한다.
   같은 이슈의 기존 브랜치·PR을 재사용하고 다른 사람의 변경을 덮어쓰지 않는다.
5. 승인된 범위 안에서 구현하고 필요한 테스트·문서·버전·변경 기록을 갱신한다.
   판단이 필요한 사항은 이슈에 질문한 뒤 다른 진행 가능한 작업을 계속한다.
6. [검증 절차](spec/ci.md)에 따라 `pnpm verify`와 기존 Windows CI 결과를 확인한다.
   실패하거나 실행하지 못한 검사는 구분해서 기록한다.
   검증 전 결과는 Draft PR 또는 검증 대기 상태로 제출한다.
7. 이슈와 운영 보고에 실제 결과, PR·커밋, 검증 결과와 다음 작업을 남긴다.
   CI가 진행 중이면 실행을 무한히 기다리지 않고 다음 실행이 이어받게 한다.

정지 조건과 사람 승인은 [작업 절차](spec/process.md)를 따른다. 이미 받은 명확한
승인은 해당 범위에서 재사용한다. 미승인 변경을 임의로 진행하지 않는다.

## 제출과 이어받기

코드 제출은 연결된 GitHub 기능을 사용한다. 로컬 Git에 인증 정보가 자동으로
생긴다고 가정하지 않는다. 토큰이나 비밀번호를 문서·이슈·소스에 기록하지 않는다.

- 커밋은 Conventional Commits 형식과 확인된 작성자의 `Signed-off-by`를 사용한다.
- `main` 직접 push, 강제 push, 자동 병합, 릴리스와 배포는 수행하지 않는다.
- 원본 이슈는 자동으로 닫지 않는다. 병합 여부는 공동작업자가 결정한다.
- 임시 작업 공간이 유지된다고 가정하지 않는다. 실제 브랜치·PR과 운영 보고에서 재개한다.
- 같은 실행을 다시 이어갈 때는 기존 기록을 갱신하고 중복 PR·보고를 만들지 않는다.
- 새로운 유료 AI API, 별도 서버, 추가 결제나 자동충전을 도입하지 않는다.

일일 보고에는 다음 정보를 남긴다.

| 항목 | 내용 |
| --- | --- |
| 실행 | 한국시간 기준 실행일과 확인 시각 |
| 대상 | 검토한 신규·미완료 이슈, 제외·보류 이유 |
| 상태 | 완료, 검증 대기, 질문 대기, 보류 또는 미제출 |
| 결과 | 이슈별 브랜치, PR URL과 현재 커밋 |
| 검증 | 실제 실행한 검사와 결과, 미실행 사유, CI 링크 |
| 이어받기 | 마지막 처리 댓글과 남은 작업 |
| 주간 잔여 사용량 | 공식 조회 결과 또는 확인 불가 사유 |

여기서 완료는 필수 검증을 통과한 작업 결과를 뜻하며 PR 병합을 뜻하지 않는다.
동일한 인증·권한 실패를 설정 변경 없이 반복하지 않는다. 실행 한도에 도달하면
안전하게 보존한 결과와 미완료 상태를 기록하고 다음 실행에서 계속한다.

보고의 마지막 항목으로 사용량을 적는다. 공식 계정 조회 기능에서 실제 값을
읽을 수 있을 때만 잔여율, 초기화 시각, 확인 시각과 출처를 적는다.
정확한 잔여 토큰 수가 제공되지 않으면 토큰 수로 환산하지 않는다.
