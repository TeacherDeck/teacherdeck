# 키 보관 정책

> 이 문서에는 키 값, 패스프레이즈, 시크릿을 **절대** 적지 않는다(SEC-009). 정책과 절차만 적는다.

## 1. 키 종류

| 키 | 용도 | 공개키 위치 | 비고 |
|---|---|---|---|
| 업데이터 서명키 | Tauri updater 아티팩트 서명 | `tauri.conf.json` updater `pubkey` | **신뢰 루트**다. 모듈 공개키도 이 키로 서명된 앱 업데이트를 통해 배포된다. |
| 모듈 서명키 | 원격 카탈로그 `index.json.sig` 서명 | 앱에 내장(Rust 상수) | 업데이터 서명키와 분리한다. 원격 카탈로그 구현 시 사용(범위 밖). |
| Authenticode 인증서 | 설치본·실행 파일 코드 서명 | — | `TODO(human): SignPath` (범위 밖) |

두 서명키를 분리하는 이유: 모듈 카탈로그는 자주 갱신되므로 키 사용 빈도가 높다. 모듈 키가 유출되어도 앱 바이너리를 바꿀 수는 없게 하고, 새 모듈 공개키를 앱 업데이트로 교체해 복구할 수 있게 한다.

## 2. 생성

- 원저작자의 **개인 개발 PC**에서 `tauri signer generate`로 만들고 강한 패스프레이즈를 건다.
- 학교 PC, 공용 PC, CI에서 생성하지 않는다.
- 생성 직후 공개키만 레포에 반영하고, 개인키 파일은 레포 디렉터리 밖에 둔다.
- 현재 키: 2026-10-09 생성, minisign 키 ID `FF308F1839903C40`. 공개키는 `tauri.conf.json` `plugins.updater.pubkey`에 있다.

## 3. 운영 사본

- GitHub `release` environment 시크릿으로 등록한다.
  - `TAURI_SIGNING_PRIVATE_KEY`
  - `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`
- `release` environment는 main 브랜치와 `v*` 태그에서만 쓸 수 있게 제한하고, 필수 승인자를 지정한다(CI-004).

## 4. 백업

- 원저작자 2인이 **각자** 비밀번호 관리자에 암호화된 키 파일과 패스프레이즈를 보관한다.
- 오프라인 USB 1개를 추가로 둔다.
- 둘 중 누구 혼자서도 복구할 수 있어야 한다.

## 5. 계정 보호

- GitHub org에서 2FA를 강제한다.
- workflow·CODEOWNERS·Tauri ACL 변경은 CODEOWNERS 리뷰를 거친다(CI-006).

## 6. 회전 절차

1. 새 키 쌍을 만든다(2절).
2. 새 공개키를 담은 앱 버전을 **기존 키로 서명해** 배포한다.
3. 사용자 대부분이 업데이트한 뒤, 이후 릴리스부터 새 키로 서명한다.
4. 운영 사본(3절)과 백업(4절)을 새 키로 교체하고 기존 키를 폐기한다.
