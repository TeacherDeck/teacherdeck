# SEC-004 검증: 모듈 origin에서 Tauri IPC 접근 불가

SEC-004는 모듈 iframe(`http://deckmod.<id>.modules.localhost`)이 Tauri IPC에 닿을 수 없어야 한다고 요구한다. [ADR-0013](../adr/0013-module-origin-isolation.md) 이후 bare `http://deckmod.localhost`는 디버그 프로브 전용이다. 이 문서는 검증 절차와 이전 결과를 기록한다. 호스트나 Tauri 버전, `tauri.conf.json`, 커스텀 프로토콜을 바꾸면 다시 수행한다.

## 1. 방어 계층

1. **origin 분리**: 셸은 `http://tauri.localhost`, 각 모듈은 `http://deckmod.<id>.modules.localhost`다(`src-tauri/src/origins.rs`). 모듈은 셸 문서와 서로 다른 모듈의 DOM에 접근할 수 없다(교차 출처). 호스트는 정확한 authority/path id를 검증하고 브리지는 프레임별 source/origin을 확인한다.
2. **모듈 CSP** `connect-src 'self'`: 모듈은 `http://ipc.localhost`로 직접 요청할 수 없다.
3. **Tauri ACL**: `capabilities/main.json`은 `main` 창의 로컬 origin에만 명령 권한을 준다. `remote` 설정이 없다.
4. **Rust 권한 검사**: `host_invoke`는 호출 창이 `main`인지 확인하고, 모듈의 선언 캡을 매 호출마다 검사한다(CAP-008).

## 2. 자동 프로브 절차

디버그 빌드에만 들어 있는 프로브를 쓴다(`src-tauri/src/probe.rs`). 프로브는 bare 디버그 origin에서 IPC 접근을 시도하고 결과를 셸에 보고한다. 이 결과만으로 새 모듈 origin의 검증을 대신하지 않는다.

같은 실행에서 셸은 설치된 실행 가능 모듈 중 두 개의 독립 origin에 숨긴 합성 프로브도 연다. 호스트는 디버그 플래그가 켜진 경우에만 해당 모듈의 `/_probe/module.html`, `module.js`, `worker.js`, `data.json`을 제공한다. 실제 번들 entry HTML을 fetch하고, 같은 origin의 합성 JSON·Worker 및 sibling DOM·부모 DOM·IPC 차단을 검사한다. 데이터는 합성 marker뿐이며 사용자 storage/파일에는 접근하지 않는다. 셸은 알려진 iframe source와 정확한 origin만 수락하고 12초 안에 결과를 합쳐 기존 `sec-probe.json`에 기록한다.

```powershell
pnpm tauri build --debug --no-bundle
$env:DECK_SEC_PROBE = "1"
.\target\debug\teacherdeck.exe
# 몇 초 뒤 앱을 닫고 결과를 확인한다.
Get-Content "$env:LOCALAPPDATA\io.github.teacherdeck.deck\logs\sec-probe.json"
```

프로브가 확인하는 항목:

| 항목                                 | 기대값                             | 의미                                                      |
| ------------------------------------ | ---------------------------------- | --------------------------------------------------------- |
| `origin`                             | `http://deckmod.localhost`         | 디버그 프로브가 셸과 다른 origin에서 실행된다             |
| `tauriInternals` / `internalsInvoke` | `false`, 또는 호출이 실행되지 않음 | iframe에 IPC 객체가 없거나, 있어도 명령이 실행되지 않는다 |
| `parentAccess`                       | `blocked`                          | 셸 창 객체에 접근할 수 없다                               |
| `rawIpcFetch`                        | `blocked: ...`                     | CSP가 IPC 엔드포인트 직접 요청을 막는다                   |

독립 origin 결과는 같은 보고서의 `moduleIsolation` 배열에 들어 있다. `isolationComplete: true`는 두 모듈의 **보고 수신 완료**이며 각 항목의 통과 판정은 별도로 확인한다.

| 모듈별 항목                             | 기대값                                              |
| --------------------------------------- | --------------------------------------------------- |
| `origin`                                | 해당 모듈의 `http://deckmod.<id>.modules.localhost` |
| `bundleFetch` / `selfFetch` / `worker`  | 모두 `true`                                         |
| `siblingBlocked` / `siblingMarkerReads` | 2 이상 / 0                                          |
| `parentAccess`                          | `blocked`                                           |
| `internalsInvoke`                       | `allowed`가 아님                                    |
| `rawIpcFetch`                           | `blocked`                                           |

번들 fetch는 실제 번들 URL의 HTML 수신 증거다. UI 렌더·SDK 실행·파일 처리 증거를 대신하지 않는다. 실행 가능한 모듈이 둘 미만이거나 보고가 오지 않으면 완료로 판정하지 않는다.

추가 진단이 필요하면 `DECK_REMOTE_DEBUG=1`(디버그 빌드 전용)로 실행해 `http://127.0.0.1:9333`의 DevTools 프로토콜로 셸과 iframe을 각각 검사한다.

### 독립 모듈 origin 검증

1. keepAlive 도구 두 개를 열어 실제 iframe의 location.origin이 각각의 `http://deckmod.<id>.modules.localhost`인지 확인한다. 번들 자산·같은 origin fetch·worker가 정상 로드되는지 확인한다.
2. 한 모듈에서 `window.parent.frames`의 다른 모듈 window를 찾아 DOM 접근을 시도한다. 합성 marker만 사용하며 SecurityError로 거부돼야 한다. 셸 DOM 접근도 거부돼야 한다.
3. 실제 모듈 프레임에서 위 프로브의 IPC 객체 호출과 `http://ipc.localhost` POST를 실행한다. 타임아웃/거부와 CSP 차단을 확인하고 같은 세션에서 모듈의 host_invoke 실행 로그가 없는지 대조한다. 학생 자료/파일명/경로를 진단 출력에 넣지 않는다.
4. 다른 모듈 authority로 번들 경로를 요청해 host/path 불일치가 404인지 확인한다. 사용자 파일 리소스는 토큰의 소유 module authority만 수락해야 한다. 프로브·일반 모듈 권한을 열어 이 검사를 우회하지 않는다.

동등한 브라우저 sandbox 구조에서 same-origin sibling DOM 읽기는 2026-10-10 합성 fixture(`target/parallel-qa/isolation/`)로 재현됐다. 이것은 실제 Tauri 토큰 탈취 시험과 구분한다. 아래 2026-10-09 결과는 이전 단일 origin의 기록이며 독립 origin의 통과 증거가 아니다.

## 3. 최신 결과 — 창 ACL 변경 후 재검증

- 일시: 2026-10-10
- 환경: 현재 Windows PC, Tauri 2.12.1, 앱 0.1.1 디버그 빌드
- 변경: 자체 제목 표시줄용 창 권한 6개를 로컬 `main` 창에만 추가했다. 원격 origin 권한은 추가하지 않았다.
- 방법: 이전 실행본을 정상 종료하고 새 디버그 빌드를 `DECK_SEC_PROBE=1`로 실행했다. 새 보고서의 수정 시각과 응답하는 창을 확인한 뒤 정상 종료했다.
- 로컬 근거: `target/ux-sec-probe.json`, `target/ux-debug-build.log` (Git 제외)

| 모듈         | 실제 origin                                     | 번들·같은 origin fetch·Worker | sibling 접근 차단/표식 읽기 | 부모 DOM / IPC 객체 호출 / raw IPC |
| ------------ | ----------------------------------------------- | ----------------------------- | --------------------------- | ---------------------------------- |
| duty-planner | `http://deckmod.duty-planner.modules.localhost` | 모두 true                     | 2 / 0                       | blocked / rejected / blocked       |
| meeting-note | `http://deckmod.meeting-note.modules.localhost` | 모두 true                     | 2 / 0                       | blocked / rejected / blocked       |

`isolationComplete=true`이며 두 모듈의 개별 기대값을 모두 확인했다. bare 디버그 origin도 부모 DOM 접근과 raw IPC가 차단됐고 내부 invoke는 타임아웃으로 거절됐다. 이 프로브의 IPC 객체 호출은 기존 `shell_info` 명령을 대상으로 하며 새 창 명령 6개를 각각 실행한 검사는 아니다. 창 권한의 정확한 목록·로컬 `main` 범위·원격 권한 부재는 `shell-window-acl.test.ts`로 확인한다.

실제 마우스로 제목 표시줄을 드래그·더블클릭하거나 최소화·최대화·닫기 버튼을 누르는 검증은 남아 있다. 브라우저 컴포넌트 검사와 Windows 창 응답 확인은 이 수동 검증을 대신하지 않는다.

## 5. 이전 결과 — 단일 모듈 origin

- 일시: 2026-10-09
- 환경: Windows 11, WebView2 154, Tauri 2.12.1, 디버그 빌드(`tauri build --debug --no-bundle`)
- origin 실측: 셸 `http://tauri.localhost`, 모듈 `http://deckmod.localhost`(`origins.rs` 상수와 일치)

| 항목              | 결과                                                                                 | 판정 |
| ----------------- | ------------------------------------------------------------------------------------ | ---- |
| `origin`          | `http://deckmod.localhost`                                                           | 통과 |
| `parentAccess`    | `blocked`                                                                            | 통과 |
| `rawIpcFetch`     | `blocked: TypeError: Failed to fetch` (CSP `connect-src 'self'` 위반으로 차단)       | 통과 |
| `tauriInternals`  | `true` — 아래 참고                                                                   | 주의 |
| `internalsInvoke` | 응답 없음(3초 타임아웃). Tauri가 postMessage 경로로 재시도했지만 응답이 오지 않음    | 통과 |
| 호스트 로그       | 같은 세션에서 iframe의 `host_invoke` 호출은 실행 기록이 없음. 셸의 호출 1건만 기록됨 | 통과 |

**`tauriInternals: true`의 원인**: Tauri는 IPC 초기화 스크립트를 메인 프레임 전용으로 등록하지만, Windows WebView2는 문서 시작 스크립트를 모든 프레임에 주입한다. Tauri가 이 속성을 재정의 불가로 정의하고 앱 스크립트보다 먼저 실행하므로 모듈 프레임에서 제거할 수 없다. 따라서 모듈의 IPC 차단은 **Tauri ACL의 원격 origin 거부**(1절 3항)와 **모듈 CSP**(2항)가 담당한다.

**재검증 조건**: Tauri·WebView2 업데이트, `tauri.conf.json`·`capabilities/` 변경, 커스텀 프로토콜이나 origin 변경 시 이 절차를 다시 수행한다.
