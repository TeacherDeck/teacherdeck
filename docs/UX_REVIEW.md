# 기존 도구의 사용 흐름 복원

기준일: 2026-10-10. 이번 검토 범위는 현재 이식한 회의록·지도일 배정기와 이들이 사용하는 공통 UI예요.

## 확인한 문제

공통 컴포넌트를 사용하고 기술 규격을 지키는 것만으로 기존 사용성이 유지되지는 않았어요. 초기 이식은 설정과 설명을 앞세워 원본의 핵심 조작을 찾기 어렵게 만들었어요.

| 도구 | 원본에서 유지해야 할 흐름 | 초기 이식의 문제 | 수정 방향 |
|---|---|---|---|
| 회의록 | 참석자 입력 → 회의 시작 → 보이는 화자 목록과 단축키 → 연속 입력 | 참석자 설정이 접혀 있고 화자 선택이 드롭다운에 숨었어요. 기록 수정·내보내기 흐름도 부족했어요. | 시작 화면과 기록 화면을 나누고, 화자 버튼·단축키·입력창을 함께 보여 줘요. 기록 수정과 파일 내보내기를 연결해요. |
| 지도일 배정기 | 교사 명단 → 월별 달력 → 자동 배정 → 날짜별 직접 수정 | 날짜를 쉼표로 입력하고 여러 적용 버튼을 거쳐야 했어요. 달력이 아래로 밀렸어요. | 명단 추가와 달력을 앞에 놓고, 날짜 선택과 체크로 고정·제외를 지정해요. 담당자를 고르면 즉시 교체해요. |

회의록은 원본 `index.html`의 시작 화면, 화자 목록, 키보드 처리, 기록 편집, 내보내기 구현을 대조했어요. 배정기는 기존 Apps Script의 메뉴·교사 시트·달력 시트와 직접 편집 처리를 대조했어요. 배정기 원본 폴더에는 화면용 HTML이 없어 원본 화면을 직접 실행한 것으로 기록하지 않아요.

## 공동작업자의 규격 확인

- **언어와 구조:** Rust·Tauri 2 호스트, React·TypeScript 셸 및 웹 모듈 구조를 유지해요. 원본의 HTML·Apps Script 전체 실행환경을 앱에 덧붙이지 않아요.
- **디자인:** Fluent UI React v9 기반 `@deck/ui`, WinUI 이름의 컨트롤, 시스템 글꼴과 공통 토큰을 사용해요. 원본의 조작 순서를 살리면서 색·글꼴·입력 컨트롤은 티처덱 기준으로 맞춰요.
- **모듈 경계:** 모듈은 SDK와 브리지를 통해 저장·파일 기능을 사용해요. 모듈에 Tauri 호출이나 원본 웹 저장소를 직접 가져오지 않아요.
- **공통 UI 보완:** SettingsExpander 머리글을 키보드로 조작할 수 있는 버튼으로 바꾸고, TextBox에 기본 표시 행 수를 지정할 수 있게 했어요.

관련 기준은 [디자인 시스템](spec/design-system.md), [모듈 규격](spec/modules.md), [ADR-0001](adr/0001-app-shell.md), [ADR-0011](adr/0011-winui-aligned-deck-ui.md)이에요.

## 이후 이식에서 지킬 절차

1. 원본의 실제 시작 화면과 가장 자주 쓰는 작업 순서를 먼저 확인해요.
2. 반드시 유지할 조작·단축키·파일 양식을 적고, 이를 회귀 테스트와 화면 검증의 기준으로 삼아요.
3. 화면의 색과 공통 컨트롤을 통일하되, 핵심 동작을 설정 패널이나 추가 확인 단계 뒤로 옮기지 않아요.
4. 실제 입력부터 결과 확인까지 조작해 보고, 좁은 창·밝은/어두운 테마·확대 글자도 확인해요.
5. 검증하지 않은 원본 기능은 구현 완료로 표시하지 않아요. 검증 범위와 남은 차이는 각 모듈 README에 남겨요.

최종 테스트·화면 검증·Windows 빌드 결과와 한계는 [개발 현황](DEVELOPMENT_STATUS.md)에 기록해요.
