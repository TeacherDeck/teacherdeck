# 기본 앱·기본 모듈 디자인 개선 계획

작성일: 2026-10-11. 현재 상태: 승인된 일곱 화면·공통 셸·20개 아이콘에 적용했고 전체 자동 검증을 통과했다. 화면 근거와 실기 한계는 [검수 기록](../reviews/design-improvements-2026-10-11.md)에 있다.

목표는 ‘티처덱을 열면 필요한 도구를 바로 찾고, 한 번 익힌 조작을 다음 도구에서도 쓰는 것’이다. 공동작업자의 Fluent v9·WinUI·Mica 기반을 유지한다. 개별 화면 개선은 [일곱 항목 계획](design-improvements-2026-10-11.md), 결정은 [ADR-0029](../adr/0029-compact-tool-workspaces.md), 규범은 [디자인 시스템](../spec/design-system.md)에 연결한다.

## 1. 기본 앱

| 영역 | 적용 내용 | 확인 기준 |
|---|---|---|
| 홈 | 검색 위치 유지, 즐겨찾기는 짧은 실행 목록, 전체 도구는 작은 카드와 두 줄 설명 | Ctrl+F·별·카테고리 유지, 같은 창에서 노출되는 도구 수 비교 |
| 도구 정보 | 아이콘·이름·버전·호환 상태를 작은 정보 행에 배치, 작업 제목은 모듈 h1 | 정보가 잘리지 않고 iframe 작업 높이가 늘어남 |
| 내비게이션 | 기존 뒤로·Alt+←·도구에서 레일 숨김 유지 | 도구 복귀 때 입력과 keepAlive iframe 보존 |
| 설정 | 기존 SettingsGroup/Card/Expander를 기준으로 기본 설정·학교 자료·백업의 제목과 설명을 일관되게 유지 | 같은 동작의 용어와 저장 상태 일치. 기존 데이터 관리 기능을 디자인 변경으로 재구현하지 않음 |
| 오류·진행 | 진행은 실행 옆, 오류는 닫힌 설정 밖, 완료는 결과 옆 | 색 외에 문구·기호 제공, 실패 뒤 재시도/다음 행동 확인 |

## 2. 아이콘

20개 기본 도구의 아이콘을 동일한 48×48 좌표, 파란 바탕, 흰 선, 일정한 안쪽 여백으로 정리한다. 실제 홈에서는 32px, 짧은 즐겨찾기와 정보 행에서는 더 작은 크기로 확인한다. 색을 늘리는 대신 기능을 나타내는 그림을 바꾼다. 의미 색(휴일·경고·오류)은 UI 토큰으로 따로 표현한다.

| 도구 | 그림의 의미 |
|---|---|
| 퀵캡처 / 이미지 크롭 | 고정 영역과 촬영점 / 겹친 자르기 모서리 |
| 사진 추출 / 이미지 압축 | 인물 사진과 밖으로 나오는 화살표 / 산 모양과 안으로 모이는 화살표 |
| 파일명 정리 / 문서 형식 변환 | 이름표와 입력 커서 / 문서 사이 이동 화살표 |
| PDF 마스킹 / PDF 압축 | 문서의 가림 막대 / 문서와 압축 화살표 |
| 회의록 / 빠른 메모 | 발언 말풍선과 기록 / 접힌 메모지 |
| 지도일배정기 / D-day | 체크한 달력 / 날짜와 목표 지점 |
| 자리 / 모둠 / 발표 / 역할 | 교실 책상 / 연결된 사람 / 발표대 / 역할 체크 목록 |
| 네트워크 / 쿨 예약실 | 연결된 PC / 시계가 붙은 말풍선 |
| 타이머 / QR | 초시계 / 세 개의 QR 위치 표시 |

모듈의 `icon.svg`를 그대로 카탈로그·설치본에 포함한다. 원격 모듈도 자신의 아이콘으로 표시되므로 셸에 도구별 예외를 만들지 않는다. 누락·로드 실패 시 카테고리 아이콘으로 돌아간다. 신규 모듈은 템플릿 사각형을 출시 아이콘으로 남기지 않는다. 아이콘만으로 버튼 의미를 전달하지 않고 이름을 함께 보여 준다.

## 3. 기본 모듈의 공통 골격

| 작업 종류 | 기본 배치 | 적용 예 |
|---|---|---|
| 파일 일괄 처리 | 입력 → 옵션 → 미리보기 → 실행 → 결과. 파일 추가 후 입력 면적 축소, 결과는 실제 결과가 있을 때 표시 | 파일명 정리·문서 변환. 나머지 파일 도구도 향후 기능 변경 시 같은 기준으로 점검 |
| 계속 실행 | 주 실행·현재 상태·저장 위치를 먼저, 덜 쓰는 설정은 접기 | 퀵캡처·타이머 |
| 기록 | 입력·현재 대상·최근 기록 우선, 지난 기록 관리와 백업은 보조 | 회의록·메모 |
| 배정·편집 | 첫 사용은 자료 준비, 이후 결과와 직접 편집 우선. 자동 배정 조건은 접기 | 지도일·자리·모둠·역할 |

공통 `PageHeader`, `ToolLayout`, `SettingsExpander`, `InfoBar`, `ListView`, `ContentDialog`를 조합한다. 같은 역할의 컨트롤을 모듈 내부에 다시 만들지 않는다. 현재 컴포넌트 API로 이번 일곱 개선을 구현할 수 있으므로 새 라이브러리나 공통 컨트롤을 추가하지 않는다.

## 4. 색·글자·스크롤·키보드

- 제목은 Subtitle 20/26, 본문은 Body, 보조 메타데이터는 Caption으로 역할을 구분한다. 긴 이름은 줄바꿈하며 버튼을 글자 위에 겹치지 않는다.
- 휴일·일요일은 빨강, 토요일은 파랑, 선택은 브랜드, 성공/경고/오류는 해당 의미 토큰을 쓴다. 휴일명·선택·고정 기호·성공 문구를 함께 표시한다.
- 기본은 페이지 스크롤 하나다. 긴 파일 목록·회의 기록만 별도 스크롤을 허용한다. 실행·닫기·현재 입력이 접근 불가능해지지 않게 확인한다.
- 화면 변경은 탭 순서를 따라가고, 대화상자를 닫으면 원래 컨트롤로 돌아간다. 회의록의 화자·IME, 메모의 Ctrl+Enter, 캡처의 반복 단축키는 별도 회귀 항목이다.

## 5. 적용 순서와 검수

이번 적용은 홈·정보 행·20개 아이콘과 기존 일곱 항목(파일명, 문서 변환, 지도일, 캡처, 홈, 메모, 회의록)을 함께 통합한다. 설정/학교 자료의 대대적인 재배치와 나머지 도구의 기능 재기획은 이 변경에 섞지 않으며, 위 공통 기준을 다음 작업의 출발점으로 사용한다.

동일 합성 자료로 1280×720·1024×768·800×600, 라이트·다크, 텍스트 150%·CSS 200%에서 렌더와 키보드 동작을 점검한다. CSS 확대를 Windows DPI 실기 검증이라고 보고하지 않는다. 캡처 투명도·실제 저장 픽셀·OS 단축키처럼 브라우저로 확인할 수 없는 것은 별도 실기 검수로 기록한다. 단위 테스트와 `pnpm verify`, 설치본 빌드를 통과시킨 뒤 항목별 결과를 검수 문서에 남긴다.
