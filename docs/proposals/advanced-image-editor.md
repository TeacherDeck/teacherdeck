# 고급 이미지 편집 — 기능 명세와 구현 계획

상태: 2026-10-12 사용자와 기능 범위를 합의한 뒤 "구현을 시작해보라"는 지시에 따라 첫 버전을 구현했다. 아래는 구현 기준과 지원 범위다. 8절의 한정 고지 추가와 미저장 작업 보호를 함께 구현했으며, 정확한 계약은 ADR-0030과 spec에 정의했다. 검증 결과와 남은 실기 범위는 [구현 검수 기록](../reviews/advanced-image-editor-2026-10-12.md)에 기록한다.

## 1. 제품 결정

- 기존 **이미지 자르기**(`modules/image-crop/**`)의 코드·ID·버전·문서·동작을 보존한다.
- 별도 **고급 이미지 편집** 모듈을 `advanced-image-editor` ID로 만든다. 생성은 `pnpm new:module`을 사용한다.
- 대상 작업은 사진 보정, 여러 이미지 합성, 간단한 그림·표시, 수동 누끼, 기본 PSD 편집이다.
- 한 번에 문서 하나를 편집한다. 여러 이미지는 해당 문서의 레이어로 추가한다.
- 모든 처리와 작업 파일은 로컬에 둔다. 외부 이미지 URL 열기, 서버 업로드, 원격 모델 다운로드는 없다.

사용자가 명시한 요구: 크롭·회전·수평/원근 보정, 명도·대비·레벨·곡선, 전체 RGB와 R/G/B 개별 보정, 글자·화살표·사각형, 레이어·브러시·지우개, 수동/색상 선택 누끼, 기본 PSD 레이어 읽기·편집·저장, 기존 및 새 텍스트의 내용 수정. AI 자동 누끼와 Photoshop 전체 호환은 요구 범위가 아니다.

현재 레이어와 조작 대상(이미지/마스크)을 항상 보인다. 사진 색보정은 글자·도형 레이어에 적용하지 않는다. 글자·도형에 브러시·지우개·원근을 쓰려면 픽셀화 선택을 거치고, 실행 취소로 원래 속성을 복원할 수 있어야 한다. 아래 레이어와 병합은 전체 합성 결과가 보존되는 조합만 허용한다. Multiply/Screen이 다른 아래 레이어에 의존하는 경우 단순히 두 레이어를 Normal로 합치지 않는다. 병합 시 글자·도형의 픽셀화를 알리고 이력에 원본 속성을 남긴다.

복잡한 기능 중 마스크와 자체 작업 파일은 포함한다. 누끼의 복원과 글자 재편집을 유지하는 데 필요하기 때문이다. 전체 Photoshop 조정 레이어·스마트 오브젝트·필터 체계는 추가하지 않는다.

## 3. PSD 호환 계약

`ag-psd`는 구조와 픽셀을 읽고 쓰는 코덱이다. 앱이 레이어 합성·텍스트 배치·전체 미리보기를 생성해야 한다. PSD 파일이 파싱된다는 사실만으로 시각적 호환을 보증하지 않는다.

| PSD 항목                                                         | 처리                                                                                                                                      |
| ---------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 8-bit RGB의 기본 픽셀 레이어                                     | 이름·순서·위치·표시·불투명도·지원 혼합 모드를 가져오고 내보낸다                                                                           |
| 단순 가로쓰기 텍스트                                             | 단일 스타일·지원 변환이면 편집 가능한 텍스트 레이어로 가져온다. 글자 내용·기본 서식·레이어 픽셀을 함께 저장하는 PSD 출력을 구현·검증한다  |
| 복잡한 텍스트                                                    | 내용 추출 가능 시 단일 스타일 텍스트로 바꾸는 미리보기를 제공하고 사용자가 선택한다. 무단 픽셀화나 완전한 서식 보존을 약속하지 않는다     |
| 글꼴 없음                                                        | 대체 글꼴과 배치 변화 가능성을 표시하고 사용자가 고른다. 글꼴을 자동 다운로드하지 않는다                                                  |
| 기본 픽셀 마스크                                                 | 위치·기본값·활성 여부 등 구현한 계약을 검증한 경우만 독립 마스크로 가져온다                                                               |
| 지원하지 않는 그룹·조정 레이어·클리핑·효과·스마트 객체 등이 있음 | 저장된 전체 합성 이미지가 있으면 한 이미지로 열기를 선택할 수 있다. 지원하지 않는 항목을 무시한 채 레이어 합성을 정답처럼 보여주지 않는다 |
| 전체 합성 이미지도 없거나 손상됨                                 | 지원하지 않는 이유를 알리고 거절한다                                                                                                      |
| PSB·CMYK/Lab·16/32-bit 등                                        | 첫 버전 제품 범위에서 제외한다. 이는 라이브러리 전체 기능의 한계를 뜻하지 않는다                                                          |

마스크·효과가 없고 불투명도 100%인 단순 pass-through 그룹은 폴더 구조를 평면 목록으로 펼치는 변환을 안내한 뒤 자식의 순서·최종 표시 상태·텍스트 속성을 유지할 수 있다. 그룹 편집 UI는 추가하지 않는다. 그 외 그룹은 복잡 PSD 경로를 따른다.

Photoshop의 복잡한 서식·효과 왕복은 보증하지 않는다. 지원 범위 밖 변환은 열기/내보내기 전에 알린다. 한 이미지로 가져오는 선택지에는 기존 글자·레이어의 개별 편집이 불가능하다고 명시한다. 이 경로를 PSD 레이어/텍스트 편집 수용시험의 성공으로 계산하지 않는다. PSD 출력에는 갱신된 전체 composite와 레이어 픽셀을 반드시 포함한다. 화살표·사각형은 PSD에서는 개별 픽셀 레이어로 저장한다. 단순 텍스트의 편집 가능 출력은 수용 시험 항목이며, 실패하면 조용히 픽셀화해 완료 처리하지 않는다.

작업 저장은 `.deckimage`를 사용한다. 버전이 붙은 JSON과 **보정 전 기준 픽셀**, 독립 마스크, 변환·보정값, 텍스트·도형 원본 속성을 ZIP에 담는다. 브러시·지우개는 선택 픽셀 레이어의 기준 픽셀을 바꾸고, 마스크 도구는 독립 마스크만 바꾼다. 표시 결과를 기준 픽셀로 저장한 뒤 보정값을 다시 적용하지 않는다. 텍스트·도형 표시 캐시는 선택 사항이며 원본 속성으로 재생성할 수 있어야 한다. 실행 취소 전체와 임시 캐시는 저장하지 않는다. PSD는 교환용, PNG/JPG는 최종 이미지용이며 손실 있는 내보내기만으로 작업 전체가 저장됐다고 표시하지 않는다. 같은 작업 파일을 다시 열어 모든 지원 속성을 수정할 수 있어야 한다.

## 4. 채택할 코드 원천과 의존성

기준일 2026-10-12. 실제 반입 목록·파일 해시·전이 고지를 고정했다. 아래 세 원천을 제품에 사용한다. 여기의 버전은 Photoshop 실기나 학교 PC 성능 검증이 완료됐다는 뜻이 아니다.

| 역할             | 선택                                                               | 반입 방식                                                                         |
| ---------------- | ------------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| 래스터 편집 기반 | **Klecks**, MIT, commit `7b1d4744b648de6133b0d45073af4efd2f998148` | 필요한 소스와 의존 헬퍼를 모듈 내부로 선별 이식                                   |
| PSD 입출력       | **ag-psd 31.0.3**, MIT                                             | 모듈 런타임 의존성. 확인한 소스 commit `04d927df87130ad6d765bc63d51ade0a98d66c14` |
| 작업 파일 ZIP    | **fflate 0.8.3**, MIT                                              | 레포 다른 모듈에서도 사용 중인 같은 버전을 새 모듈에 선언                         |

Klecks는 npm으로 넣을 독립 headless 엔진이 아니다. `kl-canvas`, 브러시, 이력, BB 유틸리티와 선택/행렬 헬퍼 사이의 연결을 떼어내는 이식 작업이 필요하다. 선택한 원천 코드의 상태와 새 어댑터를 한 문서 모델에 통합하고, 다른 scene graph나 별도 undo 엔진을 겹쳐 만들지 않는다.

기획 단계에서 검토한 Klecks 경로는 다음과 같다. 실제 반입은 이 절 아래의 구현 범위에 명시한 세 부분으로 좁혔다.

- `src/app/script/klecks/canvas/`: 레이어 캔버스와 합성에 필요한 부분.
- `src/app/script/klecks/brushes/pen-brush.ts`, `eraser-brush.ts`와 필수 획/타일 헬퍼.
- `src/app/script/klecks/history/`: 변경된 픽셀 타일과 속성 이력.
- `src/app/script/klecks/image-operations/flood-fill.ts`: 색상 선택.
- `src/app/script/klecks/image-operations/render-text.ts`, `shape-tool.ts`: 텍스트·도형의 표시용 픽셀 생성.
- `src/app/script/fx-canvas/`: 필요한 명도·대비·곡선·원근 계산. 관련된 원래 glfx 고지도 유지.

Klecks 자체 UI·아이콘·브랜딩·IndexedDB·서비스 워커·웹 글꼴·독자 파일 입출력은 이식하지 않는다. 원천 PSD 어댑터는 마스크를 픽셀에 합치고 조정 레이어를 건너뛰므로 그대로 사용하지 않는다. TeacherDeck의 위 PSD 계약에 맞는 어댑터를 둔다.

Klecks의 글자 렌더러는 글자를 바로 픽셀로 그리며, 레이어 타입에 영속적인 글자 속성이나 독립 마스크가 없다. **글자/도형 속성 + 표시용 캐시**, **마스크 + 합성 + 이력**이 필요한 핵심 확장이다. 이를 upstream이 이미 제공한다고 설명하지 않는다.

별도 Fabric·Konva·miniPaint·Cropper·glfx·magic-wand 런타임은 추가하지 않는다. 같은 역할의 엔진을 중복 도입하지 않는다. AI 런타임·모델과 범용 플러그인 체계도 제외한다.

라이선스 확인 사항:

- `ag-psd` 자체 코드는 MIT지만 저장소의 이미지·브러시 자산은 그 라이선스에서 제외된다. 테스트에는 자체 합성 자료를 쓴다.
- 직접 하위 의존성 `base64-js`는 MIT, `pako 2.1.0`은 `MIT AND Zlib`다. MIT 코드 기반이라는 말과 모든 전이 코드가 MIT라는 말은 구분한다. 기존 allowlist는 Zlib도 허용한다.
- 기존 glfx의 곡선 보간 파일에는 Paint.NET 유래 주석이 있다. Klecks 이식본에서도 출처 사슬을 확인한다. 해당 파일의 고지가 확정되지 않으면 반입하지 않는다. 같은 곡선 계약을 유지하는 출처 명확한 구현으로 좁혀 교체하며, 이를 이유로 고지를 제거하거나 라이선스 검사를 완화하지 않는다.
- 실제 반입 소스와 의존 폐쇄의 원문 고지는 확정했고, public·dist·staging·`.deckmod`의 고지를 바이트 단위로 대조한다. 추가 후보를 나중에 반입하려면 그 파일의 출처와 고지를 다시 확인한다.

## 5. 기존 코드 계승과 최소 구조

기존 `image-crop`에서 정지 이미지/크기 검사, SDK 파일 읽기, 출력 폴더·이름 충돌 처리, 순수 좌표/경계 계산과 합성 테스트 사례를 필요한 만큼 계승한다. 새 모듈 생성 후 내부 파일로 이식하며 기존 저자와 출처를 유지한다. 다른 모듈의 내부 경로를 import하지 않는다.

기존 다중 사진 목록 UI, 단일 사진 `Edit` 모델, 매 요청 Worker를 생성하는 흐름은 고급 모듈에 그대로 복제하지 않는다. 기존 모듈을 공통화하려고 수정하거나 새 범용 이미지 패키지를 먼저 만들지 않는다.

구성은 다음 네 부분으로 제한한다.

1. 문서/레이어 모델과 이력: 픽셀·글자·도형 레이어, 사진 마스크, 속성 변경과 타일 변경.
2. 렌더러와 도구: 단일 합성 경로, 선택과 좌표 변환, 브러시 즉시 표시.
3. 파일 어댑터: SDK 읽기/쓰기, 일반 이미지, PSD, 작업 파일.
4. `@deck/ui` 화면: 도구·옵션·레이어 목록과 키보드 조작.

색보정 순서는 명도/대비 → 레벨 → 전체 RGB 곡선 → 개별 RGB 곡선으로 고정한다. 전체 RGB 곡선은 같은 매핑을 R/G/B에 적용한다는 뜻이며 지각적 휘도만 보정한다고 표시하지 않는다. 변환과 마스크는 레이어 좌표를 기준으로 하며 함께 이동한다. 문서 크롭·리사이즈는 모든 레이어와 마스크에 일관되게 반영한다.

## 6. 성능과 자원 예산

무거운 PSD 파싱·인코딩, 원근 변환·픽셀 LUT는 Worker로 분리한다. 선택/히트테스트/브러시의 즉시 반응은 원천 엔진에 맞는 경로를 사용한다. 모든 Canvas 코드를 Worker로 다시 쓰는 것 자체를 목표로 삼지 않는다. 기본 기능은 WebGL 비활성 환경에서도 동작하도록 CPU 경로를 둔다. GPU 가속의 추가 범위는 실제 병목 확인 뒤 결정한다.

축소 미리보기와 원본 출력은 동일한 좌표·보정 규칙을 쓴다. 연속 입력은 최신 작업만 화면에 반영하고 이전 결과를 폐기한다. 출력은 원본 해상도를 사용하며 한도 초과 시 임의로 축소하지 않는다.

출발점으로 문서 24MP/한 변 10,000px, 레이어 16개, 이력 64MiB의 상한을 둔다. 이 숫자는 제품 성능 검증 결과가 아니라 첫 기술 검증의 가안이다. 특히 24MP 레이어 16개를 동시에 허용한다는 뜻이 아니다. 디코딩 원본·레이어·마스크·PSD 버퍼·이력·출력 임시 버퍼의 **총 관리 바이트 예산**을 먼저 계산하고 할당 전에 검사한다. 실제 학교 PC/WebView 기준 측정으로 파일 크기와 총 픽셀 예산을 확정한 뒤 명세를 갱신한다.

숫자 설정과 레이어 순서는 작은 속성 기록으로, 브러시·지우개·마스크는 바뀐 타일만 기록한다. 기존 Klecks 이력 구현에도 기록 추가 순간 한도 초과 가능성이 있으므로 사전 메모리 예약을 보완한다. 최신 한 작업조차 이력에 안전하게 담을 수 없으면 시작 전에 거절하고 사유를 알린다. 되돌릴 수 있다고 표시한 작업을 몰래 되돌릴 수 없게 처리하지 않는다.

PSD/ZIP은 파일 바이트만 보지 않고 문서 크기·레이어/엔트리 수·압축 해제 크기를 검사한다. 임의 경로 추출은 하지 않는다. 종료·새 문서·취소 때 Canvas, ImageBitmap, Object URL, Worker, SDK 핸들을 정리한다.

성능 시험의 첫 기준 장비는 4개 논리 코어·8GiB RAM·내장 그래픽의 Windows/WebView2로 잡는다. 3,000×2,000 문서, 사진 3개와 글자/도형 3개의 합성 자료에서 획 표시 지연 p95 50ms 이내, 축소 보정 미리보기 p95 150ms 이내, 긴 처리의 취소 반응 1초 이내를 목표로 측정한다. 이는 현재 달성한 성능이 아니다. 첫 실험에서 미달하면 원인을 확인해 캐시·작업 분할을 보완하고, 달성하지 못한 목표는 결과와 함께 보고한다.

## 7. 화면과 작업 보존

왼쪽은 도구, 중앙은 캔버스, 오른쪽은 현재 도구 설정과 레이어 목록, 상단은 열기·작업 저장·내보내기·실행 취소로 구성한다. 기존 Fluent 토큰과 `@deck/ui`를 따른다. 필요한 Slider·곡선·Canvas/Thumb 기반 편집 표면은 공통 UI에 추가하고 갤러리와 키보드 대체 조작을 포함한다.

작업 파일 저장을 완료한 revision을 기준으로 변경 여부를 계산한다. 저장 중 추가 편집이 있었다면 저장 완료 후에도 미저장 표시를 유지한다. 저장 실패·취소는 미저장 상태를 해제하지 않는다.

현재 `keepAlive:true`는 최대 3개 LRU 유지일 뿐이며 iframe 제거를 막지 않는다. storage의 값 256KiB/모듈 5MiB도 레이어 작업 보관 용도로 부족하다. 따라서 keepAlive나 localStorage/IndexedDB를 이용해 작업 보존 문제를 우회하지 않는다. 명시적 작업 파일 저장과 아래 미저장 작업 보호를 첫 버전 완료 조건으로 둔다. 충돌/강제 종료 후 자동복구는 첫 버전에서 보증하지 않는다.

## 8. 승인 대상 제안

### 제안: 선택한 MIT 소스의 한정 반입과 고지

- 정지 조건: GEN-005의 라이선스·저작자 고지 파일 변경. `packages/*`에 새 런타임 의존성이 필요해지면 GEN-004를 별도로 적용한다.
- 배경: 래스터 엔진과 PSD를 재사용하면서 원래 저자·라이선스·이식 변경 내역을 보존해야 한다.
- 제안: 4절의 소스/패키지에 한해 모듈 내부 반입 목록과 원문 고지·SHA-256·소스 commit·변경 내역을 기록하고 번들에 포함한다. `ag-psd`의 비MIT 샘플 자산은 반입하지 않는다. 고지는 이식된 파일들의 최종 목록과 함께 검토 가능하게 만든다.
- 검토한 대안: 완성 편집기 UI 삽입은 공통 UI 규칙과 맞지 않으며, 전부 자체 구현은 사용자 재사용 요구와 개발 효율에 맞지 않는다.
- 영향: 앱/기존 모듈의 라이선스·저자 표기는 유지한다. 하위 MIT/Zlib 고지를 함께 보존한다. 모듈 고지는 현 About 생성기가 자동으로 모두 수집한다고 가정하지 않는다. 생성물은 손으로 수정하지 않는다.
- 필요한 승인: 최종 반입 파일 목록과 그에 대응하는 고지 추가. 소스 도입 요청 자체는 사용자 요구에 포함되며, 미확정 파일을 포괄 승인된 것으로 간주하지 않는다.

### 제안: 미저장 문서의 이탈·언로드·종료 보호

- 정지 조건: 공개 캡/이벤트 계약과 모듈 생명주기 규격 변경(DOC-002). 새 이벤트 추가는 BRG-009에 따른 spec 변경이다.
- 배경: 기존 keepAlive LRU에서 편집기를 제거하면 미저장 레이어·글자·브러시 작업을 잃을 수 있다.
- 제안: 기존 `window` 캡의 호환 가능한 minor 확장으로 미저장/저장 중 상태를 세션에 등록하고, 셸이 도구 이탈·LRU 언로드·앱 종료 전에 저장/버리기/취소를 중재한다. 첫 편집 전에 보호 등록을 완료한다. 제목바와 Alt+F4 외에 트레이 종료·업데이트 재시작도 같은 중재를 거치고, 캡처 활성 시 닫기를 숨김으로 처리하는 기존 동작을 보존한다. 정확한 메서드/이벤트 타입은 전용 ADR에서 고정한다. `deck:1` envelope 형식은 유지한다.
- 검토한 대안: keepAlive만 켜기는 수명을 보증하지 못한다. 이미지 storage 저장은 용량에 맞지 않는다. 별도 복구 파일 서비스나 모든 모듈 무기한 유지보다 저장 확인이 범위가 작다.
- 영향: 내용·파일 경로는 상태 메시지로 보내지 않는다. 상태는 iframe의 검증된 모듈·세션으로 귀속한다. dirty 모듈은 조용히 LRU에서 제거하지 않으며 한도 도달 시 저장 확인으로 해결한다. 저장 응답을 기다리는 동안 iframe을 유지한다. 응답 실패·시간 초과면 종료/언로드를 기본 취소한다. 무한한 메모리 고정이나 자동 원본 덮어쓰기를 허용하지 않는다.
- 필요한 승인: 미저장 작업 보호의 cap minor·이벤트·셸 중재 계약. 승인 전 임의 postMessage 이벤트, 하드코딩한 모듈 예외, CSP/ACL 완화로 구현하지 않는다.

필수 수용 시험:

- 기존 `modules/image-crop/**`의 이번 작업 diff가 없고 기존 도구 회귀 시험 통과.

- 브러시 한 획, 마스크 복원, 글자 내용 변경, 레이어 삭제/병합의 undo/redo 일치.

- 복잡 PSD의 저장 composite 경로와 composite 없음의 거절, 압축 해제/총 픽셀/메모리 상한.
- 연속 슬라이더 조작, 큰 획, 레이어 증가, PSD 출력 중 취소, WebGL 비활성 환경.
- 키보드만으로 도구/곡선/꼭짓점/마스크 편집, 150% 글자·200% DPI, 실제 WebView2 출력 재열기.
- 원본 해시 불변, 이름 충돌 시 새 파일, 저장 실패 시 dirty 유지, LRU 및 종료 취소. 제목바·Alt+F4·트레이 종료·업데이트 재시작·캡처 활성 중 닫기를 각각 확인.

2026-10-12 사용자의 "모델을 sol로 바꾸었다. 구현을 시작해보라" 지시에 따라 구현을 시작했다. 앞 절의 모듈별 고지 추가와 미저장 문서 보호 제안을 구현 범위로 삼았다. 검증되지 않은 성능·PSD 호환성을 완료된 기능으로 표시하지 않는다.

### 구현에서 좁힌 반입 범위

Klecks의 전체 Canvas/PenBrush는 BB·Bezier·기존 이력·선택 경로를 함께 가져와야 하므로 첫 버전에서 반입하지 않았다. 실제 계승 파일은 flood-fill, render-text, changed-tiles 세 부분이다. 정확한 원문·변경 내역·commit·SHA-256은 [반입 기록](../../modules/advanced-image-editor/vendor/README.md)과 `adoption-manifest.json`에 있다. 독립 마스크, 편집 가능한 텍스트 속성, 통합 이력, 단순 원형 브러시와 LUT/원근 어댑터는 이를 연결하는 새 코드다.

polygon-clipping·transformation-matrix는 선택 영역을 래스터 마스크로 유지하고 소규모 좌표 계산을 통합하여 필요하지 않아 설치하지 않았다. glfx의 출처가 불확실한 곡선 보간 파일도 반입하지 않았다. 런타임으로 추가한 코덱은 ag-psd 31.0.3과 fflate 0.8.3이며 전이 MIT/Zlib 원문은 모듈 화면과 `.deckmod`의 `THIRD-PARTY-NOTICES.txt`로 제공한다.

미저장 보호 계약은 [ADR-0030](../adr/0030-unsaved-document-lifecycle.md)과 [문서 생명주기](../spec/document-lifecycle.md)에 정의했다. window 1.2, SDK 0.8 및 이를 동봉한 TeacherDeck 0.7.0을 필요 앱 기준으로 삼는다. 기존 이미지 자르기 코드는 공통화하거나 교체하지 않는다.
