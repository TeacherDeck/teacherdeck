# TeacherDeck 현재 화면 개선 제안

작성일: 2026-10-11. 상태: **설계 검토안 — 디자인 구현 전**.

교사가 도구를 찾고 실제 작업을 끝내는 데 필요한 화면을 줄이는 것이 목표다. 현재 Windows/Tauri·React·Fluent v9·`@deck/ui` 구조, 한국어 문구, Mica 배경과 기존 토큰을 유지한다. 카드 모양을 전부 바꾸거나 새로운 디자인 체계를 만들 필요는 없다. 작업에 필요한 정보와 조작의 순서를 먼저 정리하고, 그 뒤 반복 카드와 여백의 밀도를 조정한다.

## 확인 범위와 증거의 한계

현재 작업 트리의 셸 홈·내비게이션·모듈 헤더, `@deck/ui`, 퀵캡처·문서 형식 변환·파일명 정리·지도일배정기·회의록·빠른 메모 코드를 읽었다. 아래 경로와 줄 번호는 이 문서 작성 시점의 코드 기준이며, 이전 스크린샷을 현재 화면의 증거로 사용하지 않았다.

**확인한 사실**은 렌더 조건, 컴포넌트 배치, 토큰, 이벤트 연결이다. **개선 판단**은 그 구조가 작업에 미치는 영향을 바탕으로 한 제안이다. 실제 화면의 크기·잘림·대비·스크롤·조작 속도는 아직 렌더 검증하지 않았다. 이 문서만으로 접근성 적합이나 디자인 개선 완료를 선언하지 않는다.

규범은 [디자인 시스템](../spec/design-system.md), [작업 절차](../spec/process.md), [공통 UI 지침](../../packages/ui/AGENTS.md), [셸 지침](../../apps/desktop/AGENTS.md), [모듈 지침](../../modules/AGENTS.md)이다. `ToolLayout`의 입력 → 옵션 → 미리보기 → 실행 → 결과, WinUI 대응 컨트롤, 의미 토큰, 키보드·배율 기준을 따른다.

## 유지할 편의

- 홈의 `Ctrl+F` 검색, 별 즐겨찾기와 카테고리 접근, 도구 화면에서 내비 레일을 숨겨 작업 너비를 확보하는 방식.
- 퀵캡처의 고정 영역, 전역 단축키, 영역 더블클릭/Enter, 영역 이동·크기 조절, 캡처 영역 밖의 작은 도구 모음. 반복 캡처를 매번 마법사나 새 영역 선택으로 바꾸지 않는다. 연결 근거: `modules/quick-capture/src/App.tsx:293`, `apps/desktop/src/CaptureOverlay.tsx:164`, `apps/desktop/src/CaptureOverlay.tsx:217`.
- 회의록의 `Alt+1~9, 0, -, =` 화자 선택, `Alt+↑↓` 이동, Enter 기록, Shift+Enter 줄바꿈, 접두어로 종류 선택, 기록 뒤 입력으로 돌아가는 흐름. 화자 선택을 매번 대화상자로 옮기지 않는다. 근거: `modules/meeting-note/src/App.tsx:660`, `modules/meeting-note/src/App.tsx:1127`, `modules/meeting-note/src/App.tsx:1174`, `modules/meeting-note/src/App.tsx:1230`.
- 파일 처리의 원본 보존 기본값, 실행 전 미리보기, 원본 이름 변경의 별도 확인과 보호된 되돌리기. 화면을 짧게 만들기 위해 확인 절차를 합치거나 숨기지 않는다.
- 지도일배정기의 달력 직접 선택, 좁은 창에서 날짜 편집 대화상자를 사용하는 현재 분기와 기존 배정·저장 로직.

## 우선순위별 개선안

P1은 작업 흐름을 먼저 고칠 항목, P2는 흐름을 유지하며 화면 밀도를 조정할 항목이다. 아래 일곱 항목은 구현 범위를 고르기 위한 제안이며 모두를 한 번에 적용할 필요는 없다.

### 1. P1 — 파일 도구의 단계와 실제 실행 위치를 맞춘다

**현재 코드:** 파일명 정리는 `preview` 안에서 실행 방식·충돌 확인·실행 버튼·진행 표시를 먼저 렌더하고, 그 뒤 정렬·파일 미리보기를 렌더한다. `run` 구역에는 “미리보기 위에서 실행해요”라는 안내만 있다. `modules/file-rename/src/App.tsx:674`, `:691`, `:745`, `:937`.

문서 형식 변환은 순서가 맞지만 DropZone, 옵션, 최대 `40vh`의 내부 스크롤 목록, 실행, 결과 구역을 항상 배치한다. 완료 전에도 결과 제목과 설명이 존재하며 중지·실패 재시도 버튼은 비활성 상태로 나타난다. `modules/office-convert/src/App.tsx:29`, `:192`, `:278`, `:310`. `ToolLayout` 자체는 구역 순서를 조립하는 골격이다(`packages/ui/src/components.tsx:126`).

**개선 전 → 후:** ‘미리보기’ 안의 실행과 안내뿐인 ‘실행 상태’ → 미리보기에서 원본→새 이름과 충돌을 확인한 뒤, 바로 이어지는 실행 구역에서 한 번 실행한다. 진행은 그 실행 구역, 완료 요약·결과 폴더·복구는 결과 구역에 둔다. 변환 도구는 파일 추가 후 DropZone을 작은 추가 행으로 줄이고, 최초 실행 전에 불필요한 완료 안내를 줄인다. 중지·재시도는 해당 상태에서만 보여 주되 처리 중 중지는 즉시 보이게 한다.

**사용할 것:** 기존 `ToolLayout.Section`, `DropZone`, `ListView`, `Button`, `ProgressBar`, `InfoBar`, `ContentDialog`. 실행 버튼을 화면 여러 곳에 복제하거나 단계 탭을 새로 만들지 않는다. 긴 목록은 필요한 내부 스크롤 하나만 두고 실행 영역으로의 키보드 이동을 보장한다.

**완료 기준:** 같은 합성 파일로 현재와 제안 화면의 입력·미리보기·실행·결과 순서가 일치하고, 새 폴더 복사와 원본 이름 변경을 명확히 구별한다. 충돌 확인·승인·취소·재시도·보호된 되돌리기가 유지된다. 10개 문서의 미리보기와 주 실행을 오갈 때 불필요하게 페이지 전체를 왕복하지 않는다.

### 2. P1 — 지도일배정기에서 명단 준비와 배정 실행을 구분한다

**현재 코드:** 한 `flexWrap` 행에 연도·월, 배정 조건 Expander, 배정·저장, 교사 이름 입력·추가를 모두 놓는다. 교사 목록이 비면 ‘배정’은 비활성화되고 안내는 아래에 나온다. `modules/duty-planner/src/App.tsx:682`, `:699`, `:717`, `:736`, `:770`.

**개선 판단:** 조건을 준비하는 조작과 준비된 결과를 실행·저장하는 조작이 같은 줄에서 줄바꿈되어, 좁은 창에서 순서가 흐려질 수 있다. 이는 코드 구조에 근거한 우려이며 실제 줄바꿈 모습은 검증해야 한다.

**개선 전 → 후:** 연월·조건·실행·이름 입력의 혼합 행 → 위에는 ‘이번 달·하루 인원·명단 인원’ 요약과 배정/저장, 명단 추가·수정은 명단 영역, 달력 옆에는 선택한 날짜의 편집을 둔다. 첫 사용에서 명단이 없으면 이름 입력과 Enter 추가를 먼저 안내한다. 명단이 준비된 다음에는 달력과 날짜 편집이 주 작업이 된다. 현재 달력 2:1 열과 760px 이하 대화상자 분기를 출발점으로 삼는다(`App.tsx:87`, `:816`).

**사용할 것:** 기존 `SettingsExpander`, `NumberBox`, `TextBox`, `Button`, `Caption`, `ContentDialog`; 평면 행의 간격은 `deckTokens.itemGap`·`inlineGap`. 교사마다 모든 입력을 큰 카드로 늘리지 않는다.

**완료 기준:** 처음에는 이름 추가→배정, 다시 열면 월 확인→달력 편집으로 다음 행동을 알 수 있다. 월 변경·마감·저장·배정 조건의 의미와 계산은 유지한다. 좁은 날짜 편집을 닫으면 원래 날짜 버튼으로 포커스가 돌아간다.

### 3. P1 — 퀵캡처의 주 화면을 ‘계속 캡처하는 상태’ 중심으로 압축한다

**현재 코드:** 위에 시작/지금 캡처·영역 숨기기·종료·상태를 놓고, 아래 두 카드에 폴더·기억·형식·파일명과 단축키·테두리 색·두께·항상 위 설정을 모두 보여 준다. 고급 설정은 이미 접혀 있다. `modules/quick-capture/src/App.tsx:398`, `:446`, `:523`, `:558`. 시작 시 폴더가 없으면 선택 절차로 이어진다(`:293`).

**개선 전 → 후:** 주요 실행 아래 두 개의 설정 묶음이 펼쳐진 화면 → 주 행에는 ‘영역 띄우고 시작/지금 캡처’, 저장 장수, 활성 단축키를 두고, 저장 폴더는 짧은 확인·변경 행으로 둔다. 형식·파일명·테두리 스타일은 기존 `SettingsExpander`로 접어 필요할 때 조정한다. 오류·폴더 연결 끊김·단축키 충돌은 접힌 설정 밖에서도 알아볼 수 있게 한다. 현재 자동 적용 동작은 유지한다.

**사용할 것:** `Button`, `Caption`, `InfoBar`, `SettingsExpander`, 현재 캡처 도구 모음 토큰(`captureToolbarHeight`, `captureToolbarButtonSize`, `captureToolbarMinWidth`). 전역 단축키 설정을 강제로 다시 입력하게 하지 않는다.

**완료 기준:** 기억된 폴더가 있으면 현재와 같은 한 번의 시작으로 고정 영역이 나타난다. 반복 캡처는 앱 주 화면으로 돌아오지 않아도 된다. 작은 영역에서도 도구 모음이 픽셀 결과에 포함되지 않고 사용할 수 있다. 이 마지막 조건은 브라우저만으로 확정할 수 없고 Windows 캡처 실동작 확인이 필요하다.

### 4. P2 — 홈에서 도구 탐색에 쓰는 면적을 줄인다

**현재 코드:** 최소 320px 기준의 카드 그리드에 32px 아이콘, 두 줄 설명, 별과 배지를 놓고 카테고리를 세로로 이어 붙인다. 즐겨찾기 도구도 아래 전체 카테고리에 다시 나온다. 레일은 최소 200px이다. `apps/desktop/src/pages/Home.tsx:18`, `:31`, `:47`, `:217`, `:259`; `apps/desktop/src/App.tsx:71`. 검색은 이름·설명을 함께 찾고 Ctrl+F로 이동한다(`Home.tsx:169`, `:193`).

**개선 전 → 후:** 즐겨찾기와 전체 목록이 같은 무게의 카드 → 즐겨찾기는 짧은 실행 행, 전체 도구는 이름·짧은 설명·별을 유지한 작은 카드로 조정한다. 별·업데이트 필요 배지는 계속 눈에 보인다. 일반 카드는 `cardPadding`·`itemGap` 범위에서 먼저 조정하고, 인사/날짜는 검색보다 더 큰 영역을 차지하지 않게 한다. 전체 목록의 중복 제거는 찾는 위치를 바꾸므로 첫 단계에 포함하지 않는다.

**사용할 것:** 현재 `Button`, `Tooltip`, `BodyStrong`, `Caption`, Fluent 아이콘, `deckTokens.cardFill`·`cardStroke`·`cardRadius`. 카테고리·매니페스트 포맷을 바꾸거나 새 도구별 색상 규칙을 만들지 않는다. 즐겨찾기 행 변경은 현재 spec의 홈 카드 정의를 먼저 검토·갱신할 항목이다.

**완료 기준:** 같은 창·설치 도구 목록에서 첫 화면에 나타나는 도구 수와 원하는 도구를 여는 시간을 현재와 비교한다. 제목·별·상태 배지가 잘리지 않고, 설명을 줄인 경우 전체 설명에 키보드로 접근할 수 있다. 검색·카테고리·즐겨찾기로 연 도구가 모두 한 번의 열기 동작으로 실행된다.

### 5. P2 — 셸의 모듈 정보와 도구 제목이 반복되는 높이를 줄인다

**현재 코드:** 셸은 도구 이름·버전·상태의 별도 헤더를 iframe 위에 둔다. 각 도구는 다시 `PageHeader`나 `ToolLayout` 제목·설명을 렌더한다. `apps/desktop/src/pages/ModuleHost.tsx:14`, `:73`; `packages/ui/src/components.tsx:96`, `:138`. 이 구조는 현행 spec에 명시된 것으로 코드 위반은 아니다.

**개선 전 → 후:** 도구 정보 행 + 도구 제목/설명의 반복 → 셸 헤더의 여백과 아이콘을 줄여 메타데이터 행의 높이를 낮추고, 작업 제목은 모듈의 기존 h1을 유지한다. 도구 시작 제목처럼 역할이 다른 것은 남긴다. 더 큰 변경으로 이름을 한 곳에만 두는 방안은 우선 작은 화면 비교 결과를 보고 별도 결정한다.

**사용할 것:** 현재 타이틀바의 뒤로·창 조작, `Caption`, `PageHeader`, `tokens.spacingVerticalS`·`spacingHorizontalM`, 현재 버전·상태 배지. 오류나 업데이트 필요 상태, 저자·라이선스 접근을 숨기지 않는다. 헤더 역할 자체를 바꾸는 후속 구현은 먼저 `design-system.md` 화면 구조를 갱신한다.

**완료 기준:** 20px h1을 유지하며 문서·달력·회의 기록에 쓸 수 있는 높이가 늘어난다. 뒤로, 제목 인식, 버전/상태 확인과 로드 오류 안내가 유지된다. iframe 생명주기·keepAlive·브리지를 변경하지 않는다.

### 6. P2 — 빠른 메모 목록에서 카드별 반복 조작을 줄인다

**현재 코드:** 메모 카드는 최소 240px 그리드, `pagePadding`, Subtitle 제목, 본문 전체와 수정·항목 백업 저장·고정·보관 네 버튼을 각각 렌더한다. 입력 카드도 같은 padding을 쓴다. `modules/quick-note/src/App.tsx:33`, `:204`, `:280`. Ctrl+Enter 저장, 보관함, 페이지 나누기와 백업 확인창은 이미 있다.

**개선 전 → 후:** 모든 메모의 본문·네 버튼이 펼쳐진 그리드 → 목록은 제목/본문 일부·고정 상태를 먼저 보여 주고, 선택한 메모에서 전문·수정·백업·보관 조작을 보여 준다. 현재 검색과 보관함은 목록 위에 남긴다. 한 줄 메모를 입력할 때 색·고정·백업 설정이 주 입력을 밀어내지 않게 한다. 전체 본문은 기존 `TextBox(readOnly)` 또는 선택 상세 영역에서 읽을 수 있어야 한다.

**사용할 것:** 기존 `ListView`, `BodyStrong`, `Body`, `Caption`, `TextBox`, `Button`, `SettingsExpander`. 개인이 고른 메모 색은 유지하며 완료/오류 의미로 재해석하지 않는다. 내용 삭제 동작을 추가하지 않는다.

**완료 기준:** 20개 합성 메모에서 현재와 비교해 첫 화면의 메모 식별 수가 증가한다. 긴 본문을 잃지 않고 펼쳐 읽을 수 있으며, 수정/보관 후 원래 목록 위치로 돌아간다. Ctrl+Enter, 미저장 초안, 보관함, 백업/복원의 기존 보호가 유지된다.

### 7. P2 — 회의록은 입력 영역을 유지하고 관리 조작만 압축한다

**현재 코드:** 기록·화자·입력 영역을 나눈 전용 workspace와 낮은 창의 종류 선택 대화상자가 이미 있다. 회의 중 위에는 내보내기·참석자·도움말·지난 회의·새 회의, 입력 아래에는 기록·되돌리기·다시 적용·지금 저장을 둔다. 기록과 화자 영역, 페이지가 각각 스크롤할 수 있다. `modules/meeting-note/src/App.tsx:65`, `:182`, `:197`, `:226`, `:1080`, `:1211`.

**개선 전 → 후:** 현재 작업과 회의 관리 버튼이 같은 무게 → 화자·최근 기록·발언 입력을 유지하면서 지난 회의/새 회의는 관리 조작으로 시각적 무게를 낮춘다. 내보내기 F8·참석자 F9·도움말 F4를 유지한다. 작은 창에서는 종류 선택을 기존 대화상자로 두되 현재 화자와 입력은 항상 확인할 수 있어야 한다. 되돌리기·저장 상태를 작은 상태 행으로 정리하되 오류는 `InfoBar`로 보이게 한다.

**사용할 것:** 현재 `ToggleButton`, `TextBox`, `ContentDialog`, `Caption`, `InfoBar`, `deckTokens.inlineGap`. 회의록에 파일 도구용 `ToolLayout`이나 거대한 설정 카드를 적용하지 않는다. 720px/640px 분기는 이미 있으므로 새로 ‘반응형을 추가했다’고 주장할 대상이 아니다.

**완료 기준:** 12명·긴 한국어 제목·100개 기록에서도 Alt+화자 선택→입력→Enter 기록을 반복하며 입력 포커스와 현재 화자가 유지된다. 입력 화면을 보기 위해 로그·화자·페이지 세 곳의 스크롤을 계속 옮길 필요가 없어야 한다. 한글 조합 Enter, 수정 취소, 기록 되돌리기, 자동 저장/지금 저장과 실패 복구가 유지된다.

## 공휴일과 상태 색: 이미 있는 의미를 보존하고 검증한다

지도일배정기의 공휴일 색은 현재 코드에 이미 있다. `calendarStatus`는 공휴일 또는 일요일을 `red`, 토요일을 `blue`로 분류한다(`modules/duty-planner/src/calendar-view.ts:6`). 화면은 `colorPaletteRedForeground1`·`colorPaletteBlueForeground2`로 날짜/요일/공휴일 이름을 표시하고, 제외 배경·선택 테두리·직접/고정 ◆·수행 ✓를 구분한다(`modules/duty-planner/src/App.tsx:74`, `:777`, `:823`). 이를 ‘현재 공휴일에 색이 없다’고 진단하지 않는다.

후속 변경에서는 날짜의 의미 색과 배정 상태의 색을 분리한다. 날짜는 현재 빨강/파랑, 일반 이름은 `colorNeutralForeground1/2`, 선택은 `colorBrandBackground2`·`colorBrandStroke1`, 수행은 현재 성공 토큰을 사용한다. 직접·고정의 `colorStatusWarningForeground1`은 현재 표현이므로, 오류/경고와 혼동하는지 렌더 검증한 뒤 유지 또는 중립 기호+텍스트로 조정한다. 휴일 이름, ‘지도 없음’, ‘선택’, ◆, ✓ 같은 글자/기호가 색을 보완해야 한다.

| 확인 조합 | 수용 기준 |
|---|---|
| 라이트/다크의 평일·일요일·토요일·평일 공휴일·토요일 공휴일 | 공휴일 우선 빨강과 토요일 파랑의 의미가 유지되고 날짜/이름이 읽힌다. |
| 공휴일+제외, 공휴일+선택, 직접/고정+선택, 수행+선택 | 배경이나 hover/pressed가 날짜 색과 상태를 지우지 않는다. 색만으로 구분하지 않는다. |
| Mica, Win10 불투명, OS와 앱 테마가 다른 불투명 폴백 | 각 표면에서 글자·테두리 대비를 측정한다. |
| 화면과 내보낸 결과 | 화면 의미를 출력에서도 알아볼 수 있다. 출력 경로와 실제 결과는 별도 검증한다. |

## 구현 순서와 검증

1. 파일명 정리와 문서 형식 변환의 단계·실행 위치부터 비교 시안을 만든다. 기능/확인 절차는 그대로 두고 화면 구조만 비교한다.
2. 지도일배정기와 퀵캡처의 첫 사용/반복 사용 흐름을 정리한다. 실제 달력·오버레이·파일 결과로 확인한다.
3. 홈·중복 헤더·빠른 메모를 같은 크기의 전후 화면으로 비교하고 밀도를 조정한다. 회의록은 입력 중심 구조의 회귀 검증과 관리 행 압축만 진행한다.

전역 `cardMinHeight`·`pagePadding`을 한꺼번에 줄이지 않는다. `SettingsCard`와 캡처 도구 모음은 역할이 다르다. 먼저 모듈 조합과 기존 토큰 선택을 고치고, 공통 컴포넌트 변경이 필요한 경우 갤러리·spec·컴포넌트 테스트를 함께 갱신한다. 새 캡·브리지·보안·런타임 의존성 변경은 이 계획에 필요하지 않다. 정지 조건에 해당하는 후속 요구는 [제안서 절차](../spec/process.md#2-정지-조건과-제안서)로 분리한다.

| 검증 환경/상태 | 확인할 것 |
|---|---|
| 1280×720, 1024×768, 800×600 창 | 창/셸/iframe 기준을 구분해 기록한다. 첫 화면에 주 작업이 보이고 제목·버튼이 잘리지 않는다. 현재 최소 창 크기로 불가능한 크기는 지원 사실로 주장하지 않고 별도 결정한다. |
| 텍스트 150%, Windows DPI 200% | 한국어 긴 문구·이름·파일명에서 레이아웃/포커스/대화상자가 잘리지 않는다. 두 배율을 각각 및 함께 확인한다. |
| 라이트/다크/Mica·불투명 폴백 | 색 의미와 WCAG AA 대비, hover/pressed/disabled/focus 상태를 확인한다. |
| 키보드만 사용 | Ctrl+F, 별, 도구 열기, 뒤로 Alt+←, 설정 펼침/접기, 목록/대화상자 포커스 복귀, 각 도구 고유 단축키를 확인한다. |
| 빈 상태·로딩·일부 실패·최대/긴 내용 | 다음 행동 안내, 비활성 이유, 완료/실패의 구분이 주 작업 근처에 보인다. 파일명 정리는 페이지 나누기와 상세 열기를 유지한다. |
| 스크롤 | 일반 도구는 주 콘텐츠의 세로 흐름을 우선한다. 파일 목록/회의 기록처럼 필요한 내부 스크롤만 남기고, 입력·실행·닫기가 스크롤 뒤에 갇히지 않는다. |
| 화면 밀도 비교 | 같은 자료·창·배율에서 보이는 도구/메모/기록 수, 첫 작업까지의 클릭/키 입력 수, 주 실행까지의 스크롤을 기록한다. 밀도를 높여 터치·키보드 조작을 어렵게 만들지 않는다. |

현재 문서는 제안만 담는다. 구현 시 사용자에게 보이는 모듈 변경은 버전 bump·CHANGELOG, 관련 문서 갱신, 의미 있는 동작/회귀 테스트와 `pnpm verify`를 동반한다. 렌더 화면과 Windows 고유 캡처 동작의 확인은 빌드/검증 성공과 별도로 기록한다.
