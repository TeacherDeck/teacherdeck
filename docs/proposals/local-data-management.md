# 전체 설정의 로컬 자료 관리 설계

2026-10-11 사용자 요청 9번에 따른 설계다. 메모·D-Day를 먼저 구현하고, 여러 모듈의 백업·불러오기를 **설정 → 자료 관리**에 모은다. 이 문서는 통합 복구 기능의 구현 완료를 뜻하지 않는다.

## 사용 흐름

설정의 자료 관리에는 `전체 백업 저장`, `백업 불러오기`, `자료별 관리`를 둔다. 기본 백업 대상은 아래의 모든 작업 자료다. 교사는 필요할 때만 목록을 펼쳐 일부를 제외한다. 파일 이름·사진·명단을 외부에 전송하지 않는다.

불러오기는 파일 선택 → 비밀번호 입력 → 내용과 변경 범위 확인 → 복원 순서다. 화면은 자료 종류·도구 이름·항목 수·백업 날짜·현재 자료와의 차이를 보여준다. 실패한 자료를 건너뛰고 성공했다고 하지 않는다. 복원 직전에 현재 자료의 되돌리기용 백업을 만들며, 기존과 새 자료를 같은 파일에 덮어쓰지 않는다.

## 포함 범위

| 자료                  | 저장·백업 단위                                             | 복원 시 동작                                                |
| --------------------- | ---------------------------------------------------------- | ----------------------------------------------------------- |
| 빠른 메모·D-Day       | 모듈별 버전형 JSON 전체, 보관 항목 포함                    | 해당 도구 단위 교체. 같은 제목만으로 임의 병합하지 않음     |
| 학생 명부·수업·시간표 | 호스트 공통 학교 자료, 학생·학기 ID와 연결 포함            | 학교 자료 한 묶음으로 검증 후 복원                          |
| 학생 사진             | 학교 자료가 참조하는 앱 소유 사진 파일                     | 해시·형식·크기와 명부 연결 함께 검증                        |
| 교사 명부·지도일 배정 | 지도일 모듈의 조건·월별 결과·실제 수행 횟수·세부 업무 전체 | 저장 세대와 인덱스를 함께 복원                              |
| 회의록·교실 도구      | 각 모듈의 저장 자료·설정·기록 전체                         | 도구별 묶음 복원, 이력의 당시 이름·ID 보존                  |
| 그 밖의 도구 설정     | 각 모듈의 storage 키 전체                                  | 도구 ID별 격리 유지. 일부 키만 복원해 세대 참조를 깨지 않음 |
| 셸 설정               | 테마·모션·즐겨찾기 등 허용한 설정                          | 설치된 도구 ID와 대조하고 모르는 도구는 보존 표시           |
| CoolReserve           | 초안·보관·연결 상태 설명 및 중복 발송 방지 장부            | 등록 이력은 보존. 연결·첨부를 다시 확인하고 자동 등록 금지  |
| 네트워크 루틴         | 프로필·시간·조건                                           | 자동 실행은 꺼진 상태로 복원. 적용 전 어댑터 재선택·확인    |

사용자가 처리했던 원본 문서·완성 이미지·영상·캡처 결과 전체는 앱 설정 백업에 몰래 포함하지 않는다. 선택 폴더 권한, 파일 핸들, Windows 장치 ID, 임시 파일, 로그, 캐시, 실행 파일, 로그인 쿠키·인증 정보도 복원하지 않는다. 다른 PC에서는 폴더·장치·외부 앱 연결을 다시 선택한다.

TimeAlert 전체 백업은 별도 호환 형식이다. 현재 공통 자료를 포함한 TeacherDeck 백업만으로 원작의 모든 사적 기록까지 들어 있다고 표시하면 안 된다. 원작 보존 세션이 열려 있을 때만 그 원형 자료를 추가 포함하도록 설계하며, 닫힌 상태에서는 미포함 안내와 원본 다시 열기를 제공한다. 이 상세 개선은 사용자 후속 TimeAlert 작업과 연결한다.

## 파일 형식과 보호

단일 `.teacherdeck-backup` 파일을 사용한다. 외부 헤더는 형식 버전·암호화 파라미터만 가진다. 암호화된 내부 manifest에 앱 버전·생성 시각·자료 종류별 스키마 버전·크기·해시를 담고, 자료 payload와 사진을 포함한다. 이미 도입한 AES-GCM·PBKDF2 계열을 재사용하되 이 신규 포맷에는 별도 도메인 식별자와 충분한 KDF 비용을 정한다. TimeAlert 암호화 계약을 바꾸지 않는다. 비밀번호는 저장하지 않는다.

압축 해제 개수·총 크기·개별 파일·사진 화소·중첩 깊이를 제한하고, 절대 경로·상위 경로·링크·중복 경로·대소문자 충돌을 거부한다. 인증·해시·스키마 검사를 모두 통과한 뒤에만 실제 저장소를 바꾼다. 더 새 버전의 자료는 원본을 보존하면서 지원 버전 안내를 제공한다.

## 복원 원자성과 권한

일반 모듈에 다른 모듈의 storage 열람 권한을 주지 않는다. 신뢰 셸 전용 데이터 관리 명령이 호스트에서 고정된 저장 영역만 취급한다. 명령은 `목록 조회`, `백업 저장`, `복원 미리보기`, `복원 적용`, `미리보기 취소`로 나누며 임의 경로는 받지 않는다.

백업 전에 관련 도구의 저장 완료를 확인하고, 미저장 초안은 저장하거나 제외 사실을 확인해야 한다. 복원 적용 중에는 영향받는 도구를 중지하고 저장 writer·메모리 캐시를 잠근다. 현재 세대 전체를 보존한 뒤 별도 staging에서 새 자료를 구성하고, 검증 후 단일 활성 세대 참조를 전환한다. 중간 장애·전원 종료 후 재시작에서도 기존 또는 새 세대 하나만 보이도록 journal로 복구한다. 도구를 다시 열어야만 새 데이터를 사용하게 한다.

백업을 읽는 동안에도 writer를 잠근다. 저장 완료 확인만 한 뒤 키를 차례로 읽으면 세대 포인터와 chunk 파일의 시점이 달라질 수 있다. 셸에서 초안을 저장한 뒤 모듈 writer와 관련 네이티브 작업의 안전한 일시 정지 또는 호스트 일관 스냅샷을 확보하고, 한 세대의 자료를 수집한 뒤 잠금을 푼다. 예약 등록이 진행 중이면 중간 상태를 복사하지 않고 종료·취소 후 다시 안내한다.

선택 백업·복원은 독립 파일 선택이 아니라 자료 묶음 단위다. 명부·수업·사진은 항상 함께 다룬다. 교실 도구의 학기·학생 연결 ID가 들어 있으면 연결된 학교 자료도 자동 선택하며, 현재 학교 자료와 다른 세대라면 복원 미리보기에서 차이를 보여준다. 전체 연결 자료를 함께 복원하거나, 명시적으로 해당 도구의 당시 명단을 임시 명단으로 보존하는 선택만 제공한다. 식별자를 이름으로 추측해 붙이거나 묵시적으로 끊지 않는다.

미설치·알 수 없는 모듈의 자료도 백업에서 버리지 않는다. 검증된 원형 bytes와 스키마·해시를 호스트 격리 보관함에 저장하고, 호환 버전을 설치했을 때만 사용자가 연결한다. 자료 복원 때문에 모듈 코드가 설치·실행되는 일은 없다.

CoolReserve 중복 제출 장부는 자료 복원이 과거 발송을 지우지 않도록 현재 장부와 보존적으로 결합한다. 네트워크 예약 작업·캡처 세션·메시지 예약 등록 등 OS 부수 효과는 자료 복원만으로 실행하지 않는다. 복구 후 각 도구에서 새 연결·권한 확인을 받는다.

제출 시도·불명 상태 장부는 일반 복원 세대 바깥의 단조 증가 보호 기록이다. journal 장애 복구나 자동 되돌리기에서도 이미 남긴 제출 증거를 이전 세대로 롤백하지 않는다. 이 장부 결합과 내구성 확보에 실패하면 복원을 완료하지 않으며 예약 기능을 잠근다.

## 단계와 검증

1. 메모·D-Day의 로컬 저장과 개별 파일 왕복을 먼저 제공한다.
2. 호스트 저장 자료 목록·스키마 버전·크기 조회와 통합 백업 출력부터 구현한다.
3. 복원 미리보기·선택·자동 되돌리기 백업·세대 전환을 구현한다.
4. 새 PC에서 실제 이동, 잘못된 비밀번호·손상·중단·디스크 부족·미설치 도구·최신 스키마·명부/사진 불일치를 시험한다.

검증은 합성 학생·교사·메모로 한다. 수백 명·수천 기록의 왕복에서 ID·사진 해시·횟수·보관 자료가 같아야 한다. 복원 취소·실패 시 기존 저장소 바이트가 유지되어야 한다. 새 명령·ACL·복구 정책은 구현 전 ADR와 규격에 반영한다.
