# 0.4.0 자료 호환·학생 화면 보완 검수

기준일: 2026-10-11. 사용자가 승인한 TimeAlert 백업·사진 호환과 별도 학생 화면, 원작 편의성 복원 작업의 검수 기록이다. **최종 `pnpm verify` 16단계가 통과했다.** JavaScript 134파일 1,258개, Rust core 101개·host 151개·독립 DLL 3개로 총 1,513개 테스트다. 로그는 `target/adversarial-review/portability-040-verify-final.log`에 있다. 공개 배포 완료를 뜻하지 않으며 이전 0.3.2 검수 결과를 이번 결과로 재사용하지 않는다.

## 검증 방식

사용자의 요청에 따라 컴퓨터 유즈와 사용자 창의 클릭·키 입력을 중단했다. 코드 계약 검사, 합성 자료의 입출력, 원작 데이터 형식과의 대조, 실제 처리 번들의 자동 픽셀 검사를 사용한다. 실제 Windows 혼합 DPI·복제/확장 전환과 Android 복원 실증은 별도 증거가 없으면 미검증으로 남긴다.

저장소의 보안·라이선스·억제 검사와 Cargo 취약점 검사는 통과했다. 별도 gitleaks 실행기는 설치되어 있지 않아 해당 독립 검사의 통과를 주장하지 않는다. DCO 커밋 훅의 필수 빠른 검사도 유지했다.

## 학생 화면

- 창은 공개한 자리·발표·모둠·역할 결과만 받는다. 내부 명부 식별자·교사 조건·과거 집계·메모는 공개 모델에 없다.
- 소유 모듈과 창 핸들, 공개 자료 크기, 단조 증가 revision, 모니터 구성 변경을 검사한다. 일반 모듈 브리지나 파일 명령은 보조 창 ACL에 부여하지 않는다.
- 교차 리뷰에서 전송 실패 후 revision 재시도가 막히는 경로, 모듈 언로드와 창 생성의 경쟁, 셸에서 새 종료 이벤트를 누락한 경로를 찾아 보완했다.
- 메인 창을 종료해도 학생 이름이 남는 경로를 교차 검토로 발견했다. 실제 메인 종료에서는 생성 중인 세션까지 먼저 폐기하고 학생 창을 가린 뒤 닫는다. 모듈 언로드도 자기 세션을 먼저 폐기하므로 네이티브 창 닫기 실패가 자료 권한을 유지하지 않는다. 캡처를 위한 메인 창 숨김은 유지한다. 관련 호스트 회귀는 최종 전체 검사에 포함한다.
- SDK·권한 검사 14개와 셸·공통 조작·공개 화면 통합 21개 테스트가 통과했다. 통합 테스트는 선언된 소유 모듈에 종료·연결 변경 이벤트가 전달되는지도 확인한다.
- 페이지 단독 진입에 테마 provider가 빠지고 테스트의 외부 provider가 이를 가리는 문제를 발견했다. 화면 자체에 불투명 DeckProvider를 두고 저장 테마·다른 창의 테마 변경·OS 테마 변경을 반영했다. 실제 진입처럼 외부 provider 없는 셸 테스트 6개가 통과했다. 자리·모둠·역할 구성원은 표준 Subtitle 20px, 발표자 6명 이하는 TitleLarge 40px를 쓰며 페이지 제목 20px와 긴 이름 줄바꿈·1,000자리 스크롤을 유지한다.

## 이미지 출력

원작의 빠른 흐름을 유지하며 드롭 후 자동 압축, 순차 파일 읽기, 수백 장 편집 목록, 밝기·대비·크기 변경·간단한 주석과 되돌리기를 보완했다. 모듈별 상한은 README에 기록한다.

생산용 Worker 번들을 Node와 기존 Skia Canvas 실행 환경에서 처리했다. 50×40 크기, 밝기·대비, 빨간 사각형, 한글 글자, PNG 투명도, JPEG 흰 배경, 회전과 자르기 결과를 실제 출력 픽셀로 검사했다. 이는 Chromium/WebView2의 화면 실증과 구분한다. 숨겨진 브라우저 검사 시도는 환경 지연으로 중단했으며 성공 증거로 사용하지 않는다.

근거: 로컬 `target/next-tools/image-editor-node-pixels.mjs`, `image-editor-node-pixels.json`, `run-image-native.cjs`, `image-native-result.json`. 실제 생산 번들만 실행하며 사용자 이미지는 사용하지 않았다. 공개 폰트 토큰은 메인 화면에서 Worker 메시지로 전달해 React·Fluent 런타임을 Worker에서 제외했다. production Worker는 4,898바이트다. 두 하니스에서 밝기 RGB [160,200,240], 대비 [33,73,113], 빨간 사각형 288픽셀, PNG alpha 0, JPEG 흰 영역 RGB [241,255,255]를 확인했다. 원작 한글 합성 글자는 63개 어두운 픽셀로, 별도 영문 합성 글자는 165픽셀로 검사했다. 5개 이미지 테스트 파일의 41개 회귀도 통과했다.

## 자료 호환과 한글 자동화

TimeAlert 원작의 DB7 구조와 암호화 바이트 계약을 기준으로 검증했다. 미편집 원형 자료, 사진, WAL을 적용한 DB를 보존한다. 표현할 수 없는 변경을 조용히 누락하거나 다른 사람의 학생 master에 이름만으로 연결하지 않는다. DB 구조·날짜별 일과 변경·원형 연결 삭제 거부·사진 경로 재배치 회귀가 최종 전체 검사에 포함된다. 실제 포함한 사진의 과거 절대 경로는 원작 PhotoStore가 다른 기기에서도 읽는 파일명으로 바꾸며 누락된 사진의 metadata는 보존한다. Java→Rust 고정 암호화 벡터와 Rust→Java 새 salt/IV 결과가 모두 일치했다. [상세 구현 검토](timealert-portability-implementation-2026-10-11.md)에 Android 실기와의 차이를 기록한다.

한글은 공식 RegisterModule 연동과 작업 파일 두 개에 한정한 독립 보안 모듈을 사용한다. 보안 확인창을 대신 클릭하거나 모든 경로를 허용하는 예제를 설치하지 않는다. x86 DLL 독립 검사와 경로·파이프·수명 검사는 통과했으나 실제 한글은 시작 전·후 등록 모두 FALSE를 반환했다. 등록 실패 후 DLL 미로드 상태와 작업 프로세스·고유 등록값 정리를 확인했지만 내부 거부 단계는 미확정이다. 실패 시 즉시 직접 변환을 안내하며 실제 HWPX 변환 성공으로 기록하지 않는다. [진단 기록](hancom-save-timeout-followup-2026-10-11.md)을 참고한다.

첫 전체 검사에서는 대화상자 세 건의 테스트 포커스 경합이 드러났다. 확인창의 실제 포커스와 Tabster 등록·DOM 종료를 기다리도록 테스트 준비를 고쳤다. 제품의 보존·권한 단언과 시간 제한은 유지했으며 최종 전체 재실행이 통과했다.

## 설치본과 동봉 파일

`pnpm tauri build`가 통과했다. 처음 기존 빌드 폴더의 실행 파일 교체가 Windows 접근 거부로 실패해, 현재 앱을 종료하지 않고 별도 `target/review-040`에서 빌드했다. 로그는 `target/adversarial-review/portability-040-build-isolated.log`다.

- 설치본: `target/review-040/release/bundle/nsis/TeacherDeck_0.4.0_x64-setup.exe`, 27,003,489바이트(25.75MiB), SHA-256 `8450f05aecd2a6f37cb2c44b986fcb580ad43a712e73ffca65a46f6e1ddb8648`
- 실행 파일: `target/review-040/release/teacherdeck.exe`, 23,155,200바이트, SHA-256 `0cdf169a3d7f706f4cc80fcc1930d097cfef04f5893a43347487f3d9156d89fb`
- 카탈로그·소스 매니페스트와 모듈 17개의 버전·크기·SHA-256이 일치했다. 릴리스 폴더와 NSIS 포함 목록도 모든 원천 자산과 대조했다. 네이티브 601개와 모듈 영역 19개(패키지17·카탈로그·기존 `.gitkeep`) 총 620개다.
- 근거: `target/adversarial-review/verify-portability-bundle.mjs`, `portability-040-bundle.json`. NSIS 생성 목록과 배포 폴더의 대조이며 새 PC 설치·제거나 설치본 실행 검수를 대신하지 않는다.

Vite 큰 청크 안내와 기존 ts-rs 속성 파싱 경고는 남아 있다. 경고 상한·검사 규칙을 완화하지 않았다.

## 지도일 원작 형식과 복구

지도일배정기 0.4.0은 원작 GAS JSON을 연도 확인·복원 확인 후 가져온다. 누적 횟수는 기초 기록으로 보존하고 미수행 배정을 실제 수행으로 추정하지 않는다. 담당 두 칸의 위치·배정불가·원래 날짜 행을 보존하고, 세 명 또는 여러 연도를 표현하지 못하는 기존 형식 내보내기는 명시적으로 막는다. 손상 저장소는 새 자료를 모두 쓴 뒤 활성 자료를 바꾸며 실패 시 원본/잠금을 보존한다. 평소 다중 월 저장도 같은 확정 경계를 따른다. 합성 SDK host와 순수 로직 10개 파일/65개 테스트, scoped ESLint·typecheck·diff 검사를 통과했다.

2026~2030 내장 날짜 103개는 KASI 2027/2028 잠정 달력자료·2016 역서 242쪽 음력 환산표와 현행 법령을 대조했다. 2028 국회의원선거일은 예정 표시이며 2030 선거일·추가 임시공휴일은 자동 확정표에 넣지 않는다. 향후 월력요항·법령 변경과 실제 Windows UI 실증 한계는 [모듈 README](../../modules/duty-planner/README.md)에 기록했다.
