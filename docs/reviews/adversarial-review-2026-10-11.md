# 0.3.0 적대적 리뷰와 남은 작업

기준: 2026-10-11, `3351ca1`, `codex/parallel-tools-foundation`. GPT-6.1 Sol 3개 에이전트와 주 작업자가 병렬로 진단했다. 제품 소스·기존 테스트·OS 설정·사용자 자료를 변경하지 않았다. 합성 재현 파일은 `target/adversarial-review/`에 두었다.

## 판단

기본 모듈 17개와 공통 학급 자료의 구현은 있으나 **공개 배포 준비가 끝난 상태가 아니다**. 결과의 비밀성, 수행 기록 보존, 네트워크 적용 정확성에 영향을 주는 결함을 재현했다. 원작의 편의성도 일부만 이식된 상태다. 아래에서 확인된 결함, 코드상 복구 공백, 아직 만들지 않은 기능, 실기 검증을 구분한다.

이전 로컬 `pnpm verify` 1,282개 통과는 당시 기록으로 유효하지만 최신 GitHub 검증 통과를 뜻하지 않는다. [PR #10 검증](https://github.com/TeacherDeck/teacherdeck/actions/runs/38102329821/job/114360646663)은 **실패**했다. 이 리뷰에서 전체 검증을 다시 실행하지 않고 반례 검사를 실행했다.

## 확인된 결함: 먼저 수정할 10개 항목

P1은 배포 전에 반드시 해결할 문제, P2는 실제 사용 결과나 복구·조작을 잘못 만드는 문제다. 네트워크의 두 반례는 같은 상태 판정 결함으로 묶었다.

### A01 · P1 · PDF 마스킹 후 글자가 실제 출력에 남는다

- 위치: [pdf.ts:68](../../modules/pdf-mask/src/pdf.ts#L68).
- 조건: `/UserUnit=2`인 PDF에서 검색어 또는 자동 탐지 후보로 텍스트를 지운다.
- 원인: 시작점과 글자 높이는 viewport 변환을 적용하지만 `item.width`에는 확대 단위를 반영하지 않는다. 검은 영역이 글자 폭보다 작다.
- 재현: 현재 `openPdf → pageInfo → detect → redact`를 직접 사용해 합성 PDF를 저장하고 다시 렌더했다. 숨은 텍스트 배열은 비었지만 검은 영역 오른쪽에 `IDENTIFIER` 일부가 읽히는 픽셀로 남았다. 실제 글자 끝 426.048pt, 마스크 끝 245.88pt, 마스크 밖 어두운 픽셀 11,176개.
- 수정 방향: 폭·높이·회전을 같은 좌표계에서 계산한다. UserUnit, 회전, CropBox 조합으로 출력 파일을 재렌더하고 남은 픽셀까지 검사한다. 텍스트 추출 결과가 비었다는 검사만으로 완료 처리하면 안 된다.
- 증거: `pdf-userunit-counterexample.mjs`, `synthetic-userunit2.pdf`, `pdf-mask-userunit-exposure.jpg`. 실제 제품 UI 전체가 아닌, 제품 출력 함수를 직접 호출한 브라우저 검수다.

### A03 · P1 · 네트워크 설정 일부를 확인하지 않고 적용 완료로 처리한다

- 위치: [network.rs:621](../../crates/deck-core/src/caps/network.rs#L621), [logic.ts:373](../../modules/network-routine/src/logic.ts#L373).
- 반례 1: IP는 DHCP이고 내부 DNS만 지정한 상태에서 외부 모드가 되면, DHCP 여부만 보고 일치한다고 판단한다. 고정 DNS를 해제하지 않은 채 외부 모드를 적용했다고 기록한다.
- 반례 2: 같은 IP를 유지하면서 마스크·게이트웨이를 바꾸면 두 필드를 비교하지 않아 적용을 건너뛴다.
- 검증: 실제 TypeScript 판정 함수가 두 경우 모두 `matched`와 해당 적용 모드를 반환했다. Rust 판정과 OS 조회 구조도 대조했다. 실제 PC의 IP/DNS는 바꾸지 않았다. 두 문제는 원작에도 있는 결함으로, 포팅 과정에서 새로 생긴 것이라고 단정하지 않는다.
- 수정 방향: IP의 DHCP 여부와 DNS 자동 설정을 구별하고, 지정한 마스크·게이트웨이도 비교한다. 확인할 수 없는 필드는 성공으로 간주하지 않는다.
- 증거: `native-cases.mjs`, `native-cases.json`.

## 원작 편의성과 디자인에서 남은 일

- **시간표 편집:** 현재 요일·교시·수업을 여러 줄 텍스트로 입력하는 방식이다. TimeAlert의 주간 격자, 같은 수업을 연속 배치하는 조작, 가져오기 되돌리기, 시간표 PNG 내보내기를 가져오는 작업이 남았다. 전체 백업 호환과는 별개다.
- **학교 자료 복구:** 자체 JSON을 읽는 복구 경로는 있지만 정상 상태에서 사용자가 그 복구용 JSON을 만드는 메뉴가 없다. XLSX는 일과 시각·변경일·학생 연결 등을 모두 보존하는 백업이 아니다.
- **역할 화면 밀도:** 현재 React 화면을 1280×720 브라우저에서 확인했다. 학생 6명·역할 3개만으로도 세 번째 결과가 화면 아래로 밀리고 문서 높이가 1,375px였다. 조건 카드가 길어지는 구조를 줄이고, 결과를 먼저 보고 조건은 요약·접기/검색으로 편집하는 방향이 적절하다. 이는 화면 밀도 개선 제안이며 배정 오류와 같은 확정 결함으로 세지 않았다.
- **일괄 완료:** 역할별 수행 완료만 제공하는 현재 흐름은 같은 날 모두 수행한 경우 반복 클릭이 필요하다. 전체 완료와 일부 제외를 빠르게 처리하되, 미리보기만으로 횟수를 올리지 않는 원칙은 유지한다.
- **실패 안내와 재시도:** 어떤 동작이 실제 수행됐는지, 사용자가 무엇을 해야 하는지 구분해야 한다. A09·A10과 파일명 만료는 이 기준을 만족하지 못하는 구체 사례다.
- **색·키보드·축소 화면:** 휴일/선택/제외/오류의 의미색과 텍스트 표기를 함께 확인하고, 실제 셸의 120% 배율·작은 창·키보드 순서에서 도구별로 다시 확인해야 한다. 이번에는 역할 화면과 PDF 반례를 실렌더했고, 17개 도구 모든 상태의 디자인을 통과로 판정하지 않았다.

Fluent 공통 컴포넌트를 썼다는 사실만으로 원작의 편의성이 유지되지는 않는다. 원작에서 한 번에 하던 작업을 몇 번의 조작으로 끝내는지, 결과·기록이 동일하게 남는지를 이식의 통과 기준으로 삼아야 한다.
