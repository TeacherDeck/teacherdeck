# 통합 코드 리뷰 후속 수정

2026-10-12. 앱 0.6.3, 지도일 배정기 0.5.2. 사용자가 현재 리뷰 지적을 모두 수정하도록 지시했고, GPT-6.1 Sol 세 담당이 셸·지도일·원작 동기화를 나눠 수정했다. 주 작업자가 보고 순서대로 통합하고 교차 검토했다. 기준은 PR #16 병합 뒤 `origin/main`의 `4f05d5f`이며, 기존 원작과 모듈 작업을 확장하는 새 기능 개발은 포함하지 않는다.

새 캡·ACL·CSP·브리지 envelope·런타임 의존성을 추가하지 않았다. 지도일 저장 형식과 CoolReserve 원천 커밋·모듈·코어 ZIP도 그대로다. 원작 갱신 명령의 사용법과 재시도 조건은 [동기화 안내](../development-coolreserve-sync.md)에 기록했다.

교차 검토에서 발견한 원작 경로의 파일↔폴더 전환은 이번 자동 동기화의 지원 범위에서 제외한다. 해당 충돌을 모든 산출물 게시 전에 확인해 중단한다. 중간 실패가 고정되는 경로를 허용하지 않으며, 별도 경로 정리가 필요하다.

## 검증 기록

셸 지정 Vitest 27개·Rust 활성 상태 회귀 1개와 지도일 App 시험 25개가 통과했다. 지도일의 새 회귀는 보강 뒤 3개를 다시 통과했다. 지도일 첫 재실행에서 동시 컴파일/DOM 부하로 기존 5초 제한을 넘었지만, 새 시험에서 불필요한 명단 확장을 제거하고 기존 제한을 유지했다. 원작 동기화의 새 OS 통합 시험은 여러 독립 PowerShell/Git 호출의 실측 실행 시간이 약 64초라 전체 240초·각 자식 실행 60초로 제한하며 기존 시험 제한을 바꾸지 않는다.

최신 원작 동기화 지정 시험은 78.12초에 통과했다. 손상된 진행 기록·부분 게시 후 삭제·검증 목록 게시 완료 뒤 진행 기록 정리 실패·파일/폴더 구조 충돌도 포함한다.

마지막 교차 검토에서 `target`·`coverage`·`.pnpm-store`의 커밋된 원작 파일이 사전 검사에는 허용되고 최종 목록에서는 제외되는 누락을 찾았다. 제외 경로 여섯 개를 validator와 통일하고, 세 경로 각각을 모든 게시 전에 거절하며 기존 모듈·검증 목록 바이트와 ZIP·진행 기록 상태가 유지되는 회귀를 추가했다.

첫 통합 실행에서는 기존 시간표 1개·이미지 자르기 3개·자리 배치 2개·지도일 5개가 실패했다. 여러 DOM 시험이 동시에 느려졌고 당시 PC의 여유 물리 메모리는 약 1.8GiB였다. 실패 상세가 아직 출력되지 않은 실행을 중단하고 로그를 `target/release-063/verify-first.log`에 보존했다. 테스트 실행 수를 4개에서 2개로 줄여 전체 검증을 다시 진행했다. 기존 시험·assertion·시간 제한은 그대로이며 새 회귀도 모두 포함한다.

두 번째 실행에서도 이미지 자르기 1개·지도일 4개가 실패했다. 같은 저장소에서 PDF 개발 채팅의 전체 검증이 동시에 실행되고 있음을 프로세스 계층으로 확인했고, 실패한 이 채팅의 실행은 중단했다. 기존 이미지 시험과 지도일 시험의 반복 접근성 트리 검색을 정확한 label 조회·안정된 노드 재사용·열린 목록 범위 검색으로 줄였다. 사용자 조작 순서·모든 assertion·기존 시간 제한은 유지한다. 최종 검증은 다른 채팅의 미완료 소스 변경과 분리한 커밋을 기준으로 진행한다.

격리 폴더의 셸·지도일·이미지·Windows 동기화 지정 시험 63개는 통과했다(147.52초). 이후 위 제외 경로 회귀를 추가했으므로 최종 전체 검사에서 다시 확인했다.

최종 `pnpm verify` 16단계가 모두 통과했다. JavaScript 155개 파일의 1,395개 시험과 Rust 277개(순수 코어 104·호스트 170·한글 보안 모듈 3개), 총 1,672개 시험이 통과했다. 생성물·Clippy·라이선스·보안·억제 검사를 포함하며, 기존 시간 제한과 모든 시험을 유지했다. 전체 기록은 `target/release-063/verify-final.log`에 보존한다.

검증 브랜치는 `codex/review-remediation-qa`이고 관리 작업 폴더에 이번 수정만 복사했다. 공유 폴더에서 개발 중인 PDF 압축 후속 수정·새 이미지 편집 모듈·그 의존성 변경은 이번 결과에 포함하지 않는다. 기존 Rust 빌드 캐시는 재사용했고 새 캐시를 복제하지 않았다.

0.6.3 Windows 설치본을 만들고 기본 모듈 20개·아이콘·패키지 해시와 NSIS 입력 자산 623개를 대조했다. 설치본은 39,352,613바이트(37.53MiB)이며 SHA-256은 `8ad0e40d325578a72b9830d8506a59752189f112207bd5525a0d3df1ff1ea39e`다. 구성 대조 결과는 `target/release-063/bundle-063.json`, 빌드 기록은 `target/release-063/build.log`에 보존한다.

격리 작업 폴더 밖의 빌드 출력은 빌드 래퍼가 보존하므로, 성공한 설치본을 지정해 기존 정리 도구를 실행했다. 이전 설치본·오래된 모듈 패키지 3개, 42,713,281바이트(40.73MiB)를 삭제하고 현재 설치본은 유지했다. 컴퓨터 유즈는 사용하지 않았다. 실제 Windows 드래그·설치/제거·쿨메신저 등록의 성공을 합성/단위 시험으로 대신 주장하지 않는다.
