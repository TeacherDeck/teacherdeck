# 후속 도구 구현·통합 검수

기준일: 2026-10-11. GPT-6.1 Sol 작업자 3명과 통합 담당자가 원본 조사, 기능 구현, 교차 검토와 실제 브라우저 검수를 나누어 수행했다. 아래 내용은 개발 소스의 검증이며 새 Windows 설치본 배포 완료를 뜻하지 않는다.

## 구현 범위

| 모듈 | 버전 | 이번에 구현한 흐름 |
|---|---|---|
| 발표자 뽑기 | 0.1.0 | 명단 붙여넣기 → 직접 지정·제외 우선 → 총 완료횟수 기반 선정 → 발표 완료만 집계 → 되돌리기·학생 보기 |
| 역할·당번 나누기 | 0.1.0 | 역할별 필요인원 → 고정·제외 우선 → 총횟수 균등 → 담당자 교환 → 실제 수행 완료만 집계 |
| 모둠 편성 | 0.1.0 | 인원·모둠 수 → 학생·모둠 전체 고정과 분리 → 편성·직접 이동/교환 → 확정 기록·학생 보기 |
| 자리 배치 | 0.1.0 | 명단 → 행·열·통로·빈 자리 → 고정·제외·앞줄·분리 → 자리 교환 → 확정·학생 보기·학생용 파일 |
| PDF 용량 줄이기 | 0.1.0 | 파일 선택·드롭 → 처음 한 번 폴더 선택 → 기본 문서 구조 유지 압축 → 결과·실패 재시도 |
| 개인정보 지우기 | 0.1.0 | 자동 후보·검색어·명단·직접 영역 → 페이지 확인 → 선택 픽셀 제거 → 새 이미지 PDF 작성·재검사 |
| 명렬표 사진 꺼내기 | 0.2.0 | 기존 XLSX 원본 사진 보존 + NEIS PDF의 200 DPI 상자 탐지·회전 보정·학번 연결·사진만 저장 |

학급 도구는 현재 **도구별 명단**을 사용한다. 공통 명부·시간표 연결, TimeAlert 전체 백업 호환, 확장 모니터의 별도 학생 창은 구현 완료 범위가 아니다. 기존 형식을 임의로 대체했다고 주장하지 않는다. 원본 계약과 남은 어댑터 요구는 [TimeAlert 조사](time-alert-classroom-contracts.md)에 기록했다.

## 실제 화면과 결과 파일 검수

- 발표자: 합성 3명 중 제외 조건을 적용하고 총횟수가 낮은 학생을 선정했다. 발표 완료 후 1회 증가, 되돌리기 후 원래 횟수, 학생 화면의 교사 정보 제외를 확인했다.
- 역할: 합성 4명 중 기존 3회인 학생을 고정하고 다른 학생을 제외했다. 실제 모듈 Worker가 고정 학생을 지정 역할에 배정하고, 남은 역할은 0회 학생에게 배정했다. 자동 배정 자체는 횟수를 올리지 않는다.
- 모둠: 8명 중 1명을 제외하여 4명·3명으로 나눴다. 첫 모둠 전체 고정 후 재편성해도 구성원이 유지됐다. 확정과 공개 화면을 확인했다.
- 자리: 두 자리를 클릭해 교환하고 확정 이력 1건을 생성했다. 좁은 534px 화면에서 4열이 잘리던 문제와 확정 후 초안 문구를 수정했다. 1280×720에서 합성 30명의 5×6 배치와 복귀 버튼이 한 화면에 들어오며, 학생 이름은 Fluent 24px 토큰으로 표시했다.
- PDF 압축: 일반 RGB JPEG를 포함한 4쪽 합성 PDF는 **6,526,735→886,246바이트**였다. PDF.js로 다시 읽어 4쪽 검색 글자, 0/90/180/270도 페이지 크기, 링크 1개, 첨부 1개, 제목과 양식 값을 확인했다. ICC 이미지가 있는 별도 문서는 이미지 바이트를 유지하고 객체 구조만 줄여 **6,527,209→6,525,503바이트**였다. 압축률은 입력에 따라 다르다.
- PDF 마스킹: 4방향 회전, 80pt 하강부 글자를 포함한 16영역의 선택 픽셀을 확인했다. 검은 픽셀 153,086개, 미제거 선택 픽셀 0개였다. 첨부 1→0, 텍스트·양식·XMP·제목 제거를 재열기로 확인했다. 원본 6,813,417바이트에서 출력 29,408,793바이트로 커졌으며 압축 기능으로 다루지 않는다. 자동 탐지 밖의 개인정보까지 제거된다는 보장은 하지 않는다.
- PDF 사진: 합성 한 쪽에서 3명·3장을 학번과 연결하여 356×422, 355×422, 356×422 PNG로 저장했다. 네 방향 문서의 12장도 같은 방향·크기로 추출했으며 반복 학번은 미확인으로 표시했다. 여백을 500px로 잘못 다시 적용한 뒤에도 이전 3장과 직접 수정한 이름으로 저장할 수 있었다.

브라우저 검수는 실제 PDF.js·Canvas·모듈 Worker와 실제 출력 바이트를 사용했다. **파일 선택·읽기·쓰기의 OS 경계, storage 호스트, 전체화면 명령은 SDK mock**이었다. Windows 파일 대화상자·실제 디스크 저장·혼합 DPI·다중 모니터까지 통과한 것으로 세지 않는다.

## 대량 자료와 실패 복구

- 학급 명단 1,000명, 발표·역할 실제 완료 기록 10,000건, 역할 100개·정원 합계 1,000명, 자리 1,000석을 검사한다.
- 발표·역할·모둠은 100명 초과 시 50행 단위 조건 목록과 검색을 제공한다. 작은 명단의 기존 직접 조작은 유지한다. 자리 조건은 100행씩 표시한다.
- 역할 배정을 Worker로 옮기고 후보 한 번 정렬로 순수 계산을 현재 PC에서 약 10.9ms로 줄였다. 학교 PC 성능 보장 수치는 아니다.
- 저장은 청크를 기록·검증한 뒤 참조를 마지막에 바꾼다. 실패와 응답 유실을 구분하고 이전 자료를 보존한다. 손상 자료를 빈 작업으로 자동 덮어쓰지 않으며 복구는 명시적 확인 뒤 진행한다. 실제 완료 기록을 조용히 잘라내지 않는다.
- PDF의 큰 원본 이미지도 렌더 전 검사한다. PDF.js의 렌더 옵션만으로는 과대한 원본 이미지가 항상 오류가 되지 않아 별도 이미지 객체 검사를 추가했다.
- XLSX 첫 시트의 그림 관계가 없을 때 다른 시트 사진을 잘못 가져오던 오류를 수정했다. PDF 이름의 성명·이름 라벨을 분리하고, 잘못된 여백은 파일 전체 재적용을 실패시켜 이전 편집을 유지한다.

## 검사와 배포 상태

최종 `pnpm verify` 15단계가 모두 통과했다. JavaScript 773개(78파일), Rust core 59개·host 67개로 **총899개 테스트**다. 전체 로그는 `target/next-tools/verify.log`에 있다. PDF 3종과 학급 4종의 최신 프로덕션 번들도 모두 빌드했다(`target/next-tools/module-builds.log`). 테스트 병렬 실행은 최대 4개로 제한하여 여러 DOM 테스트가 CPU를 과점하지 않게 했다. 테스트 대상·기본 5초 제한·검증 문장은 줄이지 않았다.

PDF 라이브러리 최상위 패키지 라이선스 검사는 통과하지만, 내부 LiberationSans 4개 자산의 한정 예외·제3자 고지 반영은 [승인 제안](../proposals/pdf-resource-license.md)에 남아 있다. 사용하지 않는 QuickJS 자산 두 개는 제외했다. 승인 전 새 PDF 번들을 공개 배포하거나 새 설치본으로 배포하지 않는다.
