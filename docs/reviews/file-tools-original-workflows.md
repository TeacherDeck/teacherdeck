## 개인정보 지우기

## 구현으로 연결한 범위

PDF 개인정보 지우기는 원본의 PDF 선택·직접 검색어·CSV 첫 열/TXT 목록·중복 제거·새 파일 저장 흐름을 유지했다. 페이지 미리보기·자동 후보·직접 사각 영역을 추가했고 모든 페이지를 새 이미지로 작성하여 제거 영역의 원문 객체와 픽셀을 전달하지 않는다. 원본의 구조 redaction과 달리 검색·복사·벡터·양식이 사라지는 점을 저장 전에 안내한다. 자동 OCR은 미구현이다. 원문 구조 유지 압축은 별도 pdf-compress의 기본 방식으로 통합 담당이 구현·검수했다.

PDF 압축은 새 요구로 JPEG 페이지 변환을 구현했다. 더 큰 결과는 원본 바이트 복사로 표시한다. 파일명 통합 UX·정확 매칭·fs 1.3/file-ops 1.0은 사용자가 명시 승인한 뒤 구현했다. 새 폴더 복사가 기본이며 원본 이름 변경은 화면과 호스트 확인 후 실행한다.

원본 NEIS 개발 소스는 이후 target/original-neis/main.py에서 확보되었다. 200 DPI 렌더·임계값 80·3×3 닫기 두 번·외부 윤곽·페이지 대비 면적 0.002~0.15·가로세로 비 0.5~2.5·안쪽 테두리 4 px와 사진 아래 80 px 텍스트 탐색을 확인했으며 photo-extract 담당이 별도 대조한다.

## 합성 PDF 실제 검수

PDF 마스킹의 4쪽 합성 원본은 전화번호·주민번호·검색어와 80pt 하강부 글자, 0/90/180/270도 회전을 포함한다. 16개 제거 영역 내부의 153,086픽셀은 모두 검정이며 미제거 픽셀은 0이었다. 새 PDF를 다시 열어 텍스트가 없고 페이지 크기가 600×800/800×600으로 유지되는 것을 확인했다. 원본 첨부와 출력 첨부는 PDF.js 6의 Map.size로 검사했으며 원본 1개·출력 0개였다. 출력 양식 필드 0개·XMP 속성 없음·제목 없음도 확인했다. 2,500만 픽셀 원본 XObject는 디코드 전 SOURCE_IMAGE_TOO_LARGE로 저장을 차단했다.

13개 PDF 핵심 테스트(범위·목록·분할 텍스트·새 객체·이미지 한도·배치 실패/취소)와 모듈 자체 lint·빌드를 통과했다. 전체 verify와 최종 배포 판정은 통합 담당의 작업이다. 동봉 글꼴 라이선스 예외는 사용자 승인 후 모듈별 고지·해시 검사에 연결했다. 마스킹은 자동 탐지의 완전성을 보증하지 않고 스캔 페이지를 수동 영역 대상으로 안내한다.

## 파일명 통합 검증

XLSX 학번 선행 0·명시적 숫자 서식·정확 키·중복과 공란·수동 행 연결·OPC 패키지 루트 관계, HWP5/HWPX 상단 글, 500파일 미리보기를 합성 입력으로 검사했다. SDK mock에서는 실제 300,000바이트를 256KiB 읽기·64KiB 쓰기로 새 폴더에 그대로 복사하고 취소·실패·재시도에서 완료 결과가 유지되는지 검사했다. 화면 테스트는 세 방식 전환 후 수동 이름 유지와 실행 요약 확인·실패 항목만 새 미리보기로 옮기는 흐름을 포함한다.

실제 Windows 파일 테스트는 16가지 UTF-16 길이, 두 파일 이름 교환, 대소문자 변경, 재시작 후 되돌리기, rename 후 결과 기록 이전 중단의 복구를 확인했다. 열린 파일의 외부 수정·삭제와 부모 교체가 거부됐고, 목적지 점유·junction·다른 소유자/세션·512MiB/2GiB 한도를 검사했다. 동일 바이트와 원래 수정 시각을 가진 다른 파일도 실제 ID가 달라 되돌리기를 차단한다. 손상된 이력은 보존하며 unavailable 서비스는 사용자 파일 변경을 허용하지 않는다.

실브라우저 합성 SDK 검수는 루트 담당이 수행한다. 이것과 실제 Windows 파일 연산 검증은 별개이며 실제 Tauri 호스트 확인창·최종 설치본 완료를 이 문서만으로 주장하지 않는다.
