# PDF 외 전체 검증 실패 후속 수정

2026-10-12. PDF 압축 리뷰 수정 후 발견된 생성물 불일치와 UI 테스트 실패를 해결하는 작업이다. 사용자가 이 후속 범위를 명시적으로 요청했다. 구현은 GPT 6.1 Sol 작업자 3명에게 학교 자료, 지도일 배정기, 회의록·메시지 확인창으로 나누어 맡겼다.

## 검증 범위

시작 시 원 작업 폴더에는 새 편집기와 문서 수명 보호 기능 개발이 함께 진행 중이었다. 다른 전체 검증이 실행 중일 때 여유 물리 메모리가 약 0.5GiB였고, 변경하지 않은 테스트도 2.28초에서 7.37초로 느려졌다. 따라서 이때의 시간 초과를 제품 기능 오류와 구분했다.

통합 검증은 기존 리뷰 수정 커밋 `54a8371`을 기준으로, 이전 PDF 0.1.4 수정과 이번 UI 테스트 수정을 포함하는 별도 작업 트리 `codex/pdf-compression-verify-fixes`에서 수행했다. 원 작업 폴더에도 네 UI 테스트 수정은 반영되어 있다. 다른 기능 개발 파일은 이 검증 브랜치에 포함하지 않는다.

Rust 빌드 캐시도 작업 트리별로 분리했다. 원 작업 폴더의 `target`을 공유한 중간 실행에서는 이 브랜치의 Rust 원천에 없는 문서 기능 타입이 생성 결과에 나타났다. 따라서 최종 검증은 이 작업 트리의 `target`에서 프로젝트 Rust 패키지를 다시 빌드한 결과만 사용했다. 외부 의존성 캐시는 재사용할 수 있지만 프로젝트 패키지 산출물은 공유하지 않았다. 중단한 진단 실행은 전체 통과 근거로 사용하지 않는다.

## 최종 검증 결과

격리 작업 트리의 최종 `pnpm verify`는 종료 코드 0으로 16개 단계를 모두 통과했다. JS는 159개 파일, 1,442개 테스트가 통과했으며 건너뛴 테스트는 없다. Rust는 277개 테스트(`deck-core` 104개, 호스트 170개, Hancom 3개)가 통과했고 실패·무시·필터 제외는 모두 0개다.

기존 중복 의존성, `ts-rs`, 링커 안내 경고는 검사 정책에 따라 남아 있으며 실패 항목은 아니다. 코드나 검사 기준을 약화하여 통과시키지 않았다.

최종 실행 로그 저장 위치는 격리 작업 트리의 `target/verify-repair/verify-transcript.log`다. 캡처에는 긴 `cargo deny` 중복 의존성 경고 트리 일부가 생략되어 있으나, 모든 단계 결과와 테스트 총계는 포함한다.

별도 커밋 훅의 `verify:fast`와 Conventional Commit·DCO 검사는 통과했지만, gitleaks 훅은 실행 파일 미설치로 기존 스크립트가 자동으로 건너뛰었으므로 위 `pnpm verify` 16단계 통과와 구분한다.
