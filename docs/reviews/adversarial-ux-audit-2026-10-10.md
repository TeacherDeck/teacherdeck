# 현재 구현에 대한 적대적 UX 감사 — 2026-10-10

현재 구현은 기능을 실행하는 단계까지 왔지만, 실사용 품질 검수를 통과한 상태로 보기 어렵다. 작성 중 데이터의 소실, 다른 날짜 배정의 일괄 소실, 잘못된 사진 이름의 확정, 허용된 창 크기에서 기록 목록이 사라지는 문제를 우선 해결해야 한다.

이 문서는 진단 보고서다. 제품 소스·규격·의존성·버전은 수정하지 않았다. 미구현 도구를 결함으로 세지 않았으며, 수정 방향은 구현 승인 요청이 아니다.

후속: 사용자 승인에 따라 수정한 내역과 검증 근거는 [UX 보완 보고서](ux-remediation-2026-10-10.md)에 기록했다. 아래 내용은 앱0.2.1을 감사한 당시의 진단이다.

## 범위와 증거 수준

- 대상 커밋: `8a2987a`, 브랜치 `codex/parallel-tools-foundation`, 앱 `0.2.1`, 공통 UI `0.6.0`.
- 대상: 셸, 회의록 `0.5.0`, 지도일배정기 `0.3.1`, 퀵캡처 `0.1.1`, 이미지 용량 줄이기 `0.1.1`, 이미지 자르기 `0.1.1`, 명렬표 사진 꺼내기 `0.1.1`, 타이머 `0.2.1`.
- 판단 기준: 현재 저장소 명세, 사용자가 명시한 핵심 작업 흐름, 원본 회의록·QuickCapture·TimeAlert·simple_crop·중식배정 코드의 관련 동작.
- **화면 재현**: 실제 셸과 실제 모듈 React 코드를 브라우저에서 실행했다. 800×560 앱 프레임에서 모듈에 남는 공간은 600×468이었다. 넓은 타이머 화면은 1280×720에서 확인했다. OS 호출·파일 선택·저장소·브리지 연결은 감사용 모의 구현이다. 네이티브 앱의 실행 증거로 해석하면 안 된다.
- **합성 재현**: 새 합성 데이터와 테스트로 현재의 잘못된 결과를 확인했다. 실제 학생 자료는 사용하지 않았다.
- **코드 추적**: 실행 경로를 확인했지만 Windows 창·트레이·DPI 동작은 직접 조작하지 못했다. 이 한계를 각 항목에 표기했다.
- 임시 재현과 브라우저 하네스는 `target/adversarial-audit/`에만 두었다. 기존 1425 미리보기와 원본 프로그램은 수정하지 않았다.
- P1: 결과 오인·데이터 소실·주요 작업의 심각한 차단. P2: 반복 작업 방해·조작 오류·복구성 결함. P3: 맥락과 표현의 일관성 문제.

## 결함 목록

**총 19건: P1 4건, P2 14건, P3 1건.** 실행으로 확인한 문제와 코드 추적으로 확인한 문제를 구분했다.

### A01 · P1 · 회의록 — 기존 기록을 수정하면 작성 중인 초안이 사라진다

- 재현: 새 발언을 입력하되 기록하지 않는다 → 기존 기록의 수정을 누른다 → 수정 저장을 누른다.
- 결과: 원래 작성 중이던 발언이 안내 없이 빈 문자열로 바뀐다. 수정 취소는 `previousDraft`를 복원하지만 수정 저장은 복원하지 않는다. 기록 되돌리기도 현재 초안을 보존하는 구조여서 잃은 초안을 되살리지 않는다.
- 근거: 합성 UI 재현. [수정 진입](../../modules/meeting-note/src/App.tsx) 661행, 저장 513~518행, 되돌리기 576행. 원본 회의록은 기존 입력이 있을 때 수정 진입 전 확인한다.
- 최소 수정 방향: 수정용 입력과 새 발언 초안을 분리하거나, 수정 저장 후 이전 초안을 복원한다. 사용자에게 다시 입력하게 해서는 안 된다.

### A02 · P1 · 지도일배정기 — 하루의 직접 배정 해제가 전체 배정을 지운다

- 재현: 6일과 7일에 배정이 있고 6일은 직접 배정인 상태 → 6일 선택 → 직접 배정 해제 → 저장.
- 결과: 7일 등 다른 날짜도 미배정이 되며 저장된 `assignments`가 `{}`가 된다. 화면은 “이 날짜의 직접 배정을 해제했어요”라고만 말한다.
- 근거: 합성 UI 및 저장값 재현. [App.tsx](../../modules/duty-planner/src/App.tsx) 298~301행에서 호출하는 `updateInput`은 183~184행에서 전체 배정을 비운다.
- 최소 수정 방향: 대상 날짜의 고정만 해제하고 다른 배정을 유지한다. 조건 변경으로 재계산이 필요한 상태와 기존 결과 삭제를 구분한다.

### A03 · P1 · 사진 추출 — 다른 반 학번을 붙여도 ‘정확한 좌표’로 확정할 수 있다

- 재현: 같은 시트의 왼쪽 1반 머리글은 0행 0열, 오른쪽 2반 머리글은 1행 10열, 왼쪽 학생은 2행 0열에 배치한다. 해당 학생 사진은 1행 0열에 둔다.
- 결과: 머리글 선택이 열 영역보다 가까운 위쪽 행을 우선해 왼쪽 학생을 2반으로 읽는다. 사진 좌표가 맞으면 `confirmed=true`, 파일명은 `10201_합성학생.png`가 된다.
- 근거: 독립 합성 함수 실행. [roster.ts](../../modules/photo-extract/src/roster.ts) 57~60행, [batch.ts](../../modules/photo-extract/src/batch.ts) 40~55행. 원본 TimeAlert에서도 계승한 취약점이며, 실제 나이스 양식에서 이 배치가 나타나는 빈도는 확인하지 않았다.
- 최소 수정 방향: 반 머리글의 적용 열 구간을 판정하고 모호하면 미확인으로 남긴다. 사진 좌표 일치와 학생 신원 판정의 확실성을 별도로 관리한다.

### A04 · P1 · 회의록 — 허용된 최소 창 크기에서 기록 목록 높이가 0이 된다

- 재현: 800×560 앱 → 회의록 → 합성 참석자 2명 등록 → 회의 시작 → 발언 기록.
- 결과: 입력란과 화자 영역은 보이지만 기록 목록의 스크롤 컨테이너 높이는 **0px**이다. 기록을 추가해도 볼 수 없다. 그리드 행 측정값은 `71.2px 0px 269.6px`였다.
- 근거: 실제 React 화면·DOM 측정. [회의록 레이아웃](../../modules/meeting-note/src/App.tsx) 184~215행. 호스트가 허용하는 최소 크기는 [lib.rs](../../apps/desktop/src-tauri/src/lib.rs) 159행이다. 모듈만 넓게 열어 보는 검사로는 놓치는 결함이다.
- 최소 수정 방향: 기록 목록의 최소 가용 높이를 보장한다. 낮은 창에서는 화자·도움말·종류 선택을 접거나 전체 작업 영역을 스크롤할 수 있게 한다. 기록을 희생해 보조 UI를 유지하지 않는다.

### A05 · P2 · 타이머 — 발표 숫자 위에 버튼이 겹친다

- 재현: 180분 설정 → 발표 모드. 1280×720의 넓은 모듈 화면에서도 재현된다.
- 결과: 272px 숫자에 행 높이가 92px만 배정되어 시작·리셋·발표 종료 버튼이 숫자 하단을 덮는다. 600px 폭의 모의 화면에서는 `3:00:00` 폭이 약 881px이라 좌우도 잘렸다.
- 근거: 화면 및 DOM 재현. [App.tsx](../../modules/timer/src/App.tsx) 48행. 좁은 화면의 잘림은 모의 전체화면 호출에서 확인한 것이며, 실제 Windows 전체화면 해상도에 대한 판정은 아니다. 넓은 화면의 겹침은 해상도 확대만으로 해결되지 않는다.
- 최소 수정 방향: 숫자 크기와 행 높이를 함께 산정하고 조작 영역을 분리한다. 실제 전자칠판·노트북 전체화면에서 최종 확인한다.

### A06 · P2 · 공통 셸 — 도구 카드가 키보드로 열리지 않는다

- 재현: 회의록 카드에 초점을 두고 Enter 또는 Space를 누른다.
- 결과: 카드에 초점은 가지만 아무 도구도 열리지 않는다. 마우스로는 열린다. 실제 DOM은 `role=group`, `tabIndex=0`이다.
- 근거: 브라우저 키보드 재현. [Home.tsx](../../apps/desktop/src/pages/Home.tsx) 70~75행은 Card에 `onClick`만 연결한다. 키보드 전체 조작을 요구하는 UI-005에 미달한다.
- 최소 수정 방향: 실제 실행 가능한 버튼 의미와 키보드 활성화 동작을 갖추게 한다.

### A07 · P2 · 이미지 자르기 — 한 장씩 저장할 때마다 폴더를 다시 골라야 한다

- 재현: 사진 여러 장을 넣고 현재 사진 저장 → 다음 사진 저장을 반복한다.
- 결과: 매 호출마다 폴더 선택과 새 결과 폴더 생성이 반복된다. 30장을 이 흐름으로 저장하면 선택 30회와 결과 폴더 30개가 생긴다. ‘저장 후 다음 사진’의 연속 작업 이점을 훼손한다.
- 근거: 두 번 저장 시 폴더 선택·생성이 각각 두 번 발생한 합성 실행. [batch.ts](../../modules/image-crop/src/batch.ts) 83~85행, [App.tsx](../../modules/image-crop/src/App.tsx) 238행.
- 최소 수정 방향: 한 편집 작업의 출력 목적지를 유지하고, 새 작업 시작이나 명시적 변경 때만 다시 고른다. 원본 덮어쓰기 방지 원칙은 유지한다.

### A08 · P2 · 사진 추출·자르기 — 저장 실패한 파일이 무엇인지 알 수 없다

- 재현: 여러 사진 저장 중 일부 파일 쓰기를 실패시킨다.
- 결과: 배치 함수가 실패 ID를 반환해도 화면은 실패 개수만 남긴다. 어떤 사진이 누락됐는지 찾을 수 없고 실패분만 다시 저장할 경로도 없다.
- 근거: 실패 ID 반환 합성 실행 및 화면 상태 전달 코드. [사진 추출](../../modules/photo-extract/src/App.tsx) 138~145행, [자르기](../../modules/image-crop/src/App.tsx) 231~236행. 읽기 실패 목록은 존재하지만 저장 실패 목록과는 다르다.
- 최소 수정 방향: 파일별 저장 결과와 실패분 재시도를 제공한다. 큰 배치일수록 전체 개수만으로 성공을 판단하게 해서는 안 된다.

### A09 · P2 · 이미지 압축 — ‘파일 추가 시 바로 압축’이 파일 선택에는 적용되지 않는다

- 재현: 저장 폴더를 선택하고 바로 압축을 켠다 → 파일 선택으로 이미지를 추가한다.
- 결과: 목록에만 들어가고 자동 압축되지 않는다. 자동 실행은 드롭 이벤트에만 연결돼 있다.
- 근거: 새 합성 UI 재현 및 [App.tsx](../../modules/image-compress/src/App.tsx) 27~39행.
- 최소 수정 방향: 선택과 드롭을 동일한 추가·실행 경로로 처리한다. 제품 문구와 실제 동작을 일치시킨다.

### A10 · P2 · 이미지 압축 — 파일을 추가하면 이전 결과와 실패 재시도 경로를 잃는다

- 재현: 일부 실패가 있는 압축 결과 생성 → 새 이미지 추가. 파일 선택 창에서 취소해도 빈 배열이 같은 경로에 들어간다.
- 결과: 이전 결과 목록과 결과 폴더 버튼이 초기화된다. 디스크 파일은 남지만 실패 항목 확인과 재시도가 어려워진다.
- 근거: 새 합성 UI 재현 및 [App.tsx](../../modules/image-compress/src/App.tsx) 32~38행.
- 최소 수정 방향: 완료 결과와 대기 파일을 분리하고, 입력 선택 취소는 기존 상태를 바꾸지 않는다.

### A11 · P2 · 지도일배정기 — 없는 날짜에 메모를 저장할 수 있다

- 재현: 10월 31일 선택 → 11월로 변경 → 날짜 메모 작성 → 저장.
- 결과: 달력에는 31일이 없는데 편집 패널에 ‘31일 요일’이 남고 `memo["31"]`도 저장된다.
- 근거: 합성 UI 및 저장값 재현. [App.tsx](../../modules/duty-planner/src/App.tsx) 163~169행, 485행, 542행.
- 최소 수정 방향: 월 전환 시 선택일을 유효 범위로 옮기고, 존재하지 않는 날짜에 대한 모든 편집을 차단한다.

### A12 · P2 · 회의록 — 과거 기록 수정 후 검토하던 위치를 잃는다

- 재현: 기록 목록 중간에서 과거 기록 수정 → 저장.
- 결과: 무조건 맨 아래로 이동한다. 합성 스크롤 측정에서 `scrollTop`이 200에서 2000으로 바뀌었다. 원본은 해당 행을 갱신해 검토 위치를 유지한다.
- 근거: 합성 UI 재현. [App.tsx](../../modules/meeting-note/src/App.tsx) 465~467행.
- 최소 수정 방향: 새 기록 추가와 기존 기록 편집을 구분하고, 편집에는 위치를 유지한다.

### A13 · P2 · 퀵캡처 — 마지막 세션 종료 후 앱 내부 복귀 경로가 사라진다

- 조건: 캡처 중 메인 창을 닫아 백그라운드로 보낸다 → 트레이에서 캡처 세션 종료.
- 코드상 결과: 메인 창은 숨겨진 상태로 남고 오버레이·단축키·세션은 정리되며 트레이도 숨겨진다. 프로세스는 남는다.
- 근거: **Windows 실기 미검증, 코드 추적**. [lib.rs](../../apps/desktop/src-tauri/src/lib.rs) 186~191행, [capture_host.rs](../../apps/desktop/src-tauri/src/capture_host.rs) 1086~1117행, 1185행, 1304~1306행.
- 제한과 복구: 실행 아이콘으로 앱을 다시 실행하면 single-instance 처리(lib.rs 229~235행)가 메인 창을 다시 보여 준다. 따라서 ‘복구 불가능’이나 ‘프로세스 강제 종료 필요’라고 판정하지 않는다.
- 최소 수정 방향: 마지막 세션 종료 시 메인 창을 표시하거나 다시 열 수 있는 트레이를 유지한다.

### A14 · P2 · 퀵캡처 — 화면 최상단 캡처에서 도구 모음이 화면 밖으로 나간다

- 조건: 위쪽에 다른 모니터가 없는 화면에서 캡처 영역의 y를 0으로 지정한다.
- 코드상 결과: 4px 테두리일 때 외부 창 y는 배율 100%에서 −40px, 200%에서 −76px가 되어 도구 모음이 위로 벗어난다.
- 근거: **좌표 계산 확인, Windows 실기 미검증**. [overlay_geometry.rs](../../crates/deck-core/src/overlay_geometry.rs) 30~32행. 원본에도 비슷한 제약이 있어 이번 이식에서 새로 생긴 문제로 단정하지 않는다.
- 최소 수정 방향: 캡처 좌표는 유지하면서 도구 모음을 화면 안쪽에 놓는 배치 규칙을 둔다.

### A15 · P2 · 퀵캡처 — 허용하는 작은 영역에서 이동·더블클릭이 막힌다

- 조건: 캡처 영역을 허용 최솟값인 5×5px로 만든다.
- 코드상 결과: 변의 8DIP 크기 조절 영역이 중앙을 덮는다. 중앙 자체를 누른 경우만 허용하는 이동·더블클릭 캡처를 쓸 수 없다. 원본은 최소 100logical px를 보장했다.
- 근거: **코드 추적, Windows 실기 미검증**. [capture.rs](../../crates/deck-core/src/caps/capture.rs) 212행, [CaptureOverlay.tsx](../../apps/desktop/src/CaptureOverlay.tsx) 37~40행, 189~202행.
- 최소 수정 방향: 조작 가능한 최소 창 크기를 보장하거나, 작은 캡처 영역에서도 별도의 이동·캡처 수단을 제공한다.

### A16 · P2 · 타이머 — 버튼에서 Space를 누르면 다른 동작이 실행된다

- 재현: 멈춘 타이머에서 리셋 버튼에 초점을 두고 Space를 누른다.
- 결과: 리셋 활성화 대신 타이머가 시작된다. 전역 키 처리기가 입력 필드만 제외하고 버튼의 Space까지 가로챈다. 반복 keydown을 걸러내는 조건도 없다.
- 근거: 버튼 Space는 브라우저 실행 확인, 길게 누른 키 반복은 코드 추적. [App.tsx](../../modules/timer/src/App.tsx) 107~124행.
- 최소 수정 방향: 버튼 등 대화형 요소의 기본 키 동작을 존중하고 `event.repeat`을 제외한다.

### A17 · P2 · 타이머 — 시스템 시계 보정이 남은 시간을 바꾼다

- 재현: 60초 타이머의 시작·현재 시각을 합성 값으로 주고 10초 경과 후 시스템 시각 값만 뒤로 이동시킨다.
- 결과: 50초 남았던 타이머가 60초로 돌아간다. 앞으로 크게 이동시키면 즉시 종료된다.
- 근거: 순수 시간 계산 실행. [timer.ts](../../modules/timer/src/timer.ts) 25~30행, [App.tsx](../../modules/timer/src/App.tsx) 74행의 `Date.now()`. 실제 PC 시각은 변경하지 않았다.
- 최소 수정 방향: 경과 시간에 단조 증가 시계를 사용하고 절전·복귀 시 정책을 명시한다.

### A18 · P2 · 지도일배정기 — 작은 창에서 달력과 편집 결과를 왕복해야 한다

- 재현: 800×560 앱에서 지도일배정기를 연다.
- 결과: 600×468 모듈 영역의 달력은 y=334에서 시작해 y≈811까지 이어진다. 날짜 편집은 그 아래로 배치된다. 첫 화면에는 달력 첫 주 일부만 보이며, 날짜를 고르고 담당자를 바꾸려면 계속 아래로 갔다가 달력으로 되돌아와야 한다.
- 근거: 화면 및 DOM 측정. [App.tsx](../../modules/duty-planner/src/App.tsx) 56행, 82~87행의 단일 열 전환. 스크롤 자체가 막힌 것은 아니다.
- 최소 수정 방향: 선택 날짜 편집을 달력 근처의 고정 패널·접이식 영역으로 유지한다. 상단의 상시 설정이 달력 작업 공간을 과도하게 차지하지 않게 한다.

### A19 · P3 · 셸 — 카테고리를 바꿔도 이전 검색 필터가 남는다

- 재현: 이미지 카테고리에서 ‘캡처’ 검색 → 수업 카테고리로 이동.
- 결과: 수업 도구가 설치돼 있어도 ‘검색 결과가 없어요’만 나온다. 검색어는 그대로 남는다. 덱에서 카테고리로 이동할 때와 카테고리 사이를 이동할 때의 검색 초기화도 다르다.
- 근거: 브라우저 재현. [Home.tsx](../../apps/desktop/src/pages/Home.tsx) 33행의 지역 상태와 [App.tsx](../../apps/desktop/src/App.tsx)의 페이지 분기.
- 최소 수정 방향: 카테고리 전환 시 초기화하거나, 범주를 넘어 유지되는 검색이라는 점과 즉시 해제 동작을 명확히 한다.

## 기존보다 불편해진 이유에 대한 판단

1. **공통 컴포넌트 사용과 UX 보존을 같은 것으로 취급했다.** 토큰·Fluent 컨트롤·모듈 격리를 지키더라도, 저장 목적지 재선택과 편집 초안 처리처럼 사용자가 반복하는 행동이 바뀌면 원본보다 느리고 위험해진다.
2. **‘보이는 기본 상태’ 위주로 확인하고 작업 중 상태 전환을 충분히 확인하지 않았다.** 작성 중 초안→기존 기록 수정, 직접 배정→해제, 일부 저장 실패→새 파일 추가에서 결함이 드러났다.
3. **모듈 단독 화면과 실제 셸 안의 가용 공간을 혼동했다.** 최소 창의 실제 모듈 영역은 훨씬 좁다. 회의록은 보조 영역이 살아 있고 본업인 기록 목록이 0px가 된다.
4. **정확한 좌표와 정확한 학생 판정을 혼동했다.** 자동화의 자신감 표시는 개별 알고리즘 단계가 아닌 최종 결과의 확실성을 나타내야 한다.
5. **병렬 구현 뒤 공통 작업 흐름의 통합 검수가 부족했다.** 도구 카드의 키보드, 타이머의 전역 Space, 캡처 종료 후 창 수명주기처럼 각 함수가 아닌 앱 전체에서 검증해야 하는 문제가 남았다.

이 판단은 현재 결함이 드러난 지점에 대한 해석이다. 과거의 모든 작업 과정이나 모든 원본 기능을 조사했다는 의미는 아니다.

## 이번에 결함으로 다시 세지 않은 항목

- 달력의 일요일·공휴일 빨강, 토요일 파랑, 직접 배정과 수행 기록의 보조 색·기호는 현재 화면에 있다. 이전 색상 누락을 현재 결함으로 반복하지 않았다.
- 과거 퀵캡처의 두 개 불투명 창 문제는 현재 소스가 단일 투명 창으로 바뀐 상태다. 이번에 Windows 창을 직접 조작하지 못했으므로 수정 성공이나 재발을 확정하지 않았다.
- PDF 사진명렬표 추출은 원본 simple_crop에 있으나 현재 이미지·명렬표 모듈에는 이식되지 않았다. 이는 별도의 이식 범위 점검 대상이며 이번 19건의 결함 수에는 포함하지 않았다.
- 매크로, 파일 검색, PDF 마스킹, Office 변환, CoolReserve 등 미구현 도구의 부재를 현재 구현 결함으로 세지 않았다.
- 전체 보안 감사, 실파일 호환성 전수 조사, 수백 파일 성능, Windows IME 고속 입력, 다중 모니터 DPI 이동, 실제 캡처 픽셀·저장 지연은 완료했다고 주장하지 않는다.
