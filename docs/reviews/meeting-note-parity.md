# 회의록 원본 기능 대조

대상: 읽기 전용 `D:/codex_work/meeting_note/index.html`, TeacherDeck `meeting-note` 0.5.0.

| 원본 기능                                         | 모듈 결과                                                                            |
| ------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 참석자 시작, 화자 유지, Enter/IME, 줄바꿈, 단축키 | 기존 0.2 유지                                                                        |
| 동명이인 분리, 명단 탈퇴 화자의 기록 보존         | 내부 ID, 12명 입력 및 기록 화자 최대 24명 보존                                       |
| 개별 기록 화자 즉시 변경, 화자 건수               | 짧은 기록 행의 화자 버튼으로 선택 상자 열기, 사이드바 건수                           |
| 안건 제목 수정, 삭제 확인 및 앞 안건 합류         | 일반 수정으로 제목 변경, 확인 삭제 후 기록 유지                                      |
| 위원회 동일명 갱신, 삭제, JSON 입출력             | 앱 명단 갱신, 확인 삭제, 원본 JSON 가져오기 및 전체 파일 저장                        |
| 공개 마지막 발언 종료 시간, 비공개 제외           | 공개 본문 기록만 종료 시간 계산                                                      |
| 안건별 문서, 빈 안건, 결정 목록, 조치 표          | 텍스트/마크다운/HTML, 줄바꿈 및 HTML·표 구분자 이스케이프                            |
| 입력 포커스 안전망, undo 메모리 제한              | 편집 필드 밖 문자 입력 시 입력창 포커스, 50개·6MB 한도                               |
| 한글·워드 서식 클립보드 쓰기                      | 승인된 clipboard 1.0으로 공개용 표·제목·굵은 화자를 복사, 구형 호스트 파일 저장 유지 |
| 저장소와 파일 로컬 처리                           | storage + fs 1.1 SDK만 사용, 기존 파일 덮어쓰기 없음                                 |

서식 클립보드는 사용자가 `clipboard-output.md` 제안을 승인한 범위에서 구현한다. 원시 HTML이나 클립보드 읽기는 모듈에 노출하지 않는다.

추가 회귀: 타이핑과 화자 선택으로 기존 기록의 시각 포맷·목록 렌더링이 반복되지 않는지 40개 합성 기록으로 확인한다. 내보내기 창을 닫은 상태에서는 본문 생성도 생략한다. 현재 참석자 수를 따로 보관해 이전 화자가 다시 단축키 슬롯을 차지하지 않게 한다. 안건 등록은 발언 건수에 포함하지 않는다.

브라우저에서 참석자 등록, Alt+2, 여러 줄 입력과 Enter 저장, 화자 제외 후 기존 기록 보존 및 명단 재편집을 확인했다. SDK mock을 썼으며 실제 Windows IME 및 한글·Word 서식 붙여넣기 확인은 별도 수동 검증이 필요하다. 통합 검사 결과는 개발 현황 문서에 기록한다.

## 0.5.0 원본 워크플로 화면 복원

원본 `index.html` 54~123·215~239의 상단 도구줄 → 중앙 기록/오른쪽 화자 → 하단 전체폭 2줄 입력 구조를 기준으로 복원했다. 초기 이식 화면은 기록마다 제목·화자 선택 label·ComboBox·본문을 여러 줄로 쌓아 원본보다 정보 밀도가 낮았고, 화자별 색과 현재 안건 표시가 빠져 있었다.

- 중앙 기록을 시간/색 있는 화자/종류·본문/행 동작으로 구성하고 안건은 배경 있는 구분 행으로 표시한다. 공통 ListView를 유지하면서 회의 기록 행의 큰 기본 최소 높이만 제거했다. 화자 정정은 행 버튼으로 즉시 열어 선택한다.
- 오른쪽에 원본 번호키 표식·화자별 Fluent palette 보조색·선택 강조·발언/결정/조치/안건 통계를 배치한다. 단축키 이름은 접근 가능한 label에도 유지한다.
- 하단 전체폭 입력창 위에 현재 안건·화자·입력 접두어를 함께 표시한다. 종류/비공개 보조 설정은 접어 연속 입력이 중심이 되게 했다. Enter/IME/강제 기록·수정·취소·자동 저장 핸들러는 유지했다.
- 시작 화면은 익숙한 두 열 입력 폼의 폭을 제한하고 참석자에 바로 초점을 둔다. 저장된 위원회가 있으면 초기 화면에서 바로 불러오는 버튼을 보여 준다.

6개 파일·24개 테스트 통과. 기존 한글 조합 한 번 기록·단축키·화자 정정·수정/삭제/undo·공개 복사·보관 전환을 유지했고, 40개 기록의 시간 포맷이 타이핑/화자 선택마다 다시 실행되지 않는 성능 회귀도 통과했다. 새 회귀는 현재 안건·번호키/색 표식·접힌 보조 설정·짧은 기록의 화자 변경·연속 기록 후 입력 초점을 확인한다. 모듈 ESLint 통과, TypeScript 해당 모듈 오류 없음. 최종 실제 화면 밀도와 확대 QA는 lead agent가 검증한다.

0.5.0 실제 브라우저에서는 합성 참석자 3명, Alt+2와 Enter 기록 뒤 화자/내용/입력 초점 유지를 확인했다. 1280×720 모듈 viewport에서 글자/행높이150% 상태 입력창은 y587.6~659.6이고 가로 넘침이 없었다. 시간 한줄·화자색·통계 줄분리도 확인했다. QA 상단 제어줄은 실제 모듈 높이 검증 때 제거했다.
