# 퀵캡처 통합 검토

기준일: 2026-10-10. 원본 `D:/codex_work/programs/QuickCapture`의 핵심 흐름(영역 유지·이동/크기 조절·단축키/더블클릭·자동 폴더 저장)을 승인한 [제안서](../proposals/quick-capture.md) 범위로 이식해요.

## 구현 구조

모듈은 React/TypeScript와 `@deck/ui`를 사용하고 네이티브 기능은 Rust 호스트의 승인된 캡으로만 호출해요. 영역과 툴바는 셸의 고정 `/overlay` 화면을 사용하는 하나의 투명 도구 창이에요. 모듈이 네이티브 창에 HTML·주소·경로를 전달하지 않아요. 호출 창 label로 소유자를 확인하며 main 호스트 API는 보조 창에 제공하지 않아요.

화면 크기와 좌표는 물리 픽셀을 원천으로 해요. `overlay.rect`는 실제 저장할 내부 영역이에요. 호스트가 물리 테두리 inset과 상단36DIP 툴바 띠를 추가해 native 창 크기를 계산하고 이동/크기 변경 때 역변환해요. CSS 테두리는 같은 물리 inset을 창 배율로 나눠 표시해요. 하단은 거의 투명한 hit-test 면이고30DIP 미니 툴바만 상단 오른쪽에 있어요. 최종 픽셀과 native 투명성은 실제 Windows 검증이 필요해요.

## 확인한 동작

- SDK mock 호스트에 연결한 실제 모듈 화면에서 시작 버튼이 폴더 선택을 거쳐 영역·단축키·세션을 만들어요.
- 1회 캡처 → 영역 숨김 → 설정 컴포넌트 제거 → 재실행에서 저장 장수 1장, 숨김 상태와 같은 폴더가 복원됐어요. 재실행이 캡처를 자동 시작하지 않으며 진행 중인 세션에 연결해요.
- 어두운 테마와 150% 확대에서 세부 설정까지 가로 넘침이 없었어요(브라우저 viewport 1280, document width 1265).
- 0.2.1 UI는 합성 문서 위 투명 iframe에서 작은 도구줄과 캡처 영역이 하나로 표시돼요. 실제 CaptureOverlay의 body/root 배경 alpha 0, 캡처 면 alpha 0.004를 확인했고 뒤의 글·표·색상 칸이 그대로 보였어요. 도구줄 버튼은 1회 동작에 표시 장수를 1 올렸어요. 125% 브라우저 배율의 내부 영역 계산은 표시값600×400 물리 픽셀과 반올림 오차 이내로 맞았어요. Windows 창 합성이나 실제 이미지 저장을 확인한 것은 아니에요.
- 수정한 셸 테스트는 같은 창에 미니 툴바5개 동작과 캡처 영역이 함께 있고 더블클릭·Enter가 각각 한 번 캡처하며, 작업 중 비활성화·투명 문서 배경·상태 구독 해제를 확인해요. 실제 Tauri event API 테스트는 모든 구독이 현재 Window target으로 전달되는지 확인해요.
- 브리지 회귀 테스트는 캡처 결과 metadata가 살아 있는 소유 모듈에만 전달되고, 다른 모듈이나 내려간 iframe으로 전달되지 않는지 확인해요.

브라우저 검증은 파일 선택·화면 캡처·단축키를 SDK 경계에서 모의했어요. 실제 인코딩을 확인한 이미지 자르기·압축 검증과 구분해요.

## 설정 화면 복원과 브라우저 회귀

원본 main.py의 저장/캡처 두 설정 묶음을 복원했어요. 실제 키 조합 입력, 색 선택창, 유효한 변경의 250ms 자동 적용을 제공하고 좌표·직접 키 선택·색 코드는 고급 설정에 둬요. 기본 테두리는 신규 설정에만 빨강·4px을 사용하고 기존 설정은 보존해요.

실제 화면에서 Ctrl+Shift+X 입력 → 한 장 캡처 → 설정 닫기/다시 열기로 키와 장수 유지, 어두운 테마·150% 확대를 확인했어요(SDK mock). 확대에서 Fluent Dropdown 최소 폭이 옆 카드를 가리는 문제를 발견해 공통 선택/숫자 입력을 부모 폭 안에 맞췄어요. 색 입력의 input 이벤트로 선택 즉시 반영되는 것도 실제 브라우저에서 확인했어요.

## 출시 전 Windows 확인

현재 제공된 컴퓨터 제어 도구에 네이티브 앱 조작 기능이 없어 다음 항목을 자동 확인하지 못했어요. 빌드·단위 테스트 통과만으로 이를 통과했다고 보지 않아요.

1. 실제 두 모니터와 서로 다른 DPI에서 합성 격자 캡처의 크기·모서리와 테두리/툴바 미포함.
2. 다른 앱 위 고정 영역의 끌기·크기 조절·더블클릭, 전역 단축키, 충돌 후 이전 키 유지, 트레이에서 설정 다시 열기와 세션 종료.
3. 캡처 중 영역 숨김/종료, 폴더 삭제·분리·권한 변경, 잠금 화면·RDP·보호된 화면의 실패 안내.
4. NSIS 설치·제거와 실제 Windows 200% 배율에서 조작부.

폴더 권한·새 파일 저장·복구·원본 보존은 별도의 실제 Windows 파일시스템 테스트로 검증해요: [저장 권한 검토](destination-grants.md).

## 실제 회귀와 검증 한계

0.2.0의 사용자 스크린샷에서 두 창과 흰색 캡처 영역이 확인됐어요. 이전 브라우저 mock은 native 이벤트 범위와 실제 투명성을 검증하지 못했어요. 단일창과 명시 Window target으로 고쳤지만 Windows 수동 투명성·DPI·픽셀 검증은 아직 완료하지 않았어요.
