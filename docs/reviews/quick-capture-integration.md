# 퀵캡처 통합 검토

기준일: 2026-10-10. 원본 `D:/codex_work/programs/QuickCapture`의 핵심 흐름(영역 유지·이동/크기 조절·단축키/더블클릭·자동 폴더 저장)을 승인한 [제안서](../proposals/quick-capture.md) 범위로 이식해요.

## 구현 구조

모듈은 React/TypeScript와 `@deck/ui`를 사용하고 네이티브 기능은 Rust 호스트의 승인된 캡으로만 호출해요. 영역과 툴바는 셸의 고정 `/overlay` 화면을 사용하는 별도 창이에요. 모듈이 네이티브 창에 HTML·주소·경로를 전달하지 않아요. 호출 창 label로 소유자를 확인하며 main 호스트 API는 보조 창에 제공하지 않아요.

화면 크기와 좌표는 물리 픽셀을 원천으로 해요. 영역 창의 전체 좌표가 캡처 영역이며, 툴바는 별도 창이어서 크롭 inset을 계산하지 않아요. 테두리의 화면 표시 두께만 창 배율에 맞춰 조정해요. 최종 픽셀과 두 창 숨김 여부는 실제 Windows 검증이 필요해요.

## 확인한 동작

- SDK mock 호스트에 연결한 실제 모듈 화면에서 시작 버튼이 폴더 선택을 거쳐 영역·단축키·세션을 만들어요.
- 1회 캡처 → 영역 숨김 → 설정 컴포넌트 제거 → 재실행에서 저장 장수 1장, 숨김 상태와 같은 폴더가 복원됐어요. 재실행이 캡처를 자동 시작하지 않으며 진행 중인 세션에 연결해요.
- 어두운 테마와 150% 확대에서 세부 설정까지 가로 넘침이 없었어요(브라우저 viewport 1280, document width 1265).
- 실제 360×128 DIP 브라우저 프레임에서 툴바의 6개 버튼과 저장 장수 갱신을 확인했어요. 가로/세로 넘침 없이 크기에 맞았어요. 이 확인도 네이티브 창 테스트와 구분해요.
- 셸 오버레이 테스트는 더블클릭·Enter가 각각 한 번 캡처하고, 툴바 6개 동작·작업 중 캡처 비활성화·상태 구독 해제를 확인해요.
- 브리지 회귀 테스트는 캡처 결과 metadata가 살아 있는 소유 모듈에만 전달되고, 다른 모듈이나 내려간 iframe으로 전달되지 않는지 확인해요.

브라우저 검증은 파일 선택·화면 캡처·단축키를 SDK 경계에서 모의했어요. 실제 인코딩을 확인한 이미지 자르기·압축 검증과 구분해요.

## 출시 전 Windows 확인

현재 제공된 컴퓨터 제어 도구에 네이티브 앱 조작 기능이 없어 다음 항목을 자동 확인하지 못했어요. 빌드·단위 테스트 통과만으로 이를 통과했다고 보지 않아요.

1. 실제 두 모니터와 서로 다른 DPI에서 합성 격자 캡처의 크기·모서리와 테두리/툴바 미포함.
2. 다른 앱 위 고정 영역의 끌기·크기 조절·더블클릭, 전역 단축키, 충돌 후 이전 키 유지, 트레이에서 설정 다시 열기와 세션 종료.
3. 캡처 중 영역 숨김/종료, 폴더 삭제·분리·권한 변경, 잠금 화면·RDP·보호된 화면의 실패 안내.
4. NSIS 설치·제거와 실제 Windows 200% 배율에서 조작부.

폴더 권한·새 파일 저장·복구·원본 보존은 별도의 실제 Windows 파일시스템 테스트로 검증해요: [저장 권한 검토](destination-grants.md).
