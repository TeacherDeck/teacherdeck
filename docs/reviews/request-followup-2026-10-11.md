# 사용자 후속 요청 처리와 검증

2026-10-11. 주 작업자가 통합을 맡고 GPT-6.1 Sol 세 작업자가 지도일·화면·Windows 경계를 병렬 구현했다. 컴퓨터 유즈를 사용하지 않았으며 사용자 문서·명단·메신저 메시지 대신 합성 자료를 사용했다.

## GitHub와 우선순위

- 최초 조회 시 TeacherDeck의 독립 이슈는 열린 것과 닫힌 것 모두 0개였다. 이슈 API에 보이는 PR과 일반 이슈를 구분했다. 공동작업자의 최신 병합 PR은 [#11](https://github.com/TeacherDeck/teacherdeck/pull/11), `main`은 `6d08e85`이며 이미 현재 브랜치에 반영돼 있었다.
- PR #11의 확인 요청은 실제 앱 뒤로가기 클릭, 타이머·회의록 유지 화면 전환, 자리 배치 테스트 시간 초과 재발 여부다. 자동 검사 통과와 Windows 화면 실기는 구별한다.
- 기존 0.4.0 작업 `808d7ca`를 원격에 올리고 [PR #13](https://github.com/TeacherDeck/teacherdeck/pull/13)을 만들었다. [GitHub 검증](https://github.com/TeacherDeck/teacherdeck/actions/runs/38119547971)은 전체 verify와 설치본 빌드까지 통과했다. 이는 이후 0.5.0 변경의 검사 결과를 대신하지 않는다.
- TimeAlert의 남은 도구는 [이슈 #12](https://github.com/TeacherDeck/teacherdeck/issues/12)에 `rochelobeJYJ` 담당, 사용자 작업 예정으로 기록했다. 세부 범위는 [후속 목록](../TIMEALERT_BACKLOG.md)에 있다. 기존 백업 호환과 학생 화면을 삭제하거나 기능 전체를 미구현으로 되돌려 분류하지 않는다.

## 결함을 찾아 보완한 항목

- OCR 기본 문단 분할이 짧은 한국어 이름 줄을 놓치는 반례를 실제 Worker로 재현했다. sparse-text 방식으로 바꾼 뒤 한국어 라벨 인식을 다시 확인했다.
- 마지막 OCR 진행 통지 또는 기존 문서 정리 중 취소해도 새 결과를 적용할 수 있는 경계를 제거했다. 새 결과를 적용하기 직전에 취소를 확인하고, 이전 문서 정리는 commit 뒤 수행한다.
- 낮은 OCR 신뢰도를 전체 안내에만 두면 검색 후 사라지는 문제를 발견했다. 페이지 상태·페이지 선택 목록·해당 쪽 경고에 지속 표시한다.
- 재탐색 때 직접 영역과 기존 선택 해제를 유지하고 전체 후보 한도를 함께 확인한다.
- 가져온 지도일 자료의 block ID가 다르지만 실제 시각이 겹치는 반례를 검사해 직접·실제 수행 교사의 시간 충돌을 차단한다.

- 영상 작업자 준비 파일을 읽기 잠금한 뒤 기대 SHA와 다시 대조하고, 파일 드롭과 결과 게시의 잠금 순서를 통일해 교착을 막았다.
- YouTube에서 분리 영상·음성이 없고 합본 MP4만 제공할 때도 기존 합본 경로를 유지한다. 고정된 로그인·연결·크기 제한 안내만 화면에 전달한다.
- D-day 복구 회귀는 확인창 제거 이후 접근성 상태 복원까지 기다리며, 손상 자료의 보존 실패 시 잠금과 복구 성공 후 해제를 그대로 검증한다.
- 지도일 상세 편성 테스트는 전체 화면을 반복 탐색하던 접근성 조회를 해당 그룹 안으로 좁혔다. 검증 항목과 시간 제한은 그대로 유지했다.
- OCR Worker가 참조하는 원본 라이선스 파일까지 최종 모듈에 동봉하고, 엔진·언어 자료 9개 해시와 고지 파일의 원문을 대조했다.

## 확인한 증거

- PDF 마스킹 지정 회귀 7파일·39개 통과. OCR 취소·시간 초과·부분 실패 원자료 보존·재실행 중복 방지·낮은 신뢰도 안내·기존 raster 출력 회귀 포함 (`target/ocr-all-tests.log`).
- 사용자 화면 조작 없이 숨김 Chromium의 실제 로컬 Worker에 합성 PNG를 전달했다. 한국어 이름 라벨 인식, 전화번호 탐지, 해당 픽셀을 지운 후 전화번호 미검출, 외부 요청 0건을 확인했다 (`target/ocr-browser-result.json`). 합성 전화번호 외 일반 문서의 완전한 탐지나 OS 파일 저장을 입증한 것은 아니다.
- 지도일 지정 회귀 11파일·83개와 독립 타입·린트 통과. 500교사·120동시간 업무, 작은 배정 문제의 전수 최적값 대조, 취소·저장 실패·백업 시간 충돌 반례 포함 (`target/adversarial-review/duty-generalization-tests.log`).
- CoolReserve 고정 Windows 의존성 환경에서 272개 자동 검사 통과. 공개 116파일 허용목록과 ZIP·manifest 대조를 거친 배포본만 올렸다 (`target/coolreserve-release-20261011/tests-supported.log`).
- 실제 관리 Python에 허용하지 않는 명령·필드를 보내 두 거절 코드와 런타임 파일 해시 불변을 확인했다. 실제 쿨메신저 예약 등록과 현재 PC 네트워크 변경은 하지 않았다.

- 공개 Creative Commons 시험 영상으로 실제 관리 실행 환경 준비, 영상·음성 다운로드, FFmpeg 무손실 결합, Rust MP4 두 트랙 검사, append-new 출력 두 번을 확인했다. 최종 파일 38,776,395바이트, 동일 이름의 두 출력은 서로 다르고 기존 파일 보존·취소·시간 초과·staging 정리가 검증됐다 (`target/media-review/native-proof-result.json`). OS 폴더 선택 대화상자는 이 검증에 포함하지 않았다.

## 최종 통합 검사

0.5.0 최종 `pnpm verify` **16단계 모두 통과**했다. JavaScript **146파일·1,330개**, Rust **271개(core 104·host 164·한글 경계 3)**로 합계 **1,601개**다. 관리 Python의 8개 회귀도 Windows 호스트 검사에서 호출한다. 근거는 `target/review-050/verify-final-serial.log`다.

Windows 릴리스 빌드와 최종 NSIS 구성이 통과했다. 모듈 20개, 모듈 관련 파일 22개, 네이티브 파일 601개, NSIS 자산 항목 623개의 포함 경로·버전·크기·SHA-256을 대조했다. 한글 경계 DLL은 실행 파일에 포함된 바이트와 설치 자산이 같음을 확인했다. OCR 자산의 9개 해시와 Worker 원본 고지도 일치한다. 근거는 `target/review-050/build.log`, `bundle-canonical.log`, `bundle.json`, `ocr-bundle.json`이다.

- 설치본: `target/review-040/release/bundle/nsis/TeacherDeck_0.5.0_x64-setup.exe`, **39,281,722바이트(37.46MiB)**
- 설치본 SHA-256: `c1cdee42dae2b98c759a4b488bf43aab410d9654fd85aa3712052e26cf8f9aff`
- 실행 파일 SHA-256: `532b0a8a535e8d282ff7df2f40973e5aea2df4b645a49bbdf139e96100a7a87c`

설치·제거, 실제 Windows 화면의 뒤로 버튼·IME·캡처·화면 전환 검수와 실제 메신저 등록·네트워크 전환은 이번 CLI 검증에 포함하지 않았다. HWP→HWPX는 보안 모듈 등록 실패가 남아 있다. 이번 결과는 로컬 검사이며 0.4.0 원격 CI 통과를 0.5.0 결과로 대신하지 않는다.
