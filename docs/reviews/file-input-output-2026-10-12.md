# 파일 드래그 입력·기본 저장 위치 검수

- 범위: 파일 드래그 입력 피드백과 결과 저장 위치 두 항목
- 작업 브랜치: `codex/file-drop-output`
- 기준: 기존 고급 편집기 0.7.0과 main의 PDF 내용 보존 수정 통합
- 앱·SDK·캡: 0.8.0 / 0.9.0 / fs 1.4.0

템플릿을 제외한 22개 모듈을 점검했다. 파일 입력이 있는 17개 모듈을 수정했고 나머지 5개는 두 요구와 관련된 기존 동작을 확인했다. 기존 자료 형식, 변환·압축·마스킹 알고리즘, 보호된 원본 이름 변경, 메시지 등록은 변경하지 않는다.

## 보호와 반례

- 드래그 입력은 불투명 파일 핸들을 기존 검증으로 전달하며 파일 선택창을 열지 않는다. 처리 중·지원하지 않는 형식·같은 핸들의 중복 이벤트·읽기 실패를 안내한다. 동명이지만 다른 폴더의 파일을 이름만으로 제거하지 않는다.
- 별도 저장 폴더가 없으면 입력별 부모를 사용한다. 지정 폴더가 있으면 그 폴더를 직접 사용한다. 원본 없는 출력은 사용자가 폴더를 선택한다. 자동 결과 하위 폴더 생성과 다른 위치로의 묵시적 우회를 제거한다.
- 이름 충돌은 호스트의 배타적 새 파일 게시와 번호로 해결한다. 원본·기존 파일을 지우거나 덮어쓰지 않는다. 반환한 출력 위치 핸들로 같은 폴더의 다른 파일을 읽거나 목록을 얻지 못한다.
- 복원 취소 후 내부 자료 복원, 새 명단·새 회의·직접 붙여넣기, 표 입력 후 JSON 전체 복원의 출처 혼선을 교차 검토한다. 파일을 읽는 중에도 파일명이 보이는지 지연된 입력으로 확인한다.
- 서로 다른 폴더의 출력 성공·실패를 섞었을 때 실패 항목에 마지막 성공 폴더를 표시하지 않는지 확인한다.

## 검증 상태

실제 주 작업공간에 범위별 수정만 통합한 뒤 `pnpm verify` 16단계를 모두 통과했다. JavaScript는 181개 파일의 1,611개 테스트, Rust는 291개 테스트로 합계 1,902개다. 생성물 일치·린트·타입·네이티브 자산 준비·Rust fmt/clippy/test/deny·모듈·SPDX·버전·문서·보안·라이선스·억제 검사를 우회 없이 실행했다. 로그는 `target/file-drop-output/verify.log`다.

교차 검토에서 발견한 복원 취소·재확인, 새 작업·보관 자료 전환, 성공/실패한 표 붙여넣기와 원본 시트 재선택의 출처 반례를 고치고 회귀 검사에 포함했다. 입력 읽기를 지연시켜 파일명이 읽는 중에도 보이는지 확인했다. 원본·권한 종류·소유 모듈·세대·출력 충돌·배치 종료 계약은 별도 호스트 테스트 4개로 검증했다.

쿨 예약실은 원작 체크아웃의 DCO 커밋 `bbad4407346b14d791c5e0b4aacb53bd7e54660b`을 공식 동기화했다. 공개 파일 allowlist 검사를 통과했고, 네이티브 코어 14개는 기존 바이트를 유지하며 모듈 24개 파일을 고정했다. 원작 커밋은 현재 로컬 작업 브랜치에 있다. 생성물은 고정 pnpm 12.10.1과 공식 `pnpm gen`으로 갱신했다.

정상 커밋 훅의 `verify:fast`와 Conventional Commits/DCO 검사도 통과했다. 기존 선택 검사인 gitleaks는 이 PC에 설치되어 있지 않아 실행되지 않았으며, 필수 `pnpm verify`의 보안·라이선스 검사는 실행하고 통과했다.

사용자의 요청에 따라 컴퓨터 유즈·브라우저 자동화·실제 메시지 등록은 수행하지 않았다.

## Windows 수정판 설치

`pnpm tauri build`로 `TeacherDeck_0.8.0_x64-setup.exe`를 만들었다. 크기는 39,564,592바이트(37.73MiB), SHA-256은 `7faea81203fd55fa60689c7bd09a22af2ebfcb5022c7d2ed8c381552af70c362`다. 기본 모듈 21개를 카탈로그·모듈 버전·fs 선언·ZIP 내부 체크섬·현재 dist와 대조하고, 네이티브 601개와 NSIS 입력 파일을 비교했다. 로그는 `target/file-drop-output/build-080.log`, 대조 보고서는 `target/file-drop-output/build-080-audit.json`이다.

빌드 캐시에 남은 이전 모듈 패키지 46개를 포함한 자산 트리는 먼저 작업공간에 보존하고 현재 자산과 일치시켰다. 설치 파일은 원래부터 현재 primary 자산을 참조한다는 NSIS 입력 대조를 통과했다. 기존 성공 후 빌드 정리 절차는 과거 설치 파일·모듈 산출물 19개(99,362,682바이트)를 정리했다.

앱 프로세스가 없는 것을 확인하고 앞선 최신판 설치 요청에 따라 사용자별 설치를 0.8.0으로 갱신했다. 남은 0.7.0 패키지 17개는 기존 빌드와 동일한 체크섬인 것만 작업공간에 보존 이동했으며 현재 패키지와 사용자 자료는 변경하지 않았다. 설치 레지스트리·실행 파일의 버전 0.8.0과 설치된 카탈로그·모듈·네이티브 전체 목록 및 해시를 대조했다. 실행 파일은 NSIS 표식 `UNK`→`NSS`의 3바이트 외에는 빌드와 같았다. 보고서는 `target/file-drop-output/installed-080-audit.json`이다. 검수 도구는 앱을 실행하지 않았으며 실제 화면 조작은 이번 범위에서 수행하지 않았다.
