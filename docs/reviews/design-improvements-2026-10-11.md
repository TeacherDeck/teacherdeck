# 공통 디자인·도구 UX 개선 검수

2026-10-11. 앱 0.6.1. 전체 검증·설치본 빌드·동봉 구성 대조 통과. 사용자 승인 범위는 [일곱 화면 개선안](../proposals/design-improvements-2026-10-11.md)이며, [공통 앱·모듈 계획](../proposals/app-module-design-2026-10-11.md)과 [ADR-0029](../adr/0029-compact-tool-workspaces.md)를 먼저 작성한 뒤 적용했다.

## 실제 브라우저 검수

컴퓨터 유즈 없이 Playwright CLI와 실제 React App, SDK 합성 호스트를 사용했다. 업무 자료는 합성이다. 실제 네이티브 명령과 파일 선택은 mock이므로 이 결과를 실캡처·Office 실변환 증명으로 사용하지 않는다.

### 공통 홈·정보 행

같은 20개 도구와 즐겨찾기 4개를 렌더했다. 홈 컴포넌트 주변에 40px 검수 상단바와 200px 레일 공간을 배치한 비교 화면이며 전체 네이티브 앱 창은 아니다. 첫 화면 실행 카드 수는 즐겨찾기 중복도 포함한다.

| viewport | 이전 → 이후 실행 카드 수 | 즐겨찾기 영역 높이 |
|---|---|---|
| 1280×720 | 10 → 11 | 236 → 82px |
| 1024×768 | 10 → 11 | 236 → 140px |
| 800×600 | 4 → 7 | 392 → 140px |

Ctrl+F 검색, Enter 실행, Space 별 토글, 두 테마의 CSS100/150/200%에서 가로 넘침 없음, 20개 실제 SVG 디코드·시트 육안 확인을 통과했다. 독립 `ModuleHost` 렌더에서 긴 제목·호환 경고·로드 오류의 800px/CSS200%도 넘침이 없었다. 기본 정보 행 높이는 52→28px이다.

증거: `target/design-qa/checks.log`, `host-checks.log`, `output/playwright/design-home-*.png`, `design-host-*.png`, `design-icons.png`.

### 파일 도구

두 모듈 × 세 크기(1280×720·1024×768·800×600) × 두 테마의 12조합과, 텍스트 토큰150%/브라우저 deviceScaleFactor2의 추가 12조합을 통과했다. 합성10개 파일을 사용해 미리보기 내부 스크롤 하나, 실행 영역으로 키보드 이동, Enter 실행·완료 결과를 확인했다. 이때 저장과 Office 코어는 합성 호스트다.

증거: `output/playwright/fileflows/summary.json`, PNG 36장.

### 지도일·퀵캡처

각 모듈에서 세 크기 × 두 테마 × 기본/텍스트 토큰150%/CSS200%의 18조합을 통과했다. 단독 모듈 viewport다. 지도일은 Enter 연속 명단 추가·명단 닫기 포커스·실제 배정 Worker·날짜 직접 선택·좁은 날짜 대화상자 복귀를 확인했다. 휴일/선택/제외/고정/수행 조합의 날짜 대비는 8가지에서 최소5.22:1이었다.

퀵캡처는 기억한 합성 폴더에서 Enter 한 번으로 시작, 폴더 재선택0회, 장수 갱신, 충돌시 활성 단축키 유지, 설정 밖 오류를 확인했다. 800px/CSS200%에서 아래로 밀렸던 지도일 실행 버튼은 월 요약 행으로 옮겨 수정했다.

증거: `output/playwright/design-duty/README.md`, `duty-text-matrix.json`, `capture-text-matrix.json`, `duty-colours.json`, `capture-flow.json`과 PNG.

### 메모·회의록

실제 App의 브라우저 조작 44개와 지정 UI 테스트 31개를 통과했다. 메모의 Ctrl+Enter·IME 조합 이벤트·수정 초안 보존·페이지/선택/포커스 유지·복구 흐름, 회의록의 12화자 단축키·기록·저장 실패 표시를 확인했다. 기록 100개가 있을 때 입력마다 지난 기록의 날짜 형식을 다시 계산하지 않는 회귀도 통과했다.

같은 합성 메모 20개의 첫 화면 목록 제목 수는 1280×720에서 4→5, 1024×768에서 3→5, 800×600에서 0→2개다. 선택 상세의 같은 제목은 이 수에 포함하지 않았다. 두 모듈과 이전 메모 화면의 세 크기·두 테마·기본/텍스트150%/CSS200%/동시 확대 72조합을 측정했다. 마지막 메모 수정 전 800px 동시 확대에서 발견한 두 테마의 가로 넘침은 실제 가용 폭에 따라 한 열로 바꾸어 수정했다. 최종 두 조합 재측정은 모두 문서/viewport 폭800px, 상세란 오른쪽718px로 넘침이 없었다.

증거: `output/playwright/design-writing-review.md`, `design-writing-interactions.json`, `design-writing-layout.json`(수정 전 문제 포함), `design-writing-final-layout.json`(최종 재검수). 브라우저 조합 이벤트를 실제 Windows IME 성능 검수로 간주하지 않는다.

### 독립 리뷰

파일 도구 담당 Sol이 홈·정보 행·아이콘과 메모·회의록 변경을 독립 검토했다. 메모 2쪽에서 고정/수정 후 다른 항목이 선택되던 문제와 마지막 메모 보관 후 body로 떨어지는 포커스를 찾아 수정했다. 실제 브라우저로 21개 목록의 2쪽→1쪽 이동 시 같은 메모·포커스 유지, 마지막 항목 보관 후 입력 포커스를 재확인했다.

## 통합 검사

첫 전체 검사에서 이미지 자르기 1건·지도일 2건이 5초 제한을 넘겼고 나머지 단계는 통과했다(`target/design-qa/verify.log`). 병렬 검수용 브라우저·서버를 종료하고 같은 `pnpm verify`를 재실행해 16단계 전부 통과했다(`target/design-qa/verify-final.log`). JavaScript 153파일 1,376개와 Rust 276개(core104·host169·한글 보안3), 총1,652개 테스트가 통과했다. 검사 대상·시간 제한·병렬 설정은 바꾸지 않았다. 생성물·린트·타입·Rust fmt/clippy·라이선스·보안·버전·문서 검사도 포함한다. 별도 gitleaks는 설치되지 않아 Git 훅에서 실행하지 못했다.

## 설치본과 산출물 정리

`pnpm tauri build`를 기존 `target/review-040`에서 실행해 Windows x64 설치본을 만들었다. `target/design-qa/build.log`, `check-061.ps1`, `bundle-061.json`에 결과와 재현 검사를 남겼다.

- 설치본: `target/review-040/release/bundle/nsis/TeacherDeck_0.6.1_x64-setup.exe`, 39,350,823바이트(37.53MiB).
- SHA-256: `54b6efa863ee2517c32f2d7581611e14e2266eeb56e3a10c2175d5168ee41e2e`.
- 기본 모듈20개의 패키지 크기·SHA-256·매니페스트 버전, 새 아이콘과 소스의 일치를 확인했다. QR Worker·필수 고지, 영상 다운로드 보류도 확인했다.
- NSIS 입력 자산623개의 존재와 기본 모듈20개 포함을 대조했다. 설치·제거 실기는 이 검사에 포함하지 않았다.
- 성공 후 기존 설치본1개와 이전 모듈 패키지20개, 총59,986,553바이트(약57.2MiB)가 자동 정리됐다. 실패한 빌드 뒤 정리하거나 Cargo 캐시를 복제하지 않았다.

기존 Vite 청크 크기 안내와 ts-rs serde 경고는 남아 있으나 빌드 오류는 없었다.

## 원작 연계와 한계

쿨 예약실 아이콘은 원작 체크아웃 `target/next-tools/coolreserve-source`의 로컬 DCO 커밋 `80f1481f9bba65016a1195ad4d6f5cb341817098`에서 기존 동기화 절차로 가져왔다. 모듈0.1.1과 원천 잠금이 일치한다. Python 실행 코어14파일과 원래 저작권 바이트는 변경하지 않았으며 코어 zip 해시도 이전과 같다. 이 새 원작 커밋은 아직 GitHub에 게시하지 않았다.

Windows가 읽기 매핑 중인 동일 소스를 다시 쓰다가 실패하는 동기화 문제도 발견해 동일 바이트는 유지하고 변경본은 완성된 임시 파일로 교체하도록 했다. 독립된 합성 Git 원천으로 동일 파일 읽기 매핑·변경본 일반 교체·삭제 공유 허용 매핑·삭제 공유 없는 매핑의 4조건을 검사했다. 앞의 3조건은 동기화와 바이트 대조가 성공했고 마지막은 원본을 보존하며 실패했다. 남은 임시 파일은 0개다. 합성 검증 결과는 `target/design-sync-test/mapping-results.json`에 기록했다.

Windows 실제 DPI·Mica, 화면낭독기, 퀵캡처 투명 영역/픽셀·전역 단축키, 이번 설치본의 설치·제거는 별도 검수 범위다. 새 OS 기능은 추가하지 않았다. 브라우저 CSS 확대나 deviceScaleFactor를 이 실기 검증과 동일하다고 보고하지 않는다.
