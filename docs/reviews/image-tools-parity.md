# 이미지 도구 원본 대응 검토

## 이미지 용량 줄이기

`modules/image-compress` 0.1.0은 여러 JPG·PNG·WebP를 선택/드롭하고 새 폴더에 압축 결과를 저장한다. Worker에서 정지 이미지 여부와 64MiB/4800만 화소 자원 상한을 확인하고 EXIF 회전을 적용한다. 투명도를 유지하는 WebP를 기본으로 사용하며 압축 결과가 작지 않으면 원본을 복사한다. 원본을 수정·삭제하지 않는다.

입력 바로 아래의 실행 버튼으로 저장 폴더 선택과 압축을 이어서 수행한다. 세션에서 저장 폴더를 고른 후 바로 압축을 켜면 다음 드롭부터 즉시 처리한다. 상세 설정은 기본 접힘이며 입력/결과 목록은 내부 스크롤한다. 개별 실패를 건너뛰고 재시도할 수 있다. 취소 시 Worker와 파일 전송을 중단하며 저장이 끝난 결과는 보존한다. 파일당 Worker 제한 시간은 90초다.

합성 vitest 8개(500개 순차 일괄 처리, 확장자와 실제 형식이 다른 원본 복사 포함)와 모듈 ESLint를 통과했다. 실제 브라우저 Worker로 2048×1024 투명 PNG → 1600×800 WebP, EXIF orientation 6 JPEG → 800×1600 WebP를 확인했다. 투명 픽셀 alpha 0과 잘못된 입력 1개를 건너뛴 나머지 2개 저장을 확인했다. 출력 이미지 디코딩까지 실제이며, 파일 선택·쓰기 경계는 SDK mock을 사용했다.

## 사진명렬표 원본과 차이

`D:/codex_work/programs/simple_crop`은 일반 사진 수동 크롭 도구가 아니다. 사진명렬표 PDF에서 사진 영역을 자동 인식하고 테두리를 제거하며 텍스트에서 학년·반·번호·이름을 읽어 파일명을 만든다. 정보 미확인 사진도 별도로 저장한다. PyMuPDF·OpenCV·Pillow 기반이므로 단순 일반 이미지 크롭을 만들어 원본 이식 완료라고 할 수 없다.

`D:/codex_work/time_alert/app/src/main/java/com/timealert/teacher/core/office/NeisRosterReader.kt`는 나이스 XLSX ZIP의 셀 텍스트와 drawing 앵커를 읽는다. 학생 텍스트를 기준으로 사진을 1:1 배정하고 미배정 사진 수를 경고한다. 사진 추출 도구에서는 명단 가져오기와 달리 학생과 매칭되지 않은 모든 `xl/media` 이미지도 보존해야 한다. 원본 reader는 첫 시트/첫 drawing에 한정되어 있어 새 모듈은 관계 파일을 따라 여러 시트/drawing을 찾아야 한다.

XLSX 추출은 `photo-extract`로 구현했으며 모듈 전용 MIT 의존성 fflate 0.8.3을 사용한다. ZIP 해제·학생 수집·사진 매칭은 Worker에서 수행하고, 크기를 제한한 XML은 DOMParser로 읽으며 순회 중 화면 제어권을 돌려준다. 자세한 범위와 증거는 [사진 추출 검토](photo-extract-parity.md)에 있다. PDF 사진 영역 인식은 XLSX 사진 추출과 별도 범위로 남는다.

## 기본 이미지 자르기와 실제 화면 검증

`image-crop`은 새 기본 편집 도구다. 직접 드래그·모서리 조절·방향키·정확한 숫자 좌표·고정 비율·90도 회전·좌우/상하 반전·현재/전체 저장·다음 사진 이동을 제공한다. JPEG EXIF 방향을 디코딩할 때 적용하고 PNG 투명도 또는 JPG 흰 배경으로 저장한다. 원본 바이트는 수정하지 않는다.

lead agent가 실제 브라우저 Worker 출력과 디코딩한 픽셀을 검증했다. 드래그 크롭 결과 **267×118 빨간 영역**, 90도 회전 결과 **400×800**의 모서리 **좌상 파랑·우상 빨강·좌하 투명·우하 초록**, 반전 후 JPEG 투명 부분 **흰 배경**을 확인했다. 파일 선택·쓰기 경계는 SDK mock이고 Worker/Canvas 인코딩과 출력 디코딩은 실제 실행이다. 사진 추출도 ZIP 해제·학생 수집·매칭을 Worker에서 다시 실행한 마지막 버전으로 사진 3개의 저장 바이트가 각각 원본과 일치했다. 어두운 테마·150% 확대에서 가로 넘침이 없음을 확인했다.

## 파일 수와 메모리·취소 경계

| 도구               | 지원 범위와 상한                                                                                                                                                                                                                           |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 이미지 용량 줄이기 | 원본 데이터를 전부 쌓지 않고 한 장씩 읽기/인코딩/저장. 합성 500개 순차 처리 테스트. 파일당 64MiB/4,800만 화소, Worker 90초. fs 출력 batch 상한 2,000개·합계 2GiB 이내이며 초과 출력은 개별 실패로 남는다.                                  |
| 명렬표 사진 꺼내기 | 문서 16개, 문서당 32MiB ZIP/실제 해제 128MiB, 모듈에 보관하는 사진 합계 128MiB. 문서당 학생/사진 1,000개 상한. 사진 수백 장 추출은 가능하나 16개 문서와 별개 한도다. 모든 media 원본 바이트를 저장하며 사진 없는 학생도 유지한다.          |
| 이미지 자르기      | 편집 사진 100개·원본 바이트 합계 128MiB, 파일당 64MiB/2,400만 화소. 긴 변 1,400px 미리보기 캐시는 합계 32MiB이며 초과하면 선택 때 다시 생성. 수백 개 전체를 한 화면에 유지하는 도구가 아니므로 100개씩 저장/목록 비우기로 나누어 처리한다. |

모든 도구는 SDK 읽기/쓰기의 AbortSignal과 Worker 종료를 이용한다. 취소 전에 게시한 결과는 남고, 원본 입력과 완료한 편집/추출을 보존한다. 압축이 작아지지 않을 때 복사하는 원본에는 EXIF 등 촬영 정보가 그대로 남으며, 재인코딩한 압축/크롭 출력에서는 원본 메타데이터가 제거된다. 입력 확장자와 실제 magic이 다르면 원본 복사 확장자를 magic으로 바로잡는다. 추출의 unknown/활성 파일 형식은 `.bin`으로 저장하고 미리보기하지 않는다.

최종 독립 검토에서 사진 추출 합계 한도 초과 문서가 뒤의 작은 문서까지 막는 누적 계산을 고쳤고, 취소 전송을 일반 실패로 표시하지 않도록 고쳤다. 이미지 크롭의 미리보기 캐시 상한을 추가했다. 이 세 경계는 회귀 테스트로 검증한다. PDF 사진명렬표 자동 인식·테두리 제거는 여전히 미구현 범위이며 이 기본 크롭 도구로 원본 이식 완료를 주장하지 않는다.

최종 이미지 모듈 회귀 검증은 9개 테스트 파일·41개 테스트(압축 8·추출 23·크롭 10)가 통과했다. 세 모듈 ESLint 통과, TypeScript 검사에서 세 모듈 오류가 없었다.
