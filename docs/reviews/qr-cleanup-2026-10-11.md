# QR 코드와 빌드 산출물 정리 검수

기준일: 2026-10-11. 사용자 요청은 과거 설치 파일·정크 정리, 현재 화면의 디자인 개선 **계획**, QR 생성 모듈 추가다. GPT-6.1 Sol 병렬 작업으로 구현·설계·독립 검토를 나누고 주 작업자가 통합했다. 이번 작업에서 기존 도구 전체의 디자인을 바꾸지는 않았다.

## 구현과 교차 검토

- `qr-maker` 0.1.0: 링크·글 입력 뒤 자동 생성, PNG 기본 저장·SVG 선택, 세션 동안 저장 폴더 재사용, 비우기 후 입력 포커스 복귀. 내용은 로컬 Worker에서 처리하며 입력 기록과 네트워크 전송이 없다.
- 공통 `@deck/ui`와 기존 `fs` 1.2를 사용한다. 새 캡·ACL·브리지 변경은 없다. MIT QR 인코더의 원래 고지와 번들 의존성 고지를 모듈 패키지에 포함한다.
- 빠른 입력 변경과 폴더 선택 중 내용 변경은 이전 생성·저장을 취소한다. 같은 URL에서 링크/글 모드를 바꾸거나 끝 공백을 추가한 뒤 미리보기가 사라지던 문제를 고치고 회귀 시험을 추가했다.
- `new URL()`이 잘못된 슬래시를 보정하는 문제를 독립 검토에서 발견했다. 실제 HTTP(S) 접두사와 역슬래시 거부 검사를 추가해 검증한 주소와 QR에 담는 문자열이 어긋나지 않게 했다.
- 빌드 정리는 새 설치본의 버전·생성 시각·크기를 확인한 뒤 허용된 이전 설치 파일·모듈 패키지만 삭제한다. 실패한 빌드, 경로 탈출, Windows junction, 다른 아키텍처의 최신 유효 설치본을 보호한다. 빈 설치본의 보존 판단과 공백으로 나눈 `--bundles` 인자 처리는 교차 검토 후 보완했다.

## 실제 정리

과거 NSIS 설치 파일 18개를 먼저 삭제한 뒤, 현재 빌드 폴더와 구별한 `target/review-031`, `target/release` 두 폴더를 삭제했다. 두 폴더의 절대 경계·재분석 지점·추적 파일·실행 중인 프로세스를 확인했다. 합계 **8,795,890,468바이트(8.19GiB)**를 정리했다. 당시 최신 0.5.1 설치본은 새 빌드가 성공할 때까지 보존했다.

삭제 명세는 로컬 `target/build-cleanup/removed-installers-20261011.json`, `removed-build-folders-20261011.json`에 있다. 소스·사용자 자료·검증 증거는 삭제하지 않았다. 빌드 캐시는 자동 정리 대상에서 제외한다. 앞으로의 자동 정리 범위는 [개발 빌드 정리 안내](../development-build-cleanup.md)에 명시했다.

첫 설치본 빌드에서는 과거에 복사된 캐시의 `PERMISSION_FILES_PATH`·네이티브 링크 경로가 삭제된 두 폴더를 참조해 실패했다. 실패 뒤에도 0.5.1 설치본의 해시가 그대로임을 확인했다. 실제 Cargo 폴더 경계를 다시 검증하고 복사 과정에서 빠진 캐시 표지를 복구한 뒤, 이전 경로를 참조하는 의존성 패키지만 `cargo clean --release -p ...`로 재생성했다. 앱 소스·Tauri 권한을 바꾸거나 생성된 권한 파일을 손으로 수정하지 않았다. 실패 로그는 `build-060.log`, 캐시 정리 기록은 `stale-cache-packages.json`·`stale-cache-clean.log`에 보존했다.

## 검증

`pnpm verify` **16단계 전체 통과**. JavaScript 152파일·1,362개와 Rust 276개(core 104·host 169·제한 DLL 3) 테스트가 통과했다. 새 QR 시험 15개와 빌드 정리 시험 15개가 포함된다. 생성물·린트·타입·라이선스·보안·문서·버전 검사도 통과했다. 로그는 `target/build-cleanup/verify-060.log`다.

Playwright CLI로 제품 App·Worker·브라우저 Canvas를 실행해 별도 **21개 흐름 검사**를 통과했다. PNG와 SVG Blob을 독립 QR 해독기로 읽어 URL, 한글, 줄바꿈, 이모지, 연속·끝 공백 보존을 확인했다. 1,950바이트 한글 입력은 정상 해독되고 2,001바이트 입력은 거절됐다. 단위 시험에서는 최대 2,000바이트도 해독했다.

제목을 포함한 최종 라이트·다크 화면과 800×600 CSS 배율 200% 화면을 확인했다. 작은 화면에서 가로로 잘린 컨트롤은 없었다. 원본 스크린샷 네 개의 QR 영역을 직접 해독한 결과도 입력과 일치했다. 도구 이미지 표시에서 제기한 ‘빈 QR’ 의심은 원본 PNG 픽셀·해독 결과와 일치하지 않아 철회했다. 로컬 증거는 `output/playwright/qr-qa-report.md`, `qr-screenshot-pixels.json`, `qr-screenshot-decode.json`과 스크린샷들이다.

브라우저 검수의 OS 폴더 선택과 파일 전송은 mock이다. Windows 네이티브 폴더 선택창, 새 설치본의 설치·제거, 실제 Windows DPI를 이번 브라우저 결과로 통과 처리하지 않는다. 기존 네이티브 저장 경계는 전체 Rust 시험 범위에서 검증했다.

## 디자인 제안

[현재 화면 개선 계획](../proposals/design-improvements-2026-10-11.md)은 파일 도구의 실행 위치, 지도일배정기의 명단·달력 구분, 퀵캡처의 반복 작업 중심 화면을 우선 제안한다. 홈·중복 제목·메모·회의록 관리 행은 후속 순서다. 이미 구현된 공휴일 색과 기존 단축키·고정 캡처·입력 흐름을 유지하는 것이 전제다. 코드에 근거한 계획이며 전체 도구의 렌더 감사가 완료됐다는 뜻은 아니다.

## Windows 설치본과 자동 정리 실증

- `pnpm tauri build` 성공. 설치본: `target/review-040/release/bundle/nsis/TeacherDeck_0.6.0_x64-setup.exe`, **39,327,054바이트(37.51MiB)**.
- 설치본 SHA-256: `848ea33ff0c2b085ab81931a2c3940bd47f7335568de0d240211288e62f90fc6`.
- 기본 모듈 **20개**의 카탈로그 크기·해시와 패키지 실물을 대조했다. 영상 다운로드는 보류 상태를 유지한다.
- QR 0.1.0 패키지는 189,159바이트이며 SHA-256은 `cca32ff45f183b9ad1c52baaafe91d754173169f00a168a4fa0b571c1081e77a`다. 패키지 내부의 Worker·매니페스트·원래 인코더 고지·번들 의존성 고지를 확인했다. 원래 고지는 소스와 내용이 일치한다.
- NSIS의 0.6.0 버전과 QR 포함, 입력 자산 **623개**의 존재를 확인했다. 설치·제거 UI 검수를 의미하지 않는다.
- 새 빌드 성공 직후 래퍼가 이전 설치본 1개·이전 모듈 패키지 49개, **66,802,891바이트**를 자동 삭제했다. 새 설치본과 최신 모듈 패키지는 보존됐다. 처음 정리와 합쳐 **8,862,693,359바이트(약 8.25GiB)**의 과거 산출물을 정리했다. 재생성한 의존성 캐시의 임시 삭제량은 이 합계에서 제외했다.

성공 로그: `target/build-cleanup/build-060-rebuilt.log`. 대조 스크립트와 결과: `check-060.ps1`, `bundle-060.json`. 최초 정리·실패·복구·성공의 기록을 모두 보존했다.
