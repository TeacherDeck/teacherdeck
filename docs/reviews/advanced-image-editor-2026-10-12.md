# 고급 이미지 편집 구현 검수

기준일: 2026-10-12. 사용자와 합의한 별도 고급 편집기를 `advanced-image-editor` 0.1.0으로 구현했다. 기본 이미지 자르기의 제품 코드·ID·버전은 유지했다. 이 기록은 이번 변경의 검증 근거이며 설치본 배포나 Photoshop 전체 호환 확인을 뜻하지 않는다.

## 구현

크롭·크기·회전·반전·네 모서리 원근 보정, 명도·대비·RGB 및 개별 채널 레벨·곡선, 픽셀·글자·도형 레이어, 원형 브러시·지우개·스포이트, 사각형·다각형·색상 선택과 독립 마스크를 연결했다. 여러 줄 글자는 기존 PSD에서 가져온 경우에도 내용을 수정할 수 있다. `.deckimage`는 기준 픽셀·마스크·속성·보정값을 보존하고, PSD는 교환용, PNG/JPG는 최종 이미지용이다.

한 문서 모델과 타일 이력을 사용한다. 단계가 끝나기 전 입력된 글자·색보정도 작업 보호와 저장에 포함한다. 보호 요청이 실패하면 거절된 초안이 화면·저장에 남지 않는다. SDK의 불투명 핸들과 새 결과 파일 저장을 계승했으며 원본 덮어쓰기·외부 전송·웹 저장소는 추가하지 않았다.

미저장 상태 등록·저장 요청은 window 1.2/SDK 0.8, 이를 동봉한 앱은 0.7.0이다. 셸 전환·LRU·앱 종료는 저장/버리기/취소를 거친다. 자세한 계약은 [ADR-0030](../adr/0030-unsaved-document-lifecycle.md)과 [문서 생명주기](../spec/document-lifecycle.md)에 있다.

## 아이콘 화면과 코드 검증

사용자의 후속 요청으로 고급 이미지 편집기만 아이콘 중심으로 재배치했다. 왼쪽 세로 도구 막대와 전경색, 상단 파일 작업/현재 도구 옵션, 중앙 문서 창/캔버스/보기 상태, 오른쪽 속성·색보정·도구 설정과 아래 레이어 목록을 사용한다. [Adobe 공식 작업 화면 안내](https://helpx.adobe.com/ca/photoshop/desktop/get-started/learn-the-basics/workspace-overview.html)의 영역 역할을 참고했다. 아이콘·색·간격은 기존 Fluent/TeacherDeck 시스템을 사용한다.

V/C/M/L/W/B/E/I/H/T, Ctrl+N/O/S/Z/Shift+Z/0/1을 연결했다. 글자 입력·한글 조합·키 누름 반복·확인창·처리 중에는 해당 도구/문서 단축키를 막는다. 입력란의 Ctrl+S는 미적용 입력까지 저장한다. T는 접힌 글자 패널을 다시 열며 기존 글자 레이어를 복제하지 않는다. 긴 파일·레이어 이름을 줄바꿈하고, 화면 맞춤은 스크롤 영역의 실제 안쪽 크기로 계산한다. 비활성 다시 실행은 초안을 확정하지 않고, 브러시 획 중에는 다른 편집 동작을 잠그되 포인터 종료/취소는 계속 받는다.

아이콘 이름·툴팁·키보드 포커스·선택/비활성 상태, 패널 전환 후 미적용 초안 저장, 입력/조합 단축키 차단, 비활성 다시 실행과 브러시 완료를 DOM/SDK 시험으로 확인한다. 사용자 요청에 따라 **이 배치 변경 뒤 컴퓨터 유즈/브라우저 조작은 하지 않았다**. 아래 실제 화면 결과는 배치 변경 전 기능 검수이며, 새 배치의 시각 검수·Windows DPI 실기를 완료했다고 주장하지 않는다.

## 배치 변경 전 실제 브라우저

실제 App·SDK 청크 쓰기·미리보기/코덱 Worker를 생산 코드 그대로 실행하고 파일 선택·호스트 결과 저장 경계만 개발용 모의 호스트로 제공했다. OS 파일 선택 성공과 구분한다. 검증용 사진·글자·PSD는 합성 자료다.

- 적용 전 한글 여러 줄 글자를 저장하고 Worker로 다시 읽어 내용과 dirty 해제를 확인했다.
- R/G/B 입력 검정 12/9/7, 곡선 첫 출력 8/6/4, 명도 0.01을 적용 버튼 없이 저장해 다시 읽었다.
- 160×120 선택 영역의 마스크 19,200픽셀을 숨긴 뒤 기준 픽셀 해시가 유지됨을 확인했다. 실행 취소로 마스크가 제거됐고, 경계 보정 후 부분 알파 2,240픽셀이 생겼다.
- 브러시 해시 `371383d6`, 실행 취소 기준 해시 `780b44b0`, 지우개 해시 `1039e8d2`를 비교하고 다시 실행 일치도 확인했다.
- 네 모서리 보정 결과 320×240, 문서 크롭 240×180을 작업 파일 재읽기로 확인했다.
- PSD 저장·재열기 후 한글 여러 줄 글자 내용을 수정해 작업 파일로 저장했다.
- 색상 선택·다각형 누끼·회전 10도·좌우 반전·화살표/사각형 병합과 실행 취소를 확인했다.
- PNG 출력의 투명 픽셀 10,104개와 JPG의 투명 픽셀 0개·흰 배경 모서리를 실제 디코딩 픽셀로 비교했다.
- 손 도구의 키보드 이동 (100,100), 포인터 이동 (140,130), Shift+방향키 레이어 10px 이동을 확인했다.
- 밝은/어두운 테마, 800×600 창, CSS 화면 확대 150%·200%에서 버튼·입력의 가로 넘침이 없었다. 스크린샷을 직접 확인했다. 이 확대는 Windows DPI/IME 실기 검증을 대신하지 않는다.

도구와 증거: Playwright CLI, `target/advanced-editor-browser/qa-*.js`, `output/playwright/advanced-editor-*.png`. 앱 JavaScript 예외는 0개였다. 초기 검수 페이지 favicon 404와 Fluent 슬라이더의 `slider-vertical` 경고는 제품 실행 예외와 구분한다.

## 독립 PSD 소비 도구

`psd-tools 1.11.1` 개발용 파서로 출력 PSD를 읽었다. 픽셀 레이어 RGBA(40,80,120,128), 독립 마스크 [255,128,0,64], 글자 레이어 type 인식과 수정한 한글 여러 줄 문자열이 일치했다. 이 도구는 제품 의존성에 넣지 않았다. 실제 Photoshop의 글꼴·배치·재편집 실기는 확인하지 않았다.

PSD의 투명 픽셀/마스크 보간 경계 잔상을 고쳤다. 변형된 마스크를 나중에 제거했을 때 일부 경계의 숨은 색상이 원본과 완전히 같다는 보증은 하지 않는다. `.deckimage`는 원래 기준 픽셀과 마스크를 보존한다.

## 자원·고지·패키지

관리 메모리 256MiB, 이력 64MiB, 입력 64MiB, 문서 24MP/한 변 10,000px·레이어 16개 상한을 함께 검사한다. 입력 복제·압축 해제·변형된 PSD 픽셀/마스크와 출력 임시 버퍼도 사전 예산에 포함한다. 크기 상한만으로 모든 조합이 가능한 것은 아니다. 변경하지 않은 Worker 픽셀은 원래 버퍼를 재사용하고 새 버퍼는 소유권을 전달한다.

현재 Windows Node의 3,000×2,000 단일 사진에서 2,048px 획은 총 233ms, 가장 긴 처리 구간 29ms, commit 13ms였다. 학교 PC/WebView2의 p95 50/150ms 목표 달성 측정으로 세지 않는다. 타일 예산과 취소 복원은 자동 시험으로 확인했다.

Klecks는 flood-fill·글자 표시·변경 타일 세 부분만 선별 이식했다. ag-psd 31.0.3/fflate 0.8.3과 전이 MIT/Zlib 원문 고지를 포함했다. polygon-clipping·transformation-matrix·glfx·다른 scene graph는 추가하지 않았다. 원문/이식 SHA는 [vendor](../../modules/advanced-image-editor/vendor/README.md)에 있다.

공식 deck-pack 산출물은 `target/deckmod/advanced-image-editor-0.1.0.deckmod`, 352,444바이트, SHA-256 `e24cce8bdc18a2d8a7749e52db346999600217319146e3ed790925880b183ca2`다. 두 고지는 public·dist·staging·패키지에서 바이트가 일치했다. 전체 고지 7,061바이트 SHA-256 `331bafb0b18157a52653e27cc8d8c02a4c227d86c68d6f67a4e02c5d273c17cd`, Klecks 원문 1,076바이트 SHA-256 `0234a0861b38c1f3c9198b0f048a1b713bf3b1b198b5cced343acc7335b90785`다.

## 전체 검증과 네이티브 실기

별도 PDF 후속 수정이 함께 있던 통합 개발 작업본에서 `pnpm tauri build --debug --no-bundle`도 통과했다. 기본 모듈 21개를 공식 번들러로 묶고 셸과 네이티브 앱을 빌드했다. 기본 카탈로그·배포 패키지·디버그 앱에 복사된 고급 편집기 패키지의 크기와 SHA-256은 위 최종 패키지와 일치한다. `target/debug/teacherdeck.exe`는 44,192,256바이트, SHA-256 `7107040ceabdf3193f465720d2af91a00a4125262a2b01aad78a342fc2c2f1d5`다. 이 빌드는 실행하지 않았다. 로그는 `target/advanced-editor-plan/ui-native-build-final.log`, 대조 결과는 `target/advanced-editor-plan/bundled-editor-audit.json`이다. 디버그 빌드이므로 기존 설치본 산출물은 보존했다. 이 실행 파일은 게시 브랜치 전체의 빌드 증거와 구분한다. 게시한 편집기 소스 54개와 원 작업본은 바이트가 같으며 PDF 후속 수정은 PR에서 제외했다.

최종 아이콘 UI를 고정한 뒤 통합 개발 작업본의 **`pnpm verify` 16단계가 모두 통과했다**. JavaScript 170개 파일/1,526개, Rust 287개(코어 113·호스트 171·한글 보안 3), 총 **1,813개 시험**이다. 이 수치에는 별도 PDF 후속 시험이 포함된다. 고급 편집기와 새 공통 편집 컨트롤은 10개 파일/72개 시험이며, 그중 App 통합은 17개다. 기존 검사 기준과 5초 시험 시간 제한을 유지했다. 로그는 `target/advanced-editor-plan/verify-ui-final.log`다.

GitHub 게시용 `codex/advanced-image-editor`는 PR #17을 병합한 main `dff4cbd`에서 별도 작업본으로 만들었다. 고급 편집기와 문서 보호·공통 컨트롤 변경만 복사하고, 기존 Fluent DOM 시험의 준비·조회 동기화와 단일 worker 설정은 별도 시험 지원 커밋으로 분리했다. 기존 이미지 자르기·PDF·CoolReserve 제품 코드와 도구 스크립트는 main과 같으며, 고급 편집기 소스 54개는 통합 작업본과 바이트가 같다.

이 정확한 게시 작업본에서도 **`pnpm verify` 16단계가 모두 통과했다**. JavaScript **166개 파일/1,479개**, Rust **287개**, 총 **1,766개 시험**이다. 로그는 `target/advanced-editor-plan/publish-verify.log`다. 초기 호출의 Cargo 경로·로컬 패키지 저장소 접근 문제는 설치에 사용한 실행 환경으로 맞춘 뒤 동일한 명령을 다시 실행해 해결했다. 코드·검사 대상·단언·시간 제한은 변경하지 않았다.

아이콘 배치 변경 전 실제 디버그 앱에서 제목 표시줄 닫기·도구 이탈의 취소와 같은 연결의 업데이트 재시작 취소를 확인했다. 같은 문서 핸들·`dirty:true`·`saving:false`·합성 글자 초안이 남았다. 앱 0.7.0의 실제 기본 모듈 21개도 확인했다. Alt+F4·트레이 종료·네이티브 파일 선택·실제 결과 폴더 저장은 Windows 자동 조작 도구 오류로 확인하지 못했다. 사용자 요청 뒤 컴퓨터 유즈를 재개하지 않았다.

이 네이티브 진단의 패키지는 SHA-256 `cfe60de151a967389fc26ed1f23f8d77ce6109faffb17d938fe5d2a058e57ea5`로 마지막 입력 보호와 아이콘 UI 변경 전이다. 최종 패키지의 새 UI 실기 검증으로 세지 않는다. 실행한 합성 QA 앱은 정확한 PID·실행 경로·시작 시각으로 구분해 정리했다. 진단 근거는 `target/advanced-editor-native-qa/NATIVE-QA.md`에 있다. 설치본 제작·게시를 완료했다는 뜻은 아니다.

첫 전체 검사에서 셸 확인창의 접근성 버튼 조회가 Tabster 준비보다 빨랐다. 공통 ContentDialog 시험의 기존 동기화 방식으로 준비·포커스·취소 후 history 복원을 기다리도록 보완했다. 동시 네이티브 빌드 중 기존 지도일 DOM 시험의 시간 초과도 있었으므로 같은 검증 기준으로 재실행했다. 두 화면의 34개 시험이 통과했고 최종 전체 검사에서도 통과했다. 테스트 시간 제한·검사 대상을 완화하지 않았다.

두 번째 전체 검사는 테스트를 제외한 15단계와 Rust 287개가 통과했다. JavaScript 1,519개 중 학교 자료 테스트 하나가 열린 드롭다운의 버튼/포털 목록을 같은 이름으로 찾아 실패했다. 라벨의 실제 연결 컨트롤을 선택하고 역할/이름/동일 객체를 확인하도록 조회만 고쳤다. 해당 15개 시험은 같은 기준으로 다시 통과했다. 제품 코드·검사 대상을 바꾸거나 첫 번째 결과만 임의 선택하지 않았다.

Windows Cargo의 오래된 deck-core/deck-codegen 아티팩트가 새 소스에도 이전 window 1.1을 생성한 문제는 해당 패키지 캐시만 정리한 후 공식 `pnpm gen`으로 해결했다. 실제 window 1.2와 새 타입을 확인했고 check-gen·신규 Rust 회귀와 clippy를 다시 실행했다. 생성물을 손으로 맞추지 않았다.
