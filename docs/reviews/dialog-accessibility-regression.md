# 확인 대화상자 접근성 회귀 검증

2026-10-11, 합성 자료로 검증했다.

## 원인과 수정

조건부로 표시한 마지막 Fluent Dialog를 제거하면 `useTabster`의 마지막 참조가 사라졌다. 설치된 Tabster 8.8.1의 `Modalizer.dispose()`는 배경 접근성 복원 타이머를 취소하고 숨김 추적을 비웠다. 이미 배경에 붙인 `aria-hidden=true`는 남아 화면 전체가 스크린리더에서 사라졌다.

`DeckProvider` 안에서 Fluent의 공개 `useFocusFinders` 훅을 사용해 포커스 관리 인스턴스의 수명을 화면과 맞췄다. Dialog 제거 후에도 Fluent가 배경 접근성을 정상 복원한다. 직접 `aria-hidden`을 지우거나 라이브러리 내부 API를 호출하지 않는다.

학교 자료 XLSX 미리보기는 같은 controlled ContentDialog 인스턴스의 `open`을 전환한다. 취소 직후 다시 열어도 모달 식별자가 유지된다. 창 인스턴스를 매번 새로 만드는 과정에서 나타났던 새 모달의 비활성 숨김 경합을 피한다.

## 회귀 증거

- `ContentDialog.test.tsx`: 배경이 실제로 숨겨진 상태에서 조건부 대화상자를 취소·적용·다른 선택·Escape로 닫고 다시 연다. 매번 배경의 접근성 복원과 콜백 결과를 확인한다. jsdom에는 레이아웃과 포인터 포커스가 없으므로 Fluent의 DOM 등록 후 동작 버튼을 포커스한다. 숨김 요소를 허용하는 조회나 제한 시간 완화는 사용하지 않는다. 수정 전 첫 닫기에서 배경 숨김이 남는 실패를 확인했다.
- `SchoolData.test.tsx`: 기존 native 선택 취소→미리보기 취소→재열기→명시적 적용 검사를 유지한다. controlled 인스턴스 도입 후에도 전체 병렬 검증에서 jsdom 포커스 경합이 재현되었다. 실제 사용자처럼 접근 가능한 트리거를 포커스하고, Fluent DOM 등록 후 미리보기 입력을 포커스하며, 접근 가능한 동작 버튼을 기다리도록 보강했다. 기존 저장 횟수·내용·취소 단언과 제한 시간은 유지했다.
- 관련 공통 UI·학교 자료 6개 테스트 파일, 43개 테스트 통과. 수정한 TS/TSX 6개 파일의 ESLint 경고 0, `git diff --check` 통과.
- 실제 브라우저 역할 도구: 합성 6명·3역할 배정 후 일괄 기록에서 1명을 제외하고 2명의 완료를 기록했다. 닫은 뒤 배경 `#root`의 `aria-hidden`이 정상 복원되고, 접근성 트리와 완료 2명·미완료 1명 결과가 유지되는 것을 루트 에이전트가 확인했다.

- 실제 브라우저 학교 자료: XLSX 미리보기를 취소하고 다시 열어 적용한 뒤 합성 명부 3명과 배경 `aria-hidden` 복원을 루트 에이전트가 확인했다. 내부 CSS 확대를 제거한 제품과 같은 DOM 구조에서 저장된 시간표의 마우스 선택과 두 칸 복원도 확인했다.

제품은 WebView 전체에 `set_zoom(1.2)`를 적용한다. 초기 하니스는 내부 div만 CSS 확대해 포털 목록과 다른 좌표 기준을 만들었으므로 그 선택 실패를 제품 결함으로 판정하지 않는다. 실제 네이티브 120% 확대·Windows DPI 검증과 최종 통합 검증은 별도 범위다.

## XLSX 가져오기 되돌리기

적용 직전 학교 자료의 전체 스냅숏과 적용 성공 revision을 화면 메모리에 보관한다. 되돌리기 확인 후 기존 trusted `save`에 그 revision을 전달한다. 다른 화면에서 먼저 변경하면 호스트의 revision 검사가 저장을 거부한다. 실패하면 스냅숏을 유지하되 새 revision으로 바꾸어 재시도하지 않는다. 이후 학교 자료 저장 성공·사진 revision 변경·복구·다시 불러오기는 되돌리기를 종료한다. 기존 시간표에 XLSX 내용을 덮지 않고 새 식별자로 표를 추가하므로 되돌리기는 이전 표를 보존한다. 되돌린 표를 선택하고 있었다면 그 삭제된 표 선택과 관련 초안만 해제한다.

학교 자료 3개 파일 25개 테스트를 후속 검증했다. 명부·시간표 확인 취소/되돌리기, 정확한 적용 전 자료 복원, 실패 후 동일 revision 재시도, 후속 저장의 성공/실패 수명, 외부 revision 충돌 보존과 재읽기 후 폐기를 검사한다. 미리보기 payload와 열림 상태를 분리하여 닫힘 애니메이션 동안 학생 제목·학생 수가 시간표·0개로 바뀌지 않는 것도 검사했다.
