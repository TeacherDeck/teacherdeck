# 기본 모듈 UI/UX 감사

2026-10-24. 기준 커밋 `b4c060ef2ab53f30596e131478d79978b2f1a882`의 기본 모듈 21개를 대상으로 화면 계층, 간격·정렬, 반응형 배치, 보조 설정 노출을 점검했다. 규범은 [디자인 시스템](../spec/design-system.md), [모듈 규칙](../spec/modules.md), [공통 작업 화면 결정](../adr/0029-compact-tool-workspaces.md)이다.

이번 감사는 React 구조와 테스트를 기준으로 한 코드 감사다. 실제 Windows DPI·Mica, 화면낭독기, 네이티브 파일 선택·OCR 성능을 확인한 결과로 확대 해석하지 않는다. 조건부 분기에 있는 컨트롤 수는 동시에 보이는 개수와 다를 수 있으므로, 수치 자체보다 주 작업과 보조 작업의 계층을 판단하는 보조 근거로만 사용했다.

## 결론

- `PageHeader`, `ToolLayout`, `SettingsExpander`, 공통 간격 토큰을 대부분 사용하고 있어, 전체 모듈의 여백을 일괄 축소하거나 새 공통 컴포넌트를 만들 근거는 없었다.
- 파일 일괄 처리 도구는 입력 → 옵션 → 미리보기 → 실행 → 결과 순서를 지켰다. 기록·배정·계속 실행 도구는 작업 특성에 맞는 전용 배치를 유지했다.
- 가장 명확한 고우선순위 문제는 `pdf-mask`였다. 조건부 JSX를 포함해 33개 조작 컴포넌트를 사용하면서 `SettingsExpander`가 없어, 명단 관리·OCR 재실행·좌표 조정이 주 작업과 같은 무게로 계속 노출됐다.
- `coolreserve`, `meeting-note`, `duty-planner`, `seat-planner`는 코드량과 분기가 크지만, 이미 단계·접이식 설정·전용 작업 공간으로 나뉘어 있다. 실제 사용성 증거 없이 추가로 접으면 주요 작업을 숨길 위험이 있어 이번 수정에서 제외했다.

| 파일      | `pdf-mask`                                                                                       | 수정 | 자동 탐지·페이지 확인은 유지하고 명단·검색어, OCR 재실행, 직접 좌표를 접이식 보조 작업으로 분리했다.               |

## 적용한 수정

`pdf-mask`에서 다음 원칙으로 화면 계층을 조정했다.

1. 전화번호·주민번호 등 자동 탐지 선택과 자동 후보 다시 찾기는 주 작업으로 계속 보인다.
2. 명단·검색어 편집은 접되, 포함 여부와 검색어·후보 수는 헤더에 남긴다.
3. 페이지 이동, OCR 불확실 경고, 제거 미리보기, 후보 목록은 확인에 필수이므로 계속 보인다.
4. 이미지 글자 다시 읽기와 직접 좌표 입력은 필요할 때 펼친다.
5. 기능·저장 형식·캡·의존성은 바꾸지 않고, 키보드로 펼칠 수 있는 기존 `SettingsExpander`를 재사용한다.

## 검증 기준

- 접힌 상태에서 검색어 입력, OCR 재실행 버튼, 좌표 입력이 렌더되지 않는다.
- 각 헤더를 키보드 또는 클릭으로 펼치면 기존 컨트롤과 동작에 접근할 수 있다.
- 자동 OCR 경고와 후보 선택은 접힌 설정 밖에서 계속 보인다.
- 기존 탐지·취소·원본 보호 테스트와 `pnpm verify`를 통과해야 한다.
- Windows 800×600, 텍스트 150%, DPI 200%, 라이트·다크·Mica는 별도 실기 검수 항목으로 남긴다.

## 후속 검수

코드만으로 확정할 수 없는 항목은 실제 앱에서 확인한다. 특히 `coolreserve`의 긴 다건 편집, `seat-planner`의 많은 학생 조건, `meeting-note`의 100개 기록, `pdf-mask`의 OCR 경고 후 보조 작업 발견성을 합성 자료로 비교한다. 문제가 재현되면 해당 작업 흐름과 테스트를 함께 고치며, 전역 토큰이나 공통 컴포넌트 값을 먼저 바꾸지 않는다.
