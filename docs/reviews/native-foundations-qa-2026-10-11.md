# 파일·학급·Windows 연동 통합 검수

기준일: 2026-10-11. 이 문서는 0.3.0 통합 검수 기록이다. 이전 0.2.2/후속 도구 단계의 검증 수치를 이번 변경의 통과 수치로 사용하지 않는다.

## 공동작업자 변경 반영

`origin/main`의 `b43ce4e5ff5cad4f67960e7fe37b87efe32b5603`까지 읽고 `3c9bc5a`에서 병합했다. PR #6은 병합되었고, PR #7의 타이머 0.3.0·개발 포트 8265·메인 화면 120% 배율·이동 기록·다크 스크롤바·보호 경로 훅 제거를 반영했다. 공동작업자는 개발 origin 변경과 훅 제거의 리뷰를 요청했다. 정지 조건과 CODEOWNERS 요구는 남아 있다.

타이머는 편집한 뒤 시작을 한 번 누르면 편집기 blur로 버튼이 움직여 시작이 누락되는 문제를 실제 브라우저에서 재현했다. 편집값 확정과 시작을 같은 동작에서 처리하도록 고치고 0.3.1로 올렸다. pointerdown → blur → pointerup → click 회귀를 포함한 타이머 화면 테스트 5개가 통과했다. 실제 브라우저에서 20초 입력 후 한 번의 시작으로 작동하고 최근 기록에 20초가 남는 것을 확인했다. 600×468, 120% 배율에서도 3시간 입력 후 한 번에 시작되며 일반 화면과 발표 화면의 숫자·버튼이 겹치지 않았다.

## 원본 호환성과 파일명 작업

TimeAlert에서 만든 XLSX의 package-root relationship 경로를 실제로 읽어, 호환되지 않던 명부·파일명 표·사진 추출 파서를 보완했다. ZIP 안의 절대 part 경로와 PC 경로를 구분하며 `//`, 루트 이탈, URI 등은 계속 거부한다.

- 공통 학급 자료: 화면·파서 테스트 14개, 호스트 테스트 8개. TimeAlert 실제 형식의 명부·시간표 두 파일을 어댑터로 읽었다. 사진 자동 등록이나 전체 암호화 백업 호환까지 검증한 것은 아니다.
- 파일명 작업: JavaScript 23개, Windows 원본 이름 변경/되돌리기 14개, 폴더 목록 2개, core 2개가 범위 검증에 통과했다. 원본 변경에는 파일 identity와 SHA-256, 읽기/삭제 잠금 및 실행 기록을 사용한다.
- 실제 브라우저: 두 파일 추가 후 큰 빈 드롭 영역이 사라지고, 새 폴더 복사와 결과 두 건을 확인했다. XLSX 양식의 앞자리 0을 보존해 정확 대응 1건·미대응 1건을 표시하며 미대응 실행을 막았다. 이 브라우저 검수의 OS 파일 선택/출력은 모의했고 실제 파일명 변경은 별도 Windows 테스트에서 검증했다.

## Windows 문서 변환

`office_synthetic` 개발 예제는 사용자 파일 대신 독립 임시 영역의 합성 문서를 만들고 실제 production 변환 작업자를 호출한다. 최종 경로에서 Excel XLS→XLSX, Word DOC→DOCX의 원본 SHA-256 유지, 새 ZIP의 합성 본문·표·Excel 수식과 주석을 확인했다. 로그는 `target/next-tools/office-synthetic-registered-final.log`에 있다. 전체 서식의 시각적 동일성 검사는 별도다.

Word는 SingleUse 생성과 새 프로세스·등록 실행파일·생성 시각을 확인한다. PowerPoint의 새 프로세스가 하나라는 검사만으로는 동시에 실행된 다른 자동화와 구분할 수 없다는 독립 리뷰를 반영했다. PowerPoint는 등록된 실행파일을 고정 인자로 직접 시작하고, 보유한 자식 프로세스 핸들·PID·실행파일·생성 시각과 유일한 새 프로세스를 모두 확인한다. 소유권을 입증하기 전에는 문서를 바꾸거나 COM Quit을 호출하지 않는다. [Microsoft의 Office COM 인스턴스 설명](https://learn.microsoft.com/en-us/previous-versions/office/troubleshoot/office-developer/use-visual-c-automate-run-program-instance)을 근거로 서로 다른 생성 방식을 구분했다.

최종 PowerPoint 경로는 실제 PPT→PPTX 저장·재열기·본문/표·원본 해시 검사에 두 번 연속 통과했다. 기록은 `powerpoint-owned-final-diagnosis.log`, `powerpoint-owned-repeat-final.log`이며 두 번째 전체 시험은 11.56초였다. 별도 2초 제한 시험도 소유한 작업 프로세스의 종료와 원본 보존에 통과했다(`office-timeout-cleanup-final.log`, 2.203초). 앞선 `/EMBEDDING` 시험의 `0x800706BE`와 초기 `/AUTOMATION` 활성화 실패 기록은 남겨 두며, 두 번의 성공만으로 모든 설치 환경의 시작 안정성을 보장하지 않는다.

한글은 합성 문서 입력까지 진행했으나 SaveAs에서 120초 제한에 걸렸다. 파일 접근 승인 창을 자동 클릭하거나 보안 DLL을 설치하지 않았으며 실제 HWP→HWPX 통과로 표시하지 않는다. Office가 설치 정보에 등록됐다는 것과 실제 변환이 확인됐다는 것을 화면에서도 구분한다.

## 네트워크 루틴

원작 180개 판단 사례와 수동 우선·자정 경계·저장 실패 등을 Rust/TypeScript에서 비교했다. UAC 취소와 업데이트 후 자동 실행 재등록도 별도 회귀에서 확인한다. 실제 IP/DNS 변경이나 작업 스케줄러 등록은 수행하지 않았다.

실제 브라우저에서 현재 연결·수동 전환·즉시 검사 버튼을 화면 위로 옮겨 설정 전체를 스크롤하지 않아도 접근할 수 있게 했다. 600×468, 120% 콘텐츠 배율에서 가로 넘침 없이 버튼이 줄바꿈된다. 전환 성공/취소 표시의 브라우저 확인은 모의 호스트를 사용했다.

## CoolReserve

관리 실행 환경의 정확한 585개 파일·원래 고지 16개를 해시와 대조했다. 원작 private worker의 최종 offline 테스트 12개, 공개 파일 검사 18개가 통과했다. 앞선 원작 관련 173개 테스트도 별도로 통과했다. 실제 관리 Python 3.14.8의 isolated entry와 잘못된 요청 처리를 실행했고, 실행 전후 파일 해시가 모두 유지됐다. 이 과정에서 Gentoo를 조회하거나 메시지를 보내지 않았다.

원작 [CoolReserve PR #1](https://github.com/rochelobeJYJ/CoolReserve/pull/1)에 helper와 티처덱 모듈 소스를 함께 올렸다. 티처덱은 커밋 `3169909330fcf8197a3d1f591e08e0df02113f57`의 helper 14개·모듈 23개 파일과 해시를 고정한다. 내려받은 코드를 임의로 갱신하지 않고, 다음 원작 변경도 커밋·검증·고정 파일 갱신을 거쳐 가져온다. 원래 MIT 코어 고지와 티처덱 모듈의 GPL 고지를 함께 유지한다.

원작 자동 연결 프로필에는 검증된 첨부 목록 reader가 없어 첨부 등록을 지원한다고 표시하지 않는다. 연결이 실제로 제공하는 feature를 먼저 검사한다. 이미 검증한 본인 연결은 재사용하고, 증거가 달라지면 재확인을 요구한다. 최종 등록 확인은 모듈 밖의 신뢰된 셸에서 호스트가 고정한 실제 전달 내용을 검토하도록 연결했다.

실제 브라우저에서 제목 없는 여러 줄 초안 작성 → 초안 자동 선택 → 검토 → 덱 확인창 취소 → 초안 보존을 확인했다. 600×468에서도 확인창의 제목·닫기 버튼이 유지되고 본문·수신자·동의 항목은 스크롤할 수 있다. 동의 뒤에는 모의 호스트에서 등록 요청 완료와 자동 재등록 잠금까지 확인했다. 이 화면 검수는 실제 쿨메신저 등록이나 도착 확인이 아니다.

실행 환경 검증의 지연을 분리 측정했다. 같은 상위 폴더 핸들을 파일마다 중복 취득하던 부분을 패키지 안에서 공유하도록 바꿨다. 파일별 전후 검증·전체 해시·정확한 파일 목록 검사는 유지하고, 마지막 파일 세션이 닫힐 때까지 폴더 잠금도 유지한다. 캐시가 준비된 동일 조건에서 599개 파일 검증은 기존 9.31초 → 3.87초로 줄었다. 첫 측정 30.7초와 캐시된 결과를 혼합해 속도 개선률을 계산하지 않았다. 이 수치는 이 PC의 별도 측정이며 실제 쿨메신저 연결 전체 시간은 아니다.

## 최종 통합 검사

최종 `pnpm verify` 15단계가 모두 통과했다. JavaScript 105개 파일·1,088개 테스트, Rust core 72개·host 119개로 총 1,279개 테스트다. 생성물·린트·타입·포맷·Clippy·의존성·모듈·라이선스·보안·억제 구문 검사까지 포함한다. 로그는 `target/next-tools/verify-release.log`다. 테스트 건수·단언·5초 제한과 DOM 동시 실행 4개를 유지했다.

학급 확인창은 닫힌 대화상자를 계속 생성하지 않도록 수정했고, 자리 배치는 학생 ID 조회와 좌석 화면 재사용으로 조건 편집 비용을 줄였다. 대규모 좌석 테스트는 1,000개 네이티브 버튼과 접근 가능성 검사를 모두 유지하면서 불필요한 접근 이름 계산을 줄였다. 처음 실패한 검사 기록도 별도 로그에 보존했다.

네이티브 UI 제어가 비활성화되어 실제 Windows 캡처 창·혼합 DPI·한글 접근 승인 창 조작·메신저 등록·실제 네트워크 전환은 여기서 통과로 세지 않는다.

## 설치본과 앱 시작

`pnpm tauri build`가 성공했고 0.3.0 NSIS 설치본을 만들었다. 번들 모듈 17개의 버전·크기·SHA-256과 release 리소스로 복사된 동일 패키지를 모두 대조했다. CoolReserve의 복사된 실행 환경 585개 파일과 소스 14개도 정확한 파일 목록·크기·해시가 고정 파일과 일치했다. 기록은 `target/next-tools/build-release.log`, `bundle-verification.json`에 있다.

빌드한 실행 파일을 직접 시작해 0.3.0 시작 로그와 모듈 17개 모두 `Ready`, 메인 창 생성, 프로세스 응답을 확인했다(`target/next-tools/app-start-verification.json`). 실행 파일은 release 리소스와 함께 시험했으며, NSIS 설치·제거 및 모든 네이티브 화면의 조작 검증을 대신하지 않는다. Vite의 큰 청크 안내와 ts-rs의 `deny_unknown_fields` 해석 경고는 남아 있으며 빌드는 성공했다. gitleaks 실행 파일이 없어 별도 비밀값 스캐너 실행을 통과로 주장하지 않는다.
