# 이미지 출력 형식 보존 — 2026-10-13

앱 0.8.1, 이미지 자르기·이미지 용량 줄이기 0.3.1, 고급 이미지 편집 0.2.1의 변경 기록이다.

## 저장 동작

- 이미지 자르기·리사이즈·고급 편집의 이미지 내보내기는 원본 JPG/JPEG·PNG·WebP 형식을 기본으로 사용한다. 정상적인 원본 확장자는 대소문자와 `.jpg`/`.jpeg` 구분까지 유지한다.
- PNG·JPG·WebP를 직접 선택하면 선택한 형식으로 저장한다. 다른 형식으로 변환한 결과는 용량이 커졌다는 이유로 원본 바이트로 되돌리지 않는다.
- 확장자와 실제 이미지 내용이 다르면 실제 내용을 기준으로 올바른 확장자를 쓴다. 인코더가 요청한 형식을 지원하지 않아 PNG 등으로 대체하면 파일을 저장하지 않고 다른 형식 선택을 안내한다.
- 이미지 용량 줄이기의 이전 자동 WebP 설정은 원본 형식으로 이관한다. 기존 품질·긴 변 설정은 유지하고, 새 화면에서 명시적으로 선택한 형식은 별도로 기억한다.
- 고급 편집기의 자동 출력은 처음 연 문서를 기준으로 한다. 추가한 레이어 때문에 바뀌지 않는다. 새 문서·PSD·`.deckimage`의 이미지 내보내기는 기본 PNG이며, 레이어·편집 상태를 보관하는 작업 저장은 `.deckimage`다.
- 저장 위치는 원본 폴더 또는 사용자가 지정한 폴더다. 원본 보존, 충돌 이름 번호, 자동 하위 폴더를 만들지 않는 기존 동작을 유지한다.

## 검증 범위

회귀 시험은 혼합 입력의 파일별 형식, JPG/JPEG와 대문자 접미어, 직접 고른 형식, 이전 설정 이관, 인코딩 결과가 더 큰 경우, MIME 대체 거부, 고급 편집기의 새 문서·작업 저장을 확인한다. DOM 시험은 출력 선택과 저장 요청을 연결하고, Worker·코덱 시험은 Canvas 요청 형식과 오류 전파를 확인한다. 실제 Canvas 인코더와 파일 선택창은 모의하므로 Windows 화면 실기나 Photoshop 왕복 검증을 대신하지 않는다.

게시용 작업본에서 `pnpm verify` 16단계가 통과했다. JavaScript 185개 파일의 1,655개 테스트와 Rust 291개 테스트, 총 1,946개가 통과했다. 생성물·린트·타입·보안·라이선스·버전·문서 검사도 포함한다. 설치본을 만드는 주 작업공간과 코드·설정 1,269개를 대조했으며, 기존 일부 검사 fixture·PowerShell 파일의 줄바꿈 외에 내용 차이는 없었다.

0.8.1 Windows 설치 파일은 39,567,906바이트(37.73MiB)이며 SHA-256은 `56dd138776d47f76d4846a172a4356ed7e9434f3f077755b464bf9f6ff0387ac`다. 21개 기본 모듈의 버전·ZIP 내부 내용·체크섬과 네이티브 자산 601개, NSIS 입력 624개를 대조했다. 빌드 성공 후 기존 정리 절차가 이전 설치 파일·패키지 4개를 정리했다.

실행 중인 앱이 없는 것을 확인하고 사용자별 설치를 0.8.1로 갱신했다. 설치 프로그램 종료 코드는 0이며, 설치된 실행 파일은 NSIS 번들 표식 3바이트 외에 빌드와 동일하다. 설치 카탈로그·21개 모듈·601개 네이티브 자산도 일치한다. 빌드 폴더와 설치 폴더에 남아 있던 이전 이미지 모듈 세 개는 기존 패키지와 SHA가 일치하는 것을 확인해 작업공간에 보존 이동했다. 사용자 자료와 설정은 변경하지 않았다.

컴퓨터 유즈와 브라우저 자동화는 사용하지 않았다. 설치된 앱 화면 조작·실제 Canvas 인코딩·Photoshop 왕복 시험은 이번 검증 범위에 포함하지 않는다. 로컬 증거는 `target/product-audit-2026-10-13/`의 `verify-081.log`, `build-081-audit.json`, `installed-081-audit.json`이다.

## 별도로 남긴 개선

같은 형식의 압축 결과가 원본보다 크면 원본을 복사하는 기존 정책은 유지한다. 이 정책과 리사이즈·촬영 정보 제거 조건이 충돌하는 경우는 별도 개선 과제다. 고급 편집기의 다중 점 파일명 잘림과 큰 문서 저장 예산도 이번 형식 수정에 포함하지 않았다.
