## 빌드 잔여물

새 설치본 생성에 성공한 뒤 이전 설치본·모듈 패키지를 정리한다. release에 남은 구버전 모듈은 현재 카탈로그·패키지 해시를 대조한 경우에만 제거한다. 빈 버전 폴더만 추가로 지우며 사용자 원본·작업 자료·알 수 없는 파일은 대상이 아니다. 경로 이탈·심볼릭 링크·검사 뒤 파일 교체는 거부한다. 상세 범위는 [빌드 정리 안내](../development-build-cleanup.md)에 있다.

이번 빌드 성공 후 이전 설치·모듈 파일 25개(62,153,642바이트)를 자동 정리했다. 0.9.0 설치 후에는 새 실행 파일·모듈·네이티브 자산을 대조하고 이전 설치 모듈과 0.8.0 보관 패키지 21개(13,405,699바이트)를 삭제했다. 합계 **46개, 75,559,341바이트(약 75.6MB)**다. 빈 버전·보관 폴더와 이번 시험의 빈 임시 폴더 69개도 정리했다. 사용자 자료와 빌드 캐시·검증 근거는 보존했다.

## 검증 범위와 한계

최종 `pnpm verify` 16단계와 JavaScript 1,738개·Rust 292개, 총 **2,030개 테스트**가 통과했다. Windows x64 설치 파일은 39,438,763바이트(37.61MiB)이며, 21개 기본 모듈·601개 네이티브 자산·624개 NSIS 리소스 입력의 목록과 SHA-256을 대조했다. 설치 파일의 SHA-256은 `18fd14bd3a898bf01c23dd620cbc5e3c6385ea9036d6452aafbf9e6eb9e821fb`다.

앱이 실행 중이지 않은 상태에서 NSIS 설치를 종료 코드 0으로 완료하고 설치 버전 0.9.0을 확인했다. 설치된 실행 파일은 NSIS 표식 3바이트를 제외하면 빌드와 같으며, 카탈로그·전체 모듈·전체 네이티브 자산의 목록과 해시가 일치한다. 삭제 대상으로 확인한 구버전 패키지와 0.8.1 설치 파일은 더 이상 남아 있지 않다. 앱을 직접 실행하거나 화면을 조작한 검수는 아니다.

게시 작업본과 실제 빌드 작업본의 소스 1,457개도 대조했다. 로컬 근거는 `target/product-audit-2026-10-13/verify-090-pass.log`, `build-090-audit.json`, `installed-090-audit.json`, `cleanup-090-plan.json`, `cleanup-090-result.json`에 보관한다. 쿨 예약실 공개본 118파일·ZIP 검사는 원작 게시 커밋 `cef3b48`에 반영했으며, TeacherDeck의 실행 코드 핀은 `864de2b`다.

첫 전체 실행에서는 JavaScript 1,738개·Rust 292개 테스트가 통과했지만, CoolReserve 버전이 바뀐 생성 파일을 갱신하지 않아 `check-gen`이 실패했다. 공식 `pnpm gen`으로 재생성한 뒤 `check:gen`을 통과했다. 두 번째 전체 실행에서는 지도일 편집창의 jsdom 시험 세 건이 접근성 조회에서 실패했다. 같은 실패를 단독 재현하자 정확한 제목의 대화상자는 생성됐지만 모의 포인터가 포커스를 옮기지 않아 `aria-hidden` 상태로 남아 있었다. 제품 코드는 바꾸지 않고 시험이 대화상자·Tabster 등록·포커스를 기다리도록 수정했다. 접근성·포커스 반환 검증을 유지한 대상 3건과 지도일 화면 27건이 통과했으며, 다른 빌드·검사를 겹쳐 실행하지 않은 세 번째 전체 실행에서도 모두 통과했다. 검사 억제·skip·제한 시간 확대는 하지 않았다.

커밋 훅의 `verify:fast`와 DCO 검사는 통과했다. 별도 gitleaks 실행 파일은 설치되지 않아 기존 훅에서 실행되지 않았으며, `pnpm verify`의 보안 검사는 별도로 통과했다.

고급 편집기의 4,000×3,000 합성 사진으로 실제 작업 ZIP 저장·재열기와 래스터 합성을 검사했다. 이미지 출력의 최종 Canvas 인코더는 시험용 어댑터이므로 실제 WebView2의 대형 PNG/JPEG/WebP 인코딩이나 Photoshop 왕복 호환성을 검증한 것으로 세지 않는다. 메모·D-day는 StrictMode 재연결, 지도일은 저장 용량 부족 때 이전 초안 유지, 문서 도구는 합성 호스트 호출과 실패·취소 흐름을 검사한다.

컴퓨터 유즈·브라우저 자동화, 실제 쿨메신저 전송, OS 네트워크 변경은 수행하지 않는다. PDF/OCR의 실제 문서 탐지율과 Office 시각적 변환 충실도도 이번 수정으로 보증하지 않는다.

회의록의 미완성 입력 전체 자동 복원, 학교 자료의 주간 시간표 초안, 다른 일괄 처리 도구의 완료 목록 복원, 공개 자리표 통로 표시, 고급 편집기 비정상 종료 복구와 통합 백업은 후속 범위다. 네트워크 부분 실패 뒤 이전 설정 복원·DHCP 복구를 선택하는 흐름과 실제 OS 장애 주입 검증도 남아 있다. 자동 저장 전 입력의 강제 종료·전원 차단 복구를 보장하지 않으며, 지도일 초안은 기존 자료와 교체 세대를 포함한 저장 한도의 영향을 받는다. 제품 점검의 모든 개선 항목을 완료한 버전은 아니다.

## 한국어 문구 점검

`korean-ai-tone-audit`의 독자·메타서술 검사를 새 PDF 작업 보호 안내, 루트 README의 작업 유지 문단, PDF README 첫 두 문단에 전수 적용했다. 이 범위의 문장과 버튼은 사용자의 저장·확인·취소 행동과 제한을 직접 설명한다. 메타서술 유효 발견 없음(0건, 중복 0건). 기존 문서 전체의 문체 감사를 뜻하지 않는다.
