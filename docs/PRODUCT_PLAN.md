작성 기준: 2026-10-10 사용자 답변과 `origin/main`의 `8a71d02`. 이 문서는 확정된 제품 요구와 구현 권고안을 연결한 검토용 계획이다. 규범 원천은 [spec](spec/README.md)이며, 아래 후보 API나 배포 방식은 아직 승인·구현된 규격이 아니다.

후속 진행: 공동작업자의 `b38c1c7`을 반영하고 회의록·지도일 배정 초기 모듈을 구현했다. 구현·검증 범위는 [개발 현황](DEVELOPMENT_STATUS.md), 파일 기반의 1차 승인과 보완 검토는 [공통 기반 제안](proposals/module-foundations.md) 및 [전송 보완안](proposals/file-transfer-followup.md)을 기준으로 한다.

## 1. 확정된 제품 방향

목표 경험은 “TeacherDeck만 설치하니 교사 업무에 필요한 도구가 모여 있다”이다. 무료 공개 배포를 2026년 말까지 목표로 하며, 완성된 도구는 더 일찍 제공할 수 있다. 기여자의 실명과 기존 저자 표기는 유지한다.

우선순위는 일관된 디자인과 사용 경험, 정확한 처리, 적은 조작, 가벼운 실행이다. 도구는 작게 나누고 바로 열어 쓴다. 기존 프로그램의 핵심 조작과 업무 규칙을 재사용하며, 오래된 코드의 결합·중복·불필요한 처리를 개선한다.

간단한 변환·압축은 지원 형식과 출력 위치가 정해지면 드래그 후 기본값으로 실행하고 결과를 보여주는 흐름을 목표로 한다. ToolLayout의 입력·옵션·미리보기·실행·결과는 공통 화면 골격으로 사용하며, 모든 작업에서 단계마다 추가 클릭을 요구하지 않는다. 원본을 보존하는 안전한 기본값과 필요한 항목에만 보이는 고급 설정을 둔다.

- UI·스타일 도구는 `@deck/ui` 공개 API, 아이콘은 `@fluentui/react-icons`를 사용한다. [ADR-0011](adr/0011-winui-aligned-deck-ui.md)을 따른다.
- 공통 명단·사진·시간표 등록을 제공한다. 공통 등록을 기본 옵션으로 하되, 해제하면 이번 작업에만 자료를 쓸 수 있다.
- time_alert 현재 코드를 명부·시간표·기록·파일 양식의 주원천으로 삼는다. 동기화 없이 같은 파일을 두 제품에서 사용할 수 있게 한다.
- 수백 개 파일과 여러 학급·수백 명 자료를 처리한다. 일괄 작업은 진행·취소·부분 실패 결과를 제공하고 입력 화면을 멈추지 않는다.
- 기존 소스의 저자·라이선스·에셋 출처를 보존한다. 제3자 기여가 없다는 사용자 답변과 별개로, 코드에 포함된 외부 라이브러리의 고지는 확인한다.

이번 후보에서 매크로, 파일 검색, 문항집, 교과 시뮬레이터는 제외한다. 알림, 기기 동기화, 서버 기반 공간 예약은 후순위다. LivelySam은 필요한 로컬 기능만 선별한다.

## 2. 최신 기반에서 확정된 것과 필요한 것

최신 기반에는 WinUI 이름·props를 따르는 공통 컨트롤, 시스템 폰트, 개발용 UI 갤러리, 타이머 0.2.0과 모듈의 Fluent 직접 import 금지가 반영됐다. 파일 처리·공통 학생 자료·OS 작업 기능은 이번 업데이트로 추가되지 않았다.

확장 후보는 PDF 압축, 이미지 용량 줄이기, 간단한 이미지 편집이다. 안전한 기본값으로 드래그 후 바로 결과를 만드는 흐름을 우선한다. 유튜브 다운로드도 제품 후보로 기록하되, 현재 외부 네트워크 제한과 다운로드 엔진·배포 구성을 별도 제안에서 다룬다. 로컬 파일·개인정보 외부 전송 허용으로 확대 해석하지 않는다.

문서 변환은 확장자 문자열을 바꾸는 동작이 아니라 각 프로그램으로 파일을 열고 새 형식으로 저장하는 변환이다. 내용·서식 보존을 목표로 하며 변환 결과를 다시 열어 확인한다. 매크로가 포함된 파일은 XLSM/PPTM 등 내용을 보존할 형식을 구분하고, 파일을 열면서 문서 매크로를 실행하지 않는 설정을 검증한다.

## 4. 파일명 정리 통합안 — 사용자 검토 대상

한 도구 안에서 같은 파일 목록·미리보기·실행·복구 흐름을 사용하고, 이름을 만드는 방법만 선택하는 구성을 권고한다.

1. 파일을 끌어 넣는다. 하위 폴더 포함은 명시적으로 선택한다.
2. 이름 재료를 선택한다: 원래 이름·연번·날짜·직접 입력, 엑셀 열, 문서에서 추출한 연도·제목·분류.
3. 엑셀 매칭은 학번/번호/기존 이름의 정확 일치와 순서 매칭을 제공한다. 복합 추측 매칭은 첫 버전에서 제외하고 미연결 항목만 수동 지정한다.
4. 최종 파일명과 충돌 해결 결과를 실행 전에 확정한다. 같은 이름, 금지 문자, 긴 이름, 확장자 보존, 대소문자만 바꾸기, 이름 서로 바꾸기를 공통 엔진에서 처리한다.
5. 기본은 새 폴더에 결과 복사다. 원본 이름 변경은 별도 선택으로 제공하는 안을 제안한다.
6. 성공·실패 항목을 분리하고 실패만 다시 실행한다. 취소는 아직 시작하지 않은 항목부터 적용하고 완료 결과를 보존한다.
7. 되돌리기는 앱 재실행 후에도 사용할 수 있는 제한된 작업 이력을 권고한다. 파일이 이후 수정·이동되었으면 자동으로 덮어쓰지 않고 해당 항목을 복구 불가로 표시한다.

검토할 선택지는 **한 도구+방식 선택** 구성, **새 폴더 복사 기본+원본 변경 선택**, **정확 일치 자동 매칭+미연결 수동 처리**다. 모두 권고안이며 사용자가 별도 확인을 요청한 파일명 도구 구현 전에 확정한다. 삭제를 동반하는 복사 취소나 원본 변경의 안전한 수행 방식은 별도 호스트 제안에 포함한다.

## 5. time_alert와 NEIS photocrop 비교

이 비교는 현재 소스·기존 테스트 코드 조사 결과이며 실제 문서로 정확도를 측정한 결과는 아니다. 입력 형식이 다르므로 한쪽의 전체 성능이 우수하다고 단정하지 않는다.

| 항목           | time_alert                            | NEIS photocrop                                |
| -------------- | ------------------------------------- | --------------------------------------------- |
| 입력           | 나이스 사진명렬표·명부 XLSX           | 사진 출석부 PDF                               |
| 이미지         | XLSX 내부 원본 이미지 바이트 추출     | PDF를 200 DPI 렌더링 후 영역 크롭             |
| 매칭           | 셀·drawing 앵커, 읽기 순서·거리 폴백  | 테두리 윤곽선과 PDF 텍스트 좌표               |
| 사진 없는 학생 | 명단에 유지하고 경고                  | 사진 상자가 없으면 처리 대상에서 빠질 수 있음 |
| 미연결 사진    | 경고 개수로 남고 반환 결과에서는 빠짐 | 미확인 사진을 별도 저장                       |
| 테스트         | 해석 테스트 22개 확인                 | 해당 로컬 소스에서 자동 테스트 미확인         |

권고는 **XLSX에 time_alert를 주엔진으로 사용하고 PDF를 NEIS 방식으로 보완**하는 것이다. 독립 사진 추출은 공통 명부 등록 없이 사용하고 원본 바이트를 보존한다. 학생 기록용 축소 사진은 별도로 만든다.

이식할 때 함께 개선할 항목:

- time_alert의 주인 없는 사진도 결과 모델에 남겨 독립 추출에서 누락하지 않는다.
- 정확 좌표 매칭과 순서·거리 추측 매칭을 구분한다. 연결 근거가 불충분한 사진을 확정된 학생 사진으로 조용히 저장하지 않는다.
- 기존 테스트의 사진 바이트가 모두 같아 사진의 주인까지 검증하기 어렵다. 서로 다른 합성 이미지로 학생-사진 동일성을 확인한다.
- XLSX의 특정 시트·drawing 이름과 앵커 형식에 묶인 부분을 일반 XlsxReader의 관계 해석·크기 제한과 함께 정리한다.
- NEIS는 현재 OCR 없이 PDF 텍스트 레이어를 읽는다. 스캔 PDF의 자동 이름 추출은 별도 로컬 OCR 검토 대상이다.
- 회전 좌표 보정, 테두리 제거, 여백 조절, 미확인 사진 보존, 파일명 패턴은 NEIS에서 가져올 가치가 있다.

## 6. 공통 자료와 학교 도구

공통 설정에서 우리 반, 내 수업 학생, 사진, 학년도·학기, 일과표·시간표를 관리한다. 각 도구는 같은 위치에서 “등록한 자료 사용 / 이번 작업에만 사용”을 고른다. 초기 자료 등록을 앱 전체 사용의 필수 관문으로 만들지 않는다.

학생 자체와 학기별 학적을 구분하는 time_alert 모델을 재사용한다. 이름만으로 같은 학생이라고 합치지 않는다. 공통 명부가 변경돼도 이미 확정한 배정·출결·기록의 당시 정보는 보존한다. 도구별로 필요한 필드만 제공하며 학생 관찰 기록을 자리·발표 도구에 자동 노출하지 않는다.

배정 우선순위는 교사의 고정·제외·직접 지정이 최상위이고, 남은 대상에서 총횟수 균등을 기본으로 한다. 반복 회피·특정 조합 회피·업무 부담 등은 선택 조건으로 확장한다. 만족할 수 없는 고정 조건은 자동으로 풀지 않고 원인을 설명한다. 미리보기·다시 뽑기로 실제 수행 횟수를 올리지 않는다.

학생에게 보여주는 화면은 화면 복제와 확장을 지원한다. 학생 기기 접속은 범위에 없다. 교사용 조건·메모를 제외한 공개 결과 모델을 만들고, 화면 확장에서는 공개 창을 별도로 유지하는 호스트 설계를 검토한다.

지도일 배정기는 교사 명부와 월 달력을 사용한다. 하루 1~3명, 공휴일·사용자 제외일, 참여 조건, 고정자, 쉬운 교환과 실제 수행자 기준 집계를 기본안으로 한다. time_alert의 2026~2030 공휴일 표는 재사용 후보이며 공식 일정과 대조 후 범위·갱신 방식을 정한다. 시험감독의 교시×시험실 배정은 월별 지도일 배정보다 큰 모델이므로 후속 확장으로 구분하는 안을 권고한다.

호환은 두 단계로 검증한다.

1. 표준 XLSX 명부·시간표·사진명렬표의 같은 입력 수용 범위와 출력 양식을 유지한다.
2. `.teacherbackup` 왕복 호환을 별도로 검증한다. 현재 형식은 TIMEALERT 헤더, PBKDF2/AES-GCM, ZIP 안 SQLite DB·사진이다. Windows에서 아직 편집하지 않는 기록도 손실 없이 보존해야 한다. Android DB를 모든 모듈에 직접 노출하지 않고 호환 어댑터로 연결하는 안을 권고한다.

## 7. CoolReserve를 한 원천에서 개발하는 방식

원천은 기존 [CoolReserve 저장소](https://github.com/rochelobeJYJ/CoolReserve)로 유지한다. 업무 표 해석·문구 생성·수신자 검증·중복 등록 방지·불확실한 결과의 재등록 차단을 한 코어에서 관리한다.

권고하는 구성은 다음과 같다.

1. CoolReserve에 TeacherDeck UI/SDK를 사용하는 모듈 프론트엔드와 호스트 호출 어댑터를 둔다. 독립 실행판이 계속 필요하면 같은 업무 코어를 사용하는 별도 어댑터로 유지한다.
2. 쿨메신저 창 조작은 Python 프로그램을 iframe에 넣어 실행하는 식으로 해결하지 않는다. 허용된 대상·작업만 수행하는 호스트 기능이나 관리되는 helper 연결을 제안한다. 임의 프로그램 실행 권한을 모듈에 주지 않는다.
3. CoolReserve의 태그된 릴리스에서 모듈 산출물, 버전, 호환 호스트 버전, 해시를 만든다. 테스트와 라이선스 검사를 그 저장소에서도 수행한다.
4. TeacherDeck은 검증된 정확한 버전·해시를 참조해 기본 번들에 포함한다. 개발 브랜치의 최신 코드를 실행 중 무조건 가져오는 방식으로 두지 않는다.
5. 이후 서명된 원격 카탈로그가 준비되면 같은 산출물을 업데이트로 공급한다. 배포 자동화는 새 버전을 발견해 검증·통합 변경을 제안하도록 구성하고, 실패한 버전은 배포하지 않는다.

웹 모듈 산출물과 네이티브 연동 코드의 업데이트 주기는 다를 수 있다. 모듈 버전이 요구하는 호스트 기능이 없으면 호환성 해석기가 차단하도록 설계한다. 새 저장소·CI 파일·패키지 계약·helper 배포·카탈로그 변경은 해당 범위의 구체적 제안 후 구현한다. 아직 CoolReserve 원격 저장소를 수정하거나 배포하지 않았다.

## 8. 정확도와 조작 횟수의 기준

지원 형식과 명확한 입력은 기본값으로 자동 처리한다. 확실하지 않은 매칭·손상 문서·지원 밖 형식은 성공한 것으로 표시하지 않는다. 전체를 사용자가 다시 검수하게 만들기보다 처리할 수 없는 항목만 분리하고 해결 방법을 제공한다.

개인정보 제거는 표시 위에 색을 칠하는 데서 끝나지 않는다. 대상 텍스트·이미지 픽셀을 삭제한 새 파일을 만들고 텍스트 추출·렌더링·OCR 확인을 교차한다. 문서 속성·주석·첨부·숨은 내용 등 지원 범위를 명시하고, 제거를 입증하지 못한 파일은 완료 처리하지 않는다. 자동 탐지는 전화번호·주민번호 등 형식이 강한 값부터 시작하며 이름·주소·학번·계좌번호처럼 문맥이나 명단이 필요한 항목은 제공된 명부·검색·수동 지정과 결합한다. 임의의 모든 문서에서 개인정보를 100% 자동 발견한다고 보장하지 않는다.

회의록은 빠른 한국어 조합 입력·화자 전환·Enter 연속 입력을 실제 화면에서 확인한다. 자동 저장·미리보기·통계 처리가 입력 이벤트를 막지 않도록 분리하고, 기존 한국어 IME 처리 사례를 회귀 검사한다.

위 순서는 의존성과 검증 비용을 기준으로 한 권고다. 일정 알림을 기다리지 않고 독립 도구부터 완성할 수 있다. 네트워크 루틴·CoolReserve를 빼자는 뜻이 아니며, 필요한 호스트 계약을 먼저 만든 뒤 연결한다.

각 모듈은 합성 입력·예상 출력, 순수 로직/SDK 검사, 실제 파일 흐름, 키보드·DPI·테마 확인, `pnpm verify`, 패키지 검사를 완료한다. 배포 전에는 설치·제거·업데이트, 일반 사용자 권한, Office 버전 차이를 별도 PC에서 확인한다. 현재 PC를 첫 기준으로 하되 한 PC의 성공을 모든 학교 PC의 검증으로 표현하지 않는다.

다음 검토 결과물은 파일명 도구의 구체적인 화면 흐름과 위 4절 선택안, 파일/공통 자료의 API 제안, CoolReserve 산출물·호스트 계약이다. 추가로 큰 질문 목록을 반복하지 않고 결정이 필요한 지점에만 대안을 제시한다.
