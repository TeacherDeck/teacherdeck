# ADR-0026: TimeAlert DB7와 사진 포함 백업 이동

- 상태: 2026-10-11 사용자 승인, 구현 중
- 근거: [승인 제안 1번](../proposals/classroom-portability-presentation.md), 원작 `BackupManager.kt`, Room `AppDatabase/7.json`

## 결정

main 신뢰 셸에서만 원작 TIMEALERT v1 백업을 읽고 내보낸다. 암호는 UTF-8 PBKDF2-HMAC-SHA256 120,000회로 처리하고 salt16·IV12·AES-256-GCM 태그16 형식을 유지한다. 입력의 인증을 마친 뒤 앱 소유 임시 영역에 ZIP을 해제한다. 최대 입력512MiB·실제 해제1GiB·사진 하나16MiB/합계256MiB를 검사한다. 경로 탈출, 중복 엔트리, 불명확한 형식·스키마, 손상 DB/WAL을 거부한다.

동시 세션은 하나다. 호스트만 DB·사진 원본을 갖고 셸에는 공통 자료 투영, 원작 표별 행 수, 보존 전용 항목 안내와 불투명 세션 핸들을 돌려준다. DB7의 Room hash와 모든 알려진 표·기본값·숨김/생성 열·외래키 대상/작용·인덱스 구조를 검사하며 미래/구버전 호환을 추측하지 않는다. WAL은 SQLite backup API로 정상 DB에 접은 뒤 보존하여 원작 복원기가 WAL을 무시해도 변경이 사라지지 않게 한다.

공통 자료 적용은 expectedRevision과 명시적 확인으로 직렬화한다. 기존 자료를 대체하지 않고 새 식별자로 추가하며, 교사가 지정한 학생 연결만 기존 master를 재사용한다. 이름만 같다고 병합하지 않는다. 사진은 기존 호스트 사진 저장소에 새 식별자로 게시한다. 취소·실패에는 공통 자료와 원본 백업을 유지한다.

내보내기는 저장한 공통 자료만 사용한다. 원작 세션이 있으면 알려진 편집만 트랜잭션으로 반영하고 미편집 표·열·연락처·메모·Room 식별자를 유지한다. 삭제와 재삽입으로 관계 기록을 지우지 않는다. 원작 세션이 없으면 공식 DB7 구조로 새 DB를 만든다. 새 salt/IV로 암호화하고 기존 OutputBatch append-new로 새 파일만 게시한다. 셸에 원본 DB 경로나 비공개 필드를 전달하지 않는다.

사진명렬표는 기존 OOXML 읽기·사진 대응 규칙을 재사용하여 대응 후보를 확인한 뒤 등록한다. 동일 앵커 복수 사진, 동명이인, 매칭 실패는 교사가 확인하며 임의 확정하지 않는다. 부분 일과의 적용 시작 교시는 학교 자료의 선택적 필드로 보존하며 기존 JSON·모듈 읽기 계약은 하위 호환으로 유지한다.

## 검증

합성 DB와 암호화 입력으로 인증 실패, UTF-8 암호, ZIP 상한·경로·중복, Room/스키마 거부, WAL, 낙관적 경합, 원형 표 보존, 사진 연결과 양방향 바이트 계약을 검사한다. Android 실기 복원과 실제 새 PC 이동은 별도 증거 전까지 미검증으로 표기한다. 원작 JDK17 PBKDF2/AES-GCM API와 UTF-8 암호를 사용한 Java→Rust 고정 벡터 및 Rust→Java 출력 인증을 확인했다. 이 검사는 Android Room 복원 실기 증거를 대신하지 않는다. 전체 검증·설치본 크기는 루트 통합 완료 후 기록한다.
