# ADR-0019: 파일명 계획과 보호된 원본 변경

- 상태: 승인됨
- 날짜: 2026-10-11
- 결정자: 프로젝트 사용자 (파일 도구 통합안과 fs 1.3/file-ops 1.0 명시 승인)

## 맥락

직접 패턴·엑셀 정확 연결·문서 정보로 파일명을 정리하되, 기본은 원본을 보존하는 새 폴더 복사다. 원본 변경은 읽기 핸들과 분리된 캡과 호스트 확인이 필요하다. 이름 교환·취소·충돌·재시작·결과 변조를 고려하지 않은 단순 rename과 경로 기록만으로는 안전한 되돌리기를 제공할 수 없다.

## 결정

[파일 작업 세부 명세](../spec/file-operations.md)를 따른다. fs 1.3은 선택한 폴더에서 경로 없는 파일 핸들을 제한된 페이지로 제공한다. file-ops 1.0은 계획·실행·이력·되돌리기를 제공한다. 모듈의 파일 이름 입력은 하나의 이름이며 기존 부모 밖으로 이동하지 않는다. 복사 결과 삭제는 제공하지 않는다.

계획은 소유 모듈·세션과 결합하고 5분 후 만료한다. 서로 이름을 바꾸는 파일은 하나의 연결군이다. 실행 호출 하나는 다음 연결군 하나를 처리하며 완료 여부를 반환한다. 사용자 취소는 다음 호출을 막는다. 군 내부의 임시 이름 이동과 최종 게시 중에는 취소하지 않는다. 첫 실행과 되돌리기 시작 전에 호스트 확인창을 띄운다.

Windows에서는 reparse 파일과 모든 reparse 조상을 거부하고 부모 디렉터리를 열린 핸들로 유지한다. 파일은 쓰기/삭제 공유를 거부하는 DELETE+READ 열린 핸들로 잡고, 볼륨·파일 ID 및 SHA-256 기반 청크 검증값으로 확인한 뒤 handle 기반 rename을 수행한다. 목적지가 있으면 실패하며 덮어쓰지 않는다. 임시 파일은 같은 부모의 예측 불가능한 host 이름이고 사용자 파일을 제거하는 API는 없다.

이력은 앱 전용 디렉터리의 호스트 전용 journal이다. 일반 로그나 모듈 storage에는 원본 경로·이름·내용을 남기지 않는다. 매 이동 전에 의도를 sync하고 이동 후 상태를 append/sync한다. 재시작 시 원본·임시·최종 중 동일 파일이 있는 위치를 확인하며 추정 복구나 사용자 파일 삭제를 하지 않는다. 이력은 최대20건이며 진행 중·차단된 기록을 자동으로 버리지 않는다. 모듈에는 불투명 이력 핸들·시각·건수·상태만 제공한다.

되돌리기는 같은 ID와 내용 검증값, 수정 시각, 안전한 부모, 원래 이름의 비점유를 모두 확인한다. 수정·대체·이동·충돌된 파일과 그 연결군은 보존하고 차단한다. 복구 도중 중단된 군도 journal로 재확인한다. 실패 시 데이터를 지우거나 이름을 자동 변경하지 않는다.

## 결과

원본 변경은 승인된 선택 기능이며 기본 복사는 fs의 새 결과 출력만 사용한다(PRV-006). CAP-002/007/008, BRG-007을 유지한다. 새 런타임 의존성이나 ACL/CSP 변경은 없다. 작은 Windows FFI는 별도 native 경계에만 두고 SAFETY 근거를 기록한다. 모듈의 완료 증거와 호스트 합성 파일 검증은 구분한다.

## 대안

읽기 핸들을 일반 쓰기 권한으로 승격하거나 경로를 모듈에 노출하는 방식은 제외했다. 문자열 경로 rename 후 메타데이터만 비교하는 방식은 파일 대체 경쟁을 막지 못한다. 복사 undo로 결과 파일을 지우는 방식은 승인 범위 밖이므로 제공하지 않는다.
