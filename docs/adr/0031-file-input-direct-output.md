# ADR-0031: 파일 드래그 입력과 원본 폴더에 새 결과 저장

- 상태: 채택
- 날짜: 2026-10-12
- 근거: 사용자의 모든 모듈 드래그 입력·기본 저장 위치 수정 요청

## 배경

자동 처리를 사용하는 도구는 드래그 입력 직후 저장 폴더 선택창을 열었다. 입력한 파일이 보이기 전에 대화상자가 열려 입력 실패로 오해하기 쉬웠다. 기존 출력은 사용자가 선택한 폴더 안에 매번 결과 하위 폴더를 만들어 파일 관리를 어렵게 했다.

## 결정

파일 입력을 지원하는 모든 모듈은 네이티브 `fs.dropped`의 핸들을 기존 가져오기 검증에 전달한다. 파일명·개수·읽는 중 상태 또는 거절 이유를 화면에 표시하며 드롭 처리에서 `pickFiles`를 호출하지 않는다. 입력 자체와 자동 처리의 결과는 구분한다.

기본 출력은 각 입력 파일의 부모 폴더에 새 결과 파일을 게시한다. 사용자가 다른 폴더를 지정하면 그 폴더를 직접 쓴다. 원본이 없는 새 문서·백업·템플릿은 사용자가 폴더를 선택한다. 결과 하위 폴더를 자동 생성하지 않는다. 기존 파일과 이름이 겹치면 번호를 붙이고 원본 파일을 보존한다.

이를 위해 기존 `fs`에 하위 호환 추가 메서드 `openOutputFolder({sourceHandle?,parentHandle?})`를 더하고 버전을 1.4.0으로 올린다. 둘 중 정확히 하나의 핸들을 받는다. 소유 모듈·세션을 확인한 읽기 파일 핸들의 부모 또는 선택한 폴더 핸들만 사용한다. 결과는 기존 `OutputBatch`이며, 청크 쓰기·취소·권한 해제 계약을 그대로 따른다. 경로는 호스트에만 남는다.

기존 `createOutputFolder` 계약은 유지한다. 기존 폴더용 디렉터리 가드와 배타적 새 파일 게시를 재사용하고 모듈별 동시 배치·용량 제한을 그대로 적용한다. 권한은 세션 한정이며 기억한 저장 폴더 권한이나 파일 열람 범위를 추가하지 않는다. 반환한 폴더 핸들은 위치 표시·탐색기 확인용이며 `listFiles`나 `openRead`로 같은 폴더의 다른 파일을 열람할 권한을 주지 않는다.

## 대안과 영향

모듈에 경로를 전달하거나 입력 파일 핸들을 폴더 핸들로 위장하면 CAP-002 및 권한 종류 검증을 깨뜨린다. `createOutputFolder`의 의미를 바꾸면 기존 모듈이 요청한 하위 폴더 생성 계약을 깨뜨린다. 따라서 기존 캡의 minor 추가를 사용한다. 브리지·매니페스트·카탈로그 포맷, CSP·ACL, 의존성, 라이선스는 변경하지 않는다. 사용자 파일 삭제·덮어쓰기도 도입하지 않는다.

앱은 0.8.0, SDK는 0.9.0이 필요하다. 새 메서드를 쓰는 모듈은 `fs ^1.4.0`과 모듈 minor 버전을 선언한다. 읽기 전용·삭제된 원본·보호된 폴더의 실패를 보고하며 다른 폴더로 조용히 우회하지 않는다. 사용자가 직접 다른 폴더를 지정할 수 있다.

## 검증

모듈 테스트는 드롭 후 파일 선택창 호출 없음, 입력 확인과 거절 안내, 원본 핸들 기본 출력 및 명시 폴더 우선을 확인한다. 호스트 테스트는 서로 다른 원본 부모, 같은 이름 충돌, 폴더 미생성, 다른 모듈·세션·종류 핸들 거부, 잘못된 인자와 배치 권한 해제를 확인한다.
