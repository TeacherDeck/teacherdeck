# ADR-0020: 학교 공통자료의 제한된 읽기 공유

상태: 승인. 2026-10-11에 사용자가 [공통 기반 제안서 A](../proposals/classroom-foundation-next.md)의 school-data 1.0과 PRV-007의 학교 자료에 한정한 공유 예외를 명시적으로 승인했다.

교사가 학기·우리 반·내 수업·학생 학적·사진·일과표·시간표를 셸에서 한 번 관리한다. 모듈 저장소를 서로 읽는 방법은 사용하지 않는다. 셸 소유 학교 자료에만 `school-data` 1.0 읽기 캡을 추가하고, 각 도구가 요청한 범위 안에서 교사가 셸의 신뢰 화면으로 대상·필드를 확인한다. 연락처·생일·출결·관찰 기록·원본 경로를 공유 타입에 넣지 않는다.

학적은 학생 master와 학기별 enrollment, 수업과 enrollment 연결을 나눈다. 이름만으로 동일 학생을 판정하지 않는다. 시간표는 교시→시간과 요일→수업의 두 축, 기간표 전체 대체, 날짜별 요일 대체·부분 일과표, MOVE/CANCEL/ADD와 맞교환 그룹을 명시적으로 저장한다. A의 공통자료는 TeacherDeck 소유의 버전 있는 파일이며 Android Room DB와 같은 파일이라고 주장하지 않는다.

자료 수정은 셸 전용 명령으로만 하고 expectedRevision으로 오래된 화면의 덮어쓰기를 거부한다. 공통자료 등록이 모든 도구의 권한을 만들지 않는다. grant는 모듈과 context와 scope를 가진 불투명 토큰이고 각 요청·사진 읽기마다 재검사한다. 기억한 grant만 재시작에 복원하며 일시 grant·스냅샷·사진 리소스는 언로드에 폐기한다. 사진은 기존 인증 `/_resources/` 범위 읽기 통로와 호스트 FileReadSession을 사용하며 외부 URL이나 사진 파일 경로를 반환하지 않는다.

자료 변경이 이미 읽은 명부나 확정 이력을 자동 교체하지 않는다. 도구에서 명시적으로 다시 읽고 적용한다. 공통 등록이 없는 경우와 공유하지 않는 작업에서는 기존 임시 명단을 계속 사용한다. 권한 철회는 추가 조회·사진 리소스를 막으며 사용자가 이미 저장한 작업 스냅샷을 지우지 않는다.

새 런타임 의존성·동기화·알림 예약·사용자 원본 덮어쓰기를 추가하지 않는다. 제안서 B의 전체 TimeAlert 백업·암호화/SQLite 의존성과 C의 별도 확장 창은 이번 승인과 구현 범위에 포함하지 않는다. 세부 계약과 검사는 [학교 자료 명세](../spec/school-data.md)를 따른다.

A의 수동 파일 교환은 원본 표준 XLSX 명부·격자/목록형 주간 시간표와 TeacherDeck 자체 학교 자료 JSON 오류복구까지 구현한다. ZIP 운반/생성에는 기존 host zip, XML/학생 해석에는 검증된 사진 추출 코드와 DOMParser를 재사용해 새 의존성을 추가하지 않는다. XLSX는 전체 백업이나 사진 자동 등록이 아니며 범위를 미리보기·화면·명세에 표시한다. 학교 자료 손상은 앱 전체 실행을 막지 않고 복구 전 원본 손상본을 별도 보존한다.

2026-10-11 [출력 후속 제안](../proposals/school-data-output-followup.md)을 별도로 승인받아 main 전용 JSON 복구 파일·시간표 PNG 출력 명령과 최소 ACL을 추가한다. JSON은 호스트가 현재 검증된 저장 자료를 읽으며 모든 학기·식별자·연결·일과 시각·주간표·날짜 변경·사진 metadata를 보존한다. 사진 파일과 미저장 초안은 포함하지 않으며 같은 PC의 명부·시간표 복구용이다. 이동용 전체 백업이나 TimeAlert `.teacherbackup` 호환으로 표시하지 않는다.

PNG는 현재 화면의 주간표를 수업 식별자로 해석해 시스템 한글 글꼴과 Fluent 테마로 그린다. 미저장 편집과 표시할 교시를 포함하되 일과 시각·날짜 변경·사진은 담지 않고 학교 자료 저장을 대신하지 않는다. 긴 수업명은 줄바꿈하며 제한을 넘으면 잘라내지 않고 실패한다. 호스트는 PNG의 base64/파일 형식/완전한 디코드·16MiB·한 변 4096px·16메가픽셀을 폴더 선택 전에 확인한다. 두 출력은 기존 journaled OutputBatch의 임시 쓰기·append-new 게시를 재사용한다. 취소·오류는 원본 및 학교 자료를 보존한다. 모듈 캡·SDK·school-data 1.0 읽기 계약과 overlay ACL은 바뀌지 않는다.
