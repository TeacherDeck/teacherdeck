# ADR-0024: 셸 모션과 덱 홈 구성

- 상태: 승인됨
- 날짜: 2026-10-11
- 결정자: 프로젝트 소유자

## 맥락

셸은 화면을 바꿀 때 아무 움직임 없이 교체되고, 내비 레일의 선택 표시도 순간이동한다. 덱 홈은 같은 모양의 카드가 한 그리드로 나열될 뿐이라 자주 쓰는 도구를 찾기 어렵다. 시작할 때는 데이터를 받는 동안 스피너만 보인다.

학교 PC는 저사양이고 전자칠판으로 출력되는 경우가 많다. 모션은 짧고 가벼워야 하며, Windows "애니메이션 효과" 설정을 끈 사용자와 멀미를 느끼는 사용자를 배려해야 한다. 새 의존성(GEN-004)이나 새 창·권한(GEN-005) 없이 해결해야 한다.

## 결정

- 셸 모션은 WinUI 패턴을 따른다: 내비 레일 선택 표시(pill)의 이동, 새 페이지의 Entrance(아래에서 올라오며 나타남), 모듈 화면의 Drill-in(살짝 커지며 나타남), 카드의 순차 등장. 이전 화면의 퇴장 애니메이션은 두지 않는다.
- 모션은 CSS `transform`·`opacity`만 움직이고, 시간·곡선은 Fluent `duration*`·`curve*` 토큰, 거리·간격은 `@deck/ui` 모션 토큰으로 쓴다(UI-009).
- OS의 `prefers-reduced-motion`과 셸 설정의 "애니메이션 효과" 끔을 모두 존중한다. 둘 중 하나라도 끄면 모션을 즉시 끝난 상태로 그린다.
- 시작 화면은 별도 창 없이 셸 안에서 그린다. 데이터를 받는 동안 덱 카드가 펼쳐지는 짧은 애니메이션을 보여 주고, 실제 로딩이 끝나면 바로 넘어간다(최소 표시 시간만 둔다). 업데이트로 새 도구가 생긴 뒤 첫 실행에는 그 수를 함께 알린다.
- 모듈 화면에서는 내비 레일을 숨겨 도구가 창 너비를 모두 쓴다(전자칠판). 레일에는 카테고리만 있어 도구 안에서는 쓸 일이 거의 없다. 대신 상단바 맨 왼쪽에 모든 화면 공통 뒤로 버튼을 둔다(WinUI TitleBar). 레일은 미끄러지지 않고 바로 사라진다. 폭을 애니메이션하면 도구 화면이 프레임마다 다시 배치되기 때문이다(UI-009).
- 덱 홈은 인사·날짜, 즐겨찾기, 카테고리별 전체 도구 순으로 구성한다. 즐겨찾기는 카드의 별 토글로만 바꾼다(상황 메뉴는 터치 전자칠판에서 찾기 어렵다). 카테고리 묶음이 구분을 맡으므로 카드는 색 타일 없이 아이콘만 보인다. 즐겨찾기·본 도구 목록은 테마 설정처럼 셸 자신의 저장소에 모듈 id만 저장한다.

## 결과

- 의존성·권한·브리지 포맷 변경이 없다. 모듈 iframe 안의 모션 설정 전달은 이번 범위가 아니다(테마 페이로드 변경은 브리지 포맷 변경이므로 필요하면 별도 제안).
- 셸 저장소에는 모듈 id만 남고 파일·사용자 데이터는 남지 않는다(PRV-003).
- 시작 직후 창이 그려지기 전의 빈 Mica 창은 그대로다. 첫 그림 뒤에 창을 보이게 하려면 호스트 명령과 ACL이 필요하므로 별도 제안으로 다룬다.

## 대안

- Framer Motion 같은 모션 라이브러리: 런타임 의존성 추가(GEN-004)이고, 필요한 모션이 CSS로 충분하다.
- 별도 스플래시 창: 새 창과 ACL 변경이 필요하다(GEN-005). 셸 첫 화면으로 충분하다.
- View Transitions API로 카드 → 모듈 공유 요소 전환: 모듈 iframe 스냅샷 비용이 저사양 PC에 부담이고 React 지원이 아직 안정적이지 않다.
- 고정한 시간 동안 보여 주는 스플래시: 매일 여러 번 켜는 도구라 기다림이 누적된다.
