# ADR-0008: docs/spec은 규범 원천, 계층형 AGENTS.md는 작업 지침

- 상태: 승인됨
- 날짜: 2026-10-08
- 결정자: 신민성, 정영주

## 맥락

이후 코드는 대부분 사람이 AI 에이전트와 함께 쓴다. 에이전트는 문서가 길거나 여러 곳에 흩어지면 규칙을 놓치고, 규칙이 여러 곳에 복사되면 서로 어긋난다. 규격 위반은 리뷰가 아니라 기계적으로 즉시 드러나야 한다.

## 결정

- `docs/spec`이 규범 원천이다. 기계 검증이 가능한 규격(스키마, 캡 타입·버전, 에러 코드)의 원천은 Rust 타입이며 나머지는 `pnpm gen`으로 생성한다.
- 계층형 `AGENTS.md`는 작업 지침이다. 규칙 ID, 한 줄 요약, 링크만 담는다. `AGENTS.md`가 있는 디렉터리에는 `@AGENTS.md` 한 줄짜리 `CLAUDE.md`를 둔다.
- 모든 MUST·MUST NOT·SHOULD 규칙은 규칙 ID(`PREFIX-NNN`)를 갖고 기계적 강제 장치와 짝을 이룬다. 기계화할 수 없으면 `[manual]`로 표시한다.
- 검사기는 `[규칙ID] 메시지 (정의: 경로)` 형식으로 실패한다.

## 결과

- 문법과 규칙 인덱스: [spec/README.md](../spec/README.md). 절차: [process.md](../spec/process.md).
- 스펙 변경은 DOC-002 절차를 따른다. 코드에 맞춰 스펙을 고치지 않는다(GEN-001).
- 규칙 인덱스와 레지스트리 표는 Phase 2부터 생성물이다(GEN-006).
- Claude Code 훅은 보호 경로의 우발적 편집을 막는 장치이며 보안 경계가 아니다(Phase 7).

## 대안

- **AGENTS.md 하나에 모든 규칙**: 단순하지만 길어지면 에이전트가 놓치고, spec과 중복된다.
- **규칙 없이 리뷰에 의존**: 바이브코딩 규모에서는 리뷰가 위반을 따라잡지 못한다.
