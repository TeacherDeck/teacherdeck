# ADR-0002: 모듈은 웹 번들, 호스트는 버전이 붙은 범용 캡 제공

- 상태: 승인됨
- 날짜: 2026-10-08
- 결정자: 신민성, 정영주

## 맥락

도구를 계속 쌓아 가려면 새 도구 추가가 앱 전체 릴리스를 기다리지 않아야 한다. 동시에 네이티브 코드 배포는 서명된 앱 업데이트로만 해야 안전하다. 도구마다 호스트 기능을 따로 만들면 호스트가 끝없이 커진다.

## 결정

- 모듈은 웹 번들(HTML/JS/WASM)이다. 네이티브 코드는 호스트에만 있고 Tauri updater로만 배포한다.
- 모듈은 앱 업데이트와 독립적으로 배포한다(카탈로그).
- 호스트는 버전이 붙은 범용 캡(capability)을 제공한다. 모듈은 필요한 캡과 버전 범위를 매니페스트에 선언한다.
- 호스트가 선언을 만족시키지 못하면 "앱 업데이트 필요"를 표시한다.
- 설치본에 동봉된 모듈("기본 모듈")도 같은 포맷이다.

## 결과

- 매니페스트: [modules.md](../spec/modules.md). 캡: [capabilities.md](../spec/capabilities.md). 호환성 해석: [versioning.md](../spec/versioning.md). 배포 형식: [catalog.md](../spec/catalog.md).
- 캡은 범용 프리미티브여야 한다(CAP-001). 새 캡은 사람 승인이 필요하다(CAP-005, GEN-005).
- 무거운 처리는 우선 모듈 측 WASM으로 해결한다. 이 때문에 모듈 CSP에 `wasm-unsafe-eval`이 필요하다.

## 대안

- **모듈마다 네이티브 플러그인(DLL)**: 기능은 자유롭지만 서명·보안 검토 비용이 크고, 악성 모듈이 OS 전체 권한을 얻는다.
- **모든 도구를 앱에 내장**: 단순하지만 도구 하나 고칠 때마다 앱 전체를 릴리스해야 한다.
