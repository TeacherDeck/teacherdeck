# ADR-0012: 파일 입출력 기반과 전송 검증

- 상태: 승인됨(1차 범위), 전송 세부 결정은 ADR-0013·0014로 보완
- 날짜: 2026-10-10
- 결정자: 프로젝트 소유자, 현재 개발 대화의 “1차 파일 입출력 구현 승인”

## 맥락

파일 기반 도구를 붙이려면 선택한 파일의 바이트 읽기와 새 결과 저장이 필요하다. 현재 fs 1.0은 선택·정보·탐색기 열기만 제공한다. 구체적인 API·한도·원본 보호 정책은 [공통 기반 제안서 1차](../proposals/module-foundations.md)에 있다.

## 결정

원본은 읽기만 하고 사용자 선택 폴더 아래 새 결과 폴더에만 작성하는 1차 범위를 승인했다. 공개 API를 노출하기 전에 Windows 파일 핸들을 유지하는 읽기 서비스와 경계 테스트를 만든다. 파일은 최대 512MiB, 한 번에 읽는 양은 최대 256KiB다. 대상과 부모의 reparse point를 거부하고 열린 핸들을 유지하며 변경을 검사한다. 네이티브 파일 처리는 호스트에 둔다.

읽기·출력 권한은 기존 파일 선택 핸들에서 분리한다. SDK·리소스 URL·프로토콜을 연결하기 전 모듈 격리와 바이너리 전송 한도를 검증한다. 내부 읽기 서비스만 만든 상태에서는 fs 레지스트리와 공개 SDK를 1.1로 올리지 않는다.

## 검증에서 확인한 제약

Wry 0.57.0의 Windows 커스텀 프로토콜은 요청 본문을 전체 Vec으로 만든 뒤 앱 핸들러를 부른다. 따라서 핸들러에서 256KiB를 검사하는 것만으로 승인 제안의 수신 전·중 메모리 제한을 만족하지 못한다. POST 구현은 제공하지 않는다. 기존 모듈의 동일 origin 배치는 인접 iframe의 자료 접근 가능성도 별도로 검증해야 한다.

전송 방식과 모듈 origin 변경은 [후속 제안서](../proposals/file-transfer-followup.md)로 분리한다. 그 부분의 추가 승인 전에는 CSP·ACL·공개 브리지·프로토콜을 변경하지 않는다(GEN-005).

2026-10-10 사용자의 “두 보완안 승인” 이후 [ADR-0013](0013-module-origin-isolation.md)과 [ADR-0014](0014-bounded-file-transfers.md)를 적용한다. 공개 API는 fs 1.1이며 쓰기는 64KiB 순차 인증 브리지, 읽기는 모듈별 origin의 제한된 리소스 GET을 사용한다.

## 결과

파일을 안전하게 여는 내부 서비스는 외부 권한을 확대하지 않고 검증할 수 있다. 파일 입출력 전체 완료는 공개 API와 실제 Windows 입력·출력·취소·권한 검증 이후에만 선언한다. 공통 명부와 OS 연동은 이번 결정에 포함되지 않는다.

## 대안

전체 파일을 브리지 메시지나 POST 본문으로 한 번에 보내는 방식은 선택하지 않는다. 제한된 쓰기 청크와 모듈별 origin은 현재 승인 범위를 보완하는 대안으로 검토하며 기존 규칙을 암묵적으로 완화하지 않는다.
