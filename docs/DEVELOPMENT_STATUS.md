## 공동작업자의 추가 업데이트 통합

작업 중 원격을 다시 확인해 `a876d1e`(2026-10-10 18:59:12 +09:00)까지 통합했어요. `c81c7a2`의 개발용 `@types/node` 26.6.4 업데이트와 `a876d1e`의 테두리 없는 창·자체 제목 표시줄을 반영했어요. 셸 충돌은 새 제목 표시줄과 기존 모듈 origin 격리·보안 프로브를 모두 유지하도록 해결했어요. 회의록·배정기 소스는 원격 변경과 겹치지 않았어요.

[PR #5](https://github.com/TeacherDeck/teacherdeck/pull/5)에 사람이 처리할 요청 두 가지가 있었어요.

- 창 조작 권한 6개 추가: 사용자의 즉시 통합 지시에 따라 로컬 `main` 창에만 반영했어요. 전체 창 권한이나 원격 origin 권한은 열지 않았어요. [승인 범위](proposals/titlebar-window-controls.md)와 [ADR-0015](adr/0015-shell-window-controls.md)를 남겼어요.
- `pnpm tauri dev`에서 드래그·더블클릭·최소화/최대화/닫기 버튼 확인: 컴포넌트 동작과 ACL 범위는 자동 검증해요. 실제 네이티브 마우스 조작은 아래 검증 한계에 별도로 기록해요.

PR #1은 의존성 업데이트 안내이며 별도 사용자 요청이 없었어요. 두 PR의 대화 댓글·리뷰·인라인 댓글·연결 이슈에도 추가 요청이 없었어요.

## 초기 두 모듈: 구현·통합 검증 완료

### 회의록

0.2.0에서 **참석자 입력 → 회의 시작 → 보이는 화자 목록·연속 입력** 흐름을 복원했어요. 화자 단축키, 발언 수정·삭제·되돌리기, F4/F8/F9, 기록 종류 버튼을 제공해요. 참석자가 많아도 데스크톱 화면의 입력창이 화자 목록 아래로 밀리지 않게 배치했어요.

브라우저에서 시작·Alt+2 전환·Enter 3건 연속 기록·발언 수정·F8 공개용 본문에서 비공개 제외·새 회의 전 보관·지난 회의 복원·모듈 재실행을 확인했어요. 1080×720과 600×680, 밝은/어두운 테마와 글자 토큰 150% 확대에서 조작부의 가로 넘침이 없었어요. 이 검증은 SDK mock host를 사용해요.

공개용 텍스트·마크다운·요약, 비공개를 포함한 JSON 백업, 원본 JSON 불러오기, 위원회 명단과 지난 회의 보관을 연결했어요. 파일은 승인된 fs 1.1 API로 처리해요. 회의 전환 중 입력 동결과 보관 실패 복구를 보완했어요. 원본의 한글·워드 서식 클립보드 복사는 아직 지원하지 않아요. 즉시 앱 종료·LRU 언로드 때 비동기 저장 완료를 보장하지 않으므로 저장 완료 안내를 확인해야 해요. 자세한 제한은 [회의록 안내](../modules/meeting-note/README.md)를 봐 주세요.

### 지도일 배정

0.2.0에서 **명단 추가 → 달력 → 배정 → 날짜별 직접 수정** 순서로 재구성했어요. 이름을 Enter로 연속 추가하고, 날짜 셀 전체를 눌러 고정·제외를 체크하거나 담당자를 바로 교체해요. 여러 명 붙여넣기는 보조 기능으로 접었어요. 기존 Worker 계산·누적 횟수 균등 배정·고정/제외 우선 원칙을 유지해요.

브라우저에서 합성 교사 2명을 Enter로 추가해 10회씩 균등 배정하고, 날짜 고정 후 재배정·저장·모듈 재실행을 확인했어요. 600×680의 어두운 테마 및 글자 토큰 150% 확대에서 조작부의 가로 넘침이 없었어요. SettingsExpander는 Enter와 Space로 펼치고 접을 수 있었어요. 초기 버전에서 확인한 누적 횟수 반영과 직접 교체 우선 동작은 회귀 테스트로 확인해요.

여러 달의 실제 수행 이력을 기록·누적하는 기능은 아직 구현하지 않았어요. 자세한 동작과 제한은 [지도일 배정 안내](../modules/duty-planner/README.md)를 봐 주세요.

## 파일 공통 기반: 승인 범위 구현 완료

[1차 제안](proposals/module-foundations.md)과 [두 보완안](proposals/file-transfer-followup.md)의 사용자 승인을 반영했어요. 앱 0.1.0, SDK 0.2.0, fs 1.1.0이에요. 파일 도구가 공통으로 사용할 API이며, 개별 이미지·PDF·Office 변환 도구까지 완성한 것은 아니에요.

- 선택한 파일을 최대 256KiB씩 읽고, 결과는 선택 폴더 아래 새 폴더에만 저장해요.
- 쓰기는 기존 인증 브리지로 64KiB씩 순차 전송해요. SDK `readChunks`·`writeBlob`이 전송과 정리를 맡아요.
- 원본과 기존 결과를 덮어쓰지 않아요. 중복 이름은 연번을 붙이고, 게시가 완료된 파일은 취소해도 보존해요.
- 파일·폴더 핸들과 읽기·쓰기·결과 작업 권한을 구분하고, 모듈 소유자·언로드 세대·미사용 만료를 검사해요.
- 각 모듈은 독립 origin을 사용해요. 셸 브리지는 iframe과 정확한 origin을 함께 확인해요.
- 임시 작업은 복구 기록과 내용을 확인해 정리해요. 마지막 기록 이후 바뀐 파일, 손상된 기록, 사용자가 수정·추가한 파일은 보존해요.

파일당 512MiB, 결과 작업당 2,000개·2GiB가 현재 한도예요. 출력 위치는 hard link를 지원해야 해요. 일반적인 로컬 NTFS에서 검증했으며 다른 파일시스템·공유 드라이브는 별도 확인이 필요해요. 정상 전송의 메모리를 청크 단위로 제한하지만 악성 요청의 전역 메모리 절대 상한이나 전원 장애까지의 영속성을 보장하지는 않아요. 자세한 계약은 [SDK 안내](../packages/sdk/README.md)와 [ADR-0014](adr/0014-bounded-file-transfers.md)에 있어요.

통합 전체 검증 로그는 `target/ux-verify.log`, 새 격리 보고서는 `target/ux-sec-probe.json`, Windows 빌드 로그는 `target/ux-debug-build.log`와 `target/ux-release-build.log`에 있어요. 이전 파일 기반의 검증 로그는 `target/file-foundation-verify.log`예요. 자세한 격리 결과는 [SEC-004 기록](security/sec-004.md)을 참고해요. 로그와 빌드 산출물은 Git에 포함하지 않아요. Windows 링크 생성·파일 잠금은 승인된 샌드박스 밖 실행으로 실제 OS 동작을 확인했어요. 새 런타임 의존성이나 검사 억제는 추가하지 않았어요.

브라우저의 회의록·배정기 조작 검증은 SDK mock host에서 수행했어요. 실제 WebView2 격리 검증과 Rust의 파일 처리 검증을 별도로 수행했으며, 네이티브 파일 선택창부터 결과 파일까지의 회의록 종단 검증은 아직 남아 있어요. 새 제목 표시줄은 컴포넌트 테스트·ACL 검사·실행 창 응답을 확인했으나, 실제 마우스 드래그·더블클릭·캡션 버튼 조작은 네이티브 UI 자동 제어가 제공되지 않아 검증하지 못했어요. NSIS 실제 설치·제거, 네이티브 DPI 200%, 실제 Windows 한국어 IME 입력도 미검증이에요. gitleaks가 설치되지 않아 별도의 비밀값 검사는 수행하지 않았어요.

## 교차 드라이브 검증 재현

교차 드라이브 검증은 [수동 QA 예제](../apps/desktop/src-tauri/examples/file-output-smoke.rs)로 재현할 수 있어요. 서로 다른 드라이브의 기존 절대 폴더 두 개를 인자로 받으며 고유한 합성 작업 폴더만 만들어요. 예를 들어 현재 TEMP가 C:, 작업 폴더가 D:이면 다음 명령을 사용해요.

```powershell
.\dev.ps1 exec cargo run -p teacherdeck --example file-output-smoke -- $env:TEMP (Join-Path $PWD 'target')
```

## 후속 범위

공통 명부·사진·시간표와 사용자 동의에 따른 공유, time_alert 백업 호환, 회의록의 서식 유지 클립보드·위원회 파일 이동, 지도일 배정의 여러 달 실제 수행 이력은 후속 작업이에요. 공통 자료와 백업 호환은 [모듈 공통 기반 제안](proposals/module-foundations.md)의 별도 승인 단위에 해당해요.
