# 개발 현황

기준일: 2026-10-10. 작업 브랜치는 `codex/parallel-tools-foundation`, 이전 단계의 통합 커밋 `96b2116` 이후 변경을 관심사별 DCO 서명 커밋으로 기록했어요. 이번 변경은 아직 GitHub에 올리지 않았어요. GPT-6.1 Sol 에이전트 3개와 병렬로 기존 도구의 핵심 흐름을 복원하고 퀵캡처·이미지 도구를 개발했어요.

## 공동작업자 업데이트

원격 `main`의 `a876d1e`까지 통합했어요. 개발용 타입 업데이트와 테두리 없는 창·제목 표시줄을 기존 모듈 origin 격리·파일 전송 기능과 함께 유지해요.

[PR #5](https://github.com/TeacherDeck/teacherdeck/pull/5)의 요청은 제목 표시줄 창 조작 권한과 실제 Windows 조작 검증이었어요. 권한은 로컬 main 창에만 반영했고 컴포넌트·ACL 자동 검사를 통과했어요. 실제 네이티브 드래그·더블클릭·최소화/최대화/닫기 조작은 아래 수동 확인 항목으로 남아 있어요. 이전 조회에서 PR 댓글·리뷰·연결 이슈에 다른 사용자 요청은 없었어요.

모듈은 React/TypeScript, 네이티브 처리는 Rust/Tauri 2, 화면 컨트롤은 `@deck/ui`의 Fluent/WinUI 규격을 사용해요. 새 외부 UI 라이브러리나 Python 실행 파일을 모듈에 넣지 않았어요.

이미지 자르기는 새 기본 이미지 편집 도구예요. 원래 `simple_crop`의 PDF 사진명렬표 추출까지 이식했다고 보지는 않아요. 파일명 변경 통합 기획·PDF 마스킹·Office 변환·공통 명부·CoolReserve·네트워크 루틴 등은 후속 범위예요.

## 검증 근거

최종 `pnpm verify` 15단계 모두 통과했어요. JavaScript 318개(43개 파일), Rust core 52개·host 66개로 총 436개 테스트가 통과했어요. 생성물·타입·린트·보안 설정·의존성 라이선스 검사도 통과했어요. 선택 도구인 gitleaks는 설치돼 있지 않아 별도 비밀값 스캔은 수행하지 못했어요. 로그는 `target/parallel-verify.log`에 있어요. Vite의 500kB 청크 경고와 기존 Rust 의존성 중복 경고는 남아 있으며 검사 실패는 없어요.

7개 기본 모듈은 소스 매니페스트·카탈로그·패키지의 버전/권한 선언과 SHA256이 일치해요. 시작할 때 설치 리소스를 다시 읽으므로 이전 앱 데이터가 있어도 새 기본 모듈을 발견해요. 최종 Windows 빌드도 성공했어요. 실행 파일은 `target/release/teacherdeck.exe`(16,077,312바이트), NSIS 설치본은 `target/release/bundle/nsis/TeacherDeck_0.2.0_x64-setup.exe`(6,936,632바이트, 6.62MiB)예요. 빌드 로그는 `target/parallel-windows-build.log`에 있어요. 실행 후 앱 버전 0.2.0·7개 모듈 Ready 로그, TeacherDeck 메인 창 생성과 응답 상태를 확인했어요. 격리 환경에서 창 핸들이 0으로 조회됐으나 실제 사용자 세션의 읽기 전용 프로세스 조회로 창 생성을 확인했어요. 이 결과는 아래 네이티브 조작 검증을 대신하지 않아요.

- 스크롤: 실제 브라우저 휠 입력으로 문서와 모듈 iframe의 세로 이동을 확인했어요. 모듈 내부 스크롤 중 셸 제목 표시줄은 고정돼요. [회귀 기록](reviews/scroll-regression.md)
- 회의록: 화자 단축키·여러 줄 입력·이전 화자 기록 보존을 실제 화면에서 확인했어요. 공개용 복사의 비공개 필터, 긴 기록 타이핑 재렌더 방지, 취소·복원은 자동 테스트로 확인해요. [원본 대조](reviews/meeting-note-parity.md)
- 지도일 배정: 합성 교사 4명·하루 2명·20일에서 각 10회, 수행 기록·월별 복원, 고정 교사가 두 순번 모두 가능한 경우의 배정 오류 회귀를 확인했어요. [원본 대조](reviews/duty-planner-parity.md)
- 이미지 압축: 실제 Worker에서 2048×1024 투명 PNG를 1600×800 WebP로 압축하고 alpha 0 유지, EXIF 방향 6의 JPG를 800×1600으로 저장했어요. 손상된 파일만 실패 처리했어요.
- 사진 추출: 최종 Worker에서 합성 명렬표의 사진 3장 모두 원본 바이트와 일치했어요. 정확한 학생 1명·추측 1명·주인 미확인 1장을 구분하고 사진 없는 학생도 유지했어요.
- 이미지 자르기: 드래그한 267×118 빨간 영역이 실제 같은 크기로 저장됐어요. 90도 회전 PNG의 400×800 크기와 네 모서리 색·투명도, 좌우 반전 JPG의 흰 배경을 확인했어요. [사진 도구 검토](reviews/image-tools-parity.md)
- 퀵캡처: 실제 모듈 UI+SDK mock에서 시작·1회 캡처·영역 숨김·설정 제거/재실행 시 진행 상태 복원, 어두운 테마·150% 확대를 확인했어요. OS 화면 캡처까지의 검증은 아래와 구분해요. [통합 검토](reviews/quick-capture-integration.md)
- 파일시스템: Windows에서 새 파일 원자적 게시·중복 비덮어쓰기·권한 해제 후 파일 보존·폴더 교체 거부·소유자 핸들 격리를 실제 테스트했어요. [폴더 권한 검토](reviews/destination-grants.md)

브라우저 도구 검증은 fs/OS 호출 경계에서 mock을 사용해요. 이미지 인코딩·사진 추출 Worker와 화면 컨트롤은 실제 모듈 코드를 실행했어요. 캡처·클립보드·파일 선택창을 실제 조작했다고 주장하지 않아요.

## 승인과 보안 경계

이번 사용자 승인: [클립보드 출력](proposals/clipboard-output.md), [퀵캡처](proposals/quick-capture.md), [정확한 버전의 라이선스 예외와 로컬 시각 라이브러리](proposals/clipboard-license-followup.md). 캡처는 사용자 시작·트리거 1회당 1장이고 앱 재실행 시 자동 시작하지 않아요. 폴더 권한 해제는 권한 기록만 제거하며 기존 결과를 삭제하지 않아요.

clipboard-win 5.4.1·error-code 3.4.0의 BSL-1.0 예외만 승인대로 적용했어요. 전역 허용 목록을 넓히지 않았고 저작자·라이선스 고지는 유지해요. 새 캡처 의존성을 포함한 실제 lock의 라이선스 검사가 통과했어요.

파일 전송은 fs 1.1의 256KiB 읽기·64KiB 쓰기와 새 결과 폴더를 유지해요. 퀵캡처에만 fs 1.2의 명시적으로 기억한 append-only 목적지를 사용해요. 원본과 기존 파일을 덮어쓰지 않아요. 모듈은 경로 대신 불투명 핸들을 받아요. 결과 게시에는 hard link가 필요하여 현재 Windows NTFS 기준이며 다른 파일시스템·네트워크 공유 드라이브는 별도 확인이 필요해요.

## 남은 실제 Windows 확인

제공된 컴퓨터 제어 도구는 네이티브 앱 조작이 비활성화되어 있어 아래를 자동으로 확인하지 못했어요. 전체 테스트나 exe 생성만으로 공개 배포 준비 완료라고 보지는 않아요.

- 퀵캡처의 혼합 DPI·음수 좌표·다중 모니터 실제 픽셀, 테두리/툴바 제외, 타 앱 위 드래그·전역 키·트레이·폴더 선택부터 저장까지.
- 실제 Windows 한국어 IME의 빠른 타이핑, 한글·Word 서식 붙여넣기. arboard의 Windows HTML 형식 등록 실패 등 OS 종속 제한도 실제 앱에서 확인해야 해요.
- 제목 표시줄 마우스 조작, 네이티브 200% 배율, NSIS 실제 설치·제거.
- PDF 명렬표·공통 명부·time_alert 전체 백업 호환, 원본 XLSX 병합셀 시간표 자동 해석은 별도 후속 구현이에요.

이전 0.1.1 검증 로그(`target/ux-verify.log`, `target/ux-sec-probe.json`)는 이전 빌드의 근거이며 이번 0.2.0을 대신하지 않아요. 로그·검증 입력은 합성 자료이고 Git에 넣지 않아요.
