# 개발 현황

기준일: 2026-10-10. 작업 기준 커밋은 `b38c1c7`이에요. 공동작업자의 최신 변경을 fast-forward로 반영한 뒤 GPT-6.1 Sol 에이전트 3개와 병렬로 회의록·지도일 배정 모듈과 파일 공통 기반을 개발했어요. 현재 브랜치는 `codex/parallel-tools-foundation`이며 GitHub에는 아직 올리지 않았어요.

## 초기 두 모듈: 구현·통합 검증 완료

### 회의록

화자 등록, Alt 단축키 화자 전환과 화자 유지, Enter 연속 기록, 한국어 조합 이벤트 보호, 결정·조치·질의·안건·비공개 입력 기호를 구현했어요. 기록 되돌리기·다시 적용, 비공개를 제외한 공개용 텍스트, 비공개와 초안을 포함한 개인 보관용 텍스트, SDK storage 저장·복원을 제공해요.

브라우저에서 합성 화자 A/B를 등록하고 Alt+2로 화자를 전환한 뒤 비공개를 포함한 기록 3건을 연속 입력했어요. 공개용 텍스트에서 비공개 내용이 빠지는 것과 **지금 저장** 후 SDK mock host로 다시 열었을 때 복원되는 것을 확인했어요. 1080×640, 밝은 테마에서 입력 흐름을 확인했어요.

파일 내보내기·가져오기와 여러 회의 보관은 아직 구현하지 않았어요. 비동기 저장 요청만으로 즉시 앱 종료·LRU iframe 언로드 때 저장 완료를 보장하지 않아요. 도구를 닫기 전 저장 완료 안내를 확인해야 해요. 자세한 동작과 제한은 [회의록 안내](../modules/meeting-note/README.md)를 봐 주세요.

### 지도일 배정

Worker에서 배정을 계산하고, 누적 횟수 반영·고정일·제외일·수동 교체·재배정·SDK storage 저장·복원을 구현했어요.

브라우저에서 합성 교사 4명의 기존 횟수 `0, 0, 1, 2`를 입력해 계산한 결과 누적 횟수 `6, 6, 6, 5`를 확인했어요. 교사 A의 6일 고정과 7일 제외를 적용하고, 1일을 교사 D로 수동 교체한 뒤 재배정해도 교체 결과가 유지되는 것을 확인했어요. SDK mock host 저장 후 다시 열었을 때 상태가 복원됐어요. 600×560, 어두운 테마에서 화면을 확인했어요.

여러 달의 실제 수행 이력을 기록·누적하는 기능은 아직 구현하지 않았어요. 자세한 동작과 제한은 [지도일 배정 안내](../modules/duty-planner/README.md)를 봐 주세요.

## 파일 공통 기반: 승인 범위 구현 완료

[1차 제안](proposals/module-foundations.md)과 [두 보완안](proposals/file-transfer-followup.md)의 사용자 승인을 반영했어요. 앱 0.1.0, SDK 0.2.0, fs 1.1.0이에요. 파일 도구가 공통으로 사용할 API이며, 개별 이미지·PDF·Office 변환 도구까지 완성한 것은 아니에요.

- 선택한 파일을 최대 256KiB씩 읽고, 결과는 선택 폴더 아래 새 폴더에만 저장해요.
- 쓰기는 기존 인증 브리지로 64KiB씩 순차 전송해요. SDK `readChunks`·`writeBlob`이 전송과 정리를 맡아요.
- 원본과 기존 결과를 덮어쓰지 않아요. 중복 이름은 연번을 붙이고, 게시가 완료된 파일은 취소해도 보존해요.
- 파일·폴더 핸들과 읽기·쓰기·결과 작업 권한을 구분하고, 모듈 소유자·언로드 세대·미사용 만료를 검사해요.
- 각 모듈은 독립 origin을 사용해요. 셸 브리지는 iframe과 정확한 origin을 함께 확인해요.
- 임시 작업은 복구 기록과 내용을 확인해 정리해요. 마지막 기록 이후 바뀐 파일, 손상된 기록, 사용자가 수정·추가한 파일은 보존해요.

파일당 512MiB, 결과 작업당 2,000개·2GiB가 현재 한도예요. 출력 위치는 hard link를 지원해야 해요. 일반적인 로컬 NTFS에서 검증했으며 다른 파일시스템·공유 드라이브는 별도 확인이 필요해요. 정상 전송의 메모리를 청크 단위로 제한하지만 악성 요청의 전역 메모리 절대 상한이나 전원 장애까지의 영속성을 보장하지는 않아요. 자세한 계약은 [SDK 안내](../packages/sdk/README.md)와 [ADR-0014](adr/0014-bounded-file-transfers.md)에 있어요.

검증 로그는 `target/file-foundation-verify.log`, 격리 보고서는 `target/file-foundation-sec-probe.json`에 있어요. 자세한 격리 결과는 [SEC-004 기록](security/sec-004.md)을 참고해요. 로그와 빌드 산출물은 Git에 포함하지 않아요. Windows 링크 생성·파일 잠금은 승인된 샌드박스 밖 실행으로 실제 OS 동작을 확인했어요. 새 런타임 의존성이나 검사 억제는 추가하지 않았어요.

브라우저의 회의록·배정기 조작 검증은 SDK mock host에서 수행했어요. 실제 WebView2 격리 검증과 Rust의 파일 처리 검증을 별도로 수행했으며, 사용자 도구에서 파일 선택부터 변환까지 끝내는 종단 검증은 후속 모듈 연결 때 해야 해요. NSIS 실제 설치·제거, 네이티브 DPI 200%, 실제 Windows 한국어 IME 입력은 아직 검증하지 않았어요. gitleaks가 설치되지 않아 별도의 비밀값 검사는 수행하지 않았어요.

## 교차 드라이브 검증 재현

교차 드라이브 검증은 [수동 QA 예제](../apps/desktop/src-tauri/examples/file-output-smoke.rs)로 재현할 수 있어요. 서로 다른 드라이브의 기존 절대 폴더 두 개를 인자로 받으며 고유한 합성 작업 폴더만 만들어요. 예를 들어 현재 TEMP가 C:, 작업 폴더가 D:이면 다음 명령을 사용해요.

```powershell
.\dev.ps1 exec cargo run -p teacherdeck --example file-output-smoke -- $env:TEMP (Join-Path $PWD 'target')
```

## 후속 범위

공통 명부·사진·시간표와 사용자 동의에 따른 공유, time_alert 백업 호환, 회의록 파일 입출력·여러 회의 관리, 지도일 배정의 여러 달 실제 수행 이력은 후속 작업이에요. 공통 자료와 백업 호환은 [모듈 공통 기반 제안](proposals/module-foundations.md)의 별도 승인 단위에 해당해요.
