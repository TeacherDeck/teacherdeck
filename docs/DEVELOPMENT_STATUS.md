# 개발 현황

기준일: 2026-10-10. 작업 브랜치는 `codex/parallel-tools-foundation`이며 아직 GitHub에 올리지 않았어요. 이번 작업은 GPT-6.1 Sol 에이전트 3개와 함께 기존 도구의 UX를 복원하는 데 집중했어요.

## 0.2.0에서 놓친 문제

원본 프로그램의 배치와 조작 흐름을 보존하지 않고 기능 목록을 중심으로 재구성해 사용성이 떨어졌어요. 퀵캡처는 불필요하게 도구 창을 분리했고, Tauri 이벤트의 기본 Any target 때문에 캡처 영역과 도구 창의 상태가 섞일 수 있었어요. 사용자 스크린샷에서 두 창과 흰 캡처 영역이 실제로 확인됐어요. 이전 SDK mock과 빌드 검증은 실제 Windows 투명 합성·이벤트 전달을 검증하지 못했어요.

## 이번 UX 복원

| 도구·기반    | 버전  | 반영한 동작                                                                                               |
| ------------ | ----- | --------------------------------------------------------------------------------------------------------- |
| 호스트·셸    | 0.2.1 | 하나의 투명 캡처 창, 같은 창 상단의 작은 도구줄, 현재 창에 한정한 이벤트 구독, 실제 캡처 내부 좌표 변환   |
| 퀵캡처       | 0.1.1 | 원본처럼 저장/캡처 설정 두 묶음, 실제 키 조합 입력, 색 선택창, 유효한 설정 자동 적용, 충돌·폴더 교체 복구 |
| 회의록       | 0.5.0 | 상단 도구줄·중앙 기록/오른쪽 화자·하단 전체폭 입력, 화자색·번호키·짧은 기록 행, 입력 초점 유지            |
| 지도일배정기 | 0.3.1 | 휴일/일요일 빨강·토요일 파랑, 제외/직접고정/실제수행/선택 표시, 날짜별 담당자 즉시 교체, 달력 밀도 개선   |
| 공통 UI      | 0.6.0 | ColorPicker, 제목·본문의 기본 여백 제거, 좁은 화면의 선택/숫자 입력 폭 보정                               |

모듈은 React/TypeScript, 네이티브 처리는 Rust/Tauri 2를 유지해요. 공통 컨트롤은 `@deck/ui`와 Fluent 토큰을 사용하며 기존 디자인 시스템의 색·간격·글꼴을 따릅니다. 이번 수정에서 새 런타임 의존성이나 캡, ACL 확대는 없어요.

타이머 0.2.1과 이미지 압축·명렬표 사진 추출·이미지 자르기 0.1.1에는 공통 UI 수정을 함께 번들했어요. 개별 처리 기능은 이번에 바꾸지 않았어요. 기존 소스의 모든 기능을 이식했다고 주장하지 않아요. 파일명 통합 기획·PDF 마스킹·Office 변환·공통 명부·CoolReserve·네트워크 루틴은 후속 범위예요. 원본 PDF 명렬표·XLSX 병합셀 시간표 자동 해석 등 남은 차이는 각 대조 문서에 있어요.

## 검증 근거

최종 `pnpm verify` 15단계가 모두 통과했어요. JavaScript 341개(47개 파일), Rust core 55개·host 66개, 총 462개 테스트가 통과했어요. 로그는 `target/ux-restoration-final-verify.log`에 있어요. 생성물·타입·린트·보안 설정·의존성 라이선스 검사도 통과했어요. 별도 gitleaks는 설치되지 않아 실행하지 않았어요. 이전 `target/parallel-verify.log`·0.2.0 설치본은 이번 수정의 최종 검증을 대신하지 않아요.

- 퀵캡처: 합성 문서 위에 실제 CaptureOverlay를 투명 iframe으로 겹쳐 뒤의 글·표가 보이는 것을 확인했어요. 단축키 입력, 색 변경, 시작/장수 갱신, 설정 닫기/다시 열기, 어두운 테마·150% 확대를 실제 UI+SDK mock으로 확인했어요. 확대에서 선택 상자가 겹치는 문제와 색 입력 이벤트 문제를 발견해 수정했어요. [통합 검토](reviews/quick-capture-integration.md)
- 회의록: 합성 참석자 3명에서 Alt+2→입력→Enter 뒤 화자·내용·입력 초점을 확인했어요. 1280×720 모듈 화면의 글자/행높이 150%에서 입력창이 화면 안에 유지되고 가로 넘침이 없었어요. [원본 대조](reviews/meeting-note-parity.md)
- 지도일 배정: 기본 화면에서 한 달 전체와 휴일·주말 색을 확인했어요. 합성 교사4명·하루2명은 각10회, 담당자 즉시 교체와 직접 배정 표시, 실제 수행 기록 표시를 확인했어요. [원본 대조](reviews/duty-planner-parity.md)
- 네이티브 이벤트: 실제 Tauri JS API의 Window target 인자를 검사하고 로컬 Tauri 구현에서 emit_to(label)와 같은 Window label의 연결을 확인했어요. 물리 내부/외부 좌표는 음수 원점·여러 DPI·테두리·이동·크기·잘못된 값으로 검사해요. [호스트 검토](reviews/native-capture.md)

Windows 릴리스 빌드도 성공했어요. 실행 파일은 `target/release/teacherdeck.exe`(16,044,544바이트), 설치본은 `target/release/bundle/nsis/TeacherDeck_0.2.1_x64-setup.exe`(6,940,661바이트, 6.62MiB)예요. 빌드 로그는 `target/ux-restoration-windows-build.log`에 있어요. 기본 모듈7개의 버전·패키지 체크섬을 대조했고, 수정본을 실행해 버전0.2.1 시작 로그·7개 모듈Ready·메인 창 생성과 응답 상태를 확인했어요. Vite 청크 크기 및 기존 ts-rs serde 경고는 남아 있어요.

브라우저 확인에서 파일 선택·OS 캡처·전역키는 모의했어요. 실제 Windows 화면을 캡처하고 파일을 저장했다고 주장하지 않아요. 앞선 이미지 Worker 인코딩/추출과 파일시스템 권한 테스트의 근거는 [사진 도구](reviews/image-tools-parity.md), [폴더 권한](reviews/destination-grants.md)에 별도로 있어요.

## 공동작업자와 승인 상태

이전 원격 확인에서 `main`의 `a876d1e`까지 통합했어요. 이번 UX 수정에서는 원격을 다시 조회하지 않았어요. [PR #5](https://github.com/TeacherDeck/teacherdeck/pull/5)의 제목 표시줄 권한 요청은 앞선 변경에서 적용했으며 실제 Windows 창 조작 검증은 남아 있어요.

[클립보드 출력](proposals/clipboard-output.md), [퀵캡처](proposals/quick-capture.md), [한정 라이선스 예외·로컬 시각](proposals/clipboard-license-followup.md)은 이미 승인받은 범위예요. 새 캡처 파일만 저장하고 기존 결과를 덮어쓰거나 삭제하지 않아요. 폴더 권한 해제는 권한 기록만 제거해요. 모듈은 경로 대신 핸들만 받으며 사용자 파일과 개인정보는 외부로 보내지 않아요.

## 아직 확인하지 못한 것

현재 컴퓨터 제어 도구는 네이티브 앱 조작이 비활성화되어 있어 다음 항목은 수동 검증이 필요해요. exe 생성과 프로세스 시작만으로 이 항목을 통과했다고 보지 않아요.

- 실제 Windows 투명 캡처 창, 타 앱 위에서 이동/크기 변경·더블클릭·전역키·트레이·폴더 선택부터 저장까지.
- 혼합 DPI·음수 좌표·다중 모니터의 실제 캡처 픽셀과 테두리/도구줄 제외. 화면 맨 위의 영역에서는 원본처럼 도구줄이 화면 밖으로 나갈 수 있어요.
- 실제 Windows 한국어 IME 빠른 입력, 한글/Word 서식 붙여넣기, 제목 표시줄 조작, NSIS 설치·제거.
- 원본 XLSX 병합셀 시간표·PDF 명렬표·공통 명부·time_alert 전체 백업 호환은 후속 구현이에요.
