# 문서 형식 변환

설치된 한글·Excel·PowerPoint·Word로 HWP→HWPX, XLS→XLSX, PPT→PPTX, DOC→DOCX를 실제 저장한다. 같은 계열의 현대 형식도 선택할 수 있다. 확장자만 바꾸지 않는다. 원본은 유지하고 선택한 부모 폴더 안의 새 결과 폴더에 저장한다.

문서를 선택하면 출력 형식과 충돌을 피한 이름을 먼저 보여준다. 매크로가 발견되면 XLSM/PPTM/DOCM 보존 형식을 선택해 실패한 문서만 다시 변환할 수 있다. 이미 변환한 결과는 유지한다. Excel 4.0 매크로 시트는 직접 확인해야 한다. 중지 버튼은 호스트의 현재 작업자를 취소하며 앞서 저장한 결과를 남긴다.

문서 한 개씩, 앱 전체에서 변환 한 개만 실행한다. 전용 작업자의 120초 제한과 소유 프로세스 Job Object를 사용한다. 기존 사용자 Office 프로세스와 분리되었다는 증거가 없으면 문서를 열거나 닫지 않고 실패한다. 문서 매크로를 억제하고 읽기 전용으로 열며 새 형식 저장·재열기·ZIP 구성·원본 해시를 확인한다. 한글은 아래의 제한된 경로 확인 모듈로 작업용 파일만 연결한다. 승인창은 자동 클릭하지 않는다.

`office` 1.0과 기존 `fs` 1.1, 공개 SDK를 사용한다. 모듈 자체에 새 런타임 의존성은 없다. 설치 등록 조회는 프로그램의 실행/모든 형식 성공을 보증하지 않는다. 구조·재열기 검증에 성공한 결과도 표·그림·수식과 서식을 사용자가 확인한다.

순수 형식 계획과 SDK mock의 매크로 재시도·취소/저장 유지 흐름을 검사한다. 실제 합성 변환은 개발 전용 `office_synthetic` example이 생산 작업자를 재사용해 확인한다. 생성 위치는 레포의 `target/next-tools/office-qa/<무작위 식별자>`로 제한하며 원본 사용자 문서를 입력하지 않는다.

Excel은 프로그램 활성화 전에 CFB/BIFF5·8 및 OOXML 사전 검사를 수행한다. CFB/BIFF의 매크로 시트·이름, 암호화·불완전·지원하지 않는 구조는 거부한다. HTML/XML을 XLS로 저장한 파일과 64MiB를 넘는 BIFF Workbook 스트림 등 검사 범위 밖의 문서는 Office에서 직접 확인해야 한다. OOXML은 승인된 XML 파서로 패키지 루트의 실제 workbook 관계·namespace·정의 이름을 검사한다. 자동 실행 정의와 XLM 함수 표식은 거부하지만 정상 `AUTO_OPEN` 시트 이름은 허용한다. DTD·외부 엔티티·외부 main target·손상 구조는 거부한다. 검사 대상과 한도는 [구현 기록](../../docs/proposals/excel-xml-preflight.md)에 있으며 Office의 모든 매크로·취약점 차단을 보증하지 않는다.

한글 0.2.0 경로는 공식 `FilePathCheckDLL` ABI를 독립 구현한 x86 Rust DLL을 사용한다. DLL은 앱에 내장하며 각 작업의 입력 사본·신규 출력 파일 두 개만 정확히 허용한다. 한글 시작 전에 난수 이름의 HKCU 등록값을 준비하고, 새 한글 프로세스의 소유권을 확인한 뒤 인증된 로컬 pipe를 연결한다. 기존 등록값·전역 보안 설정·`Uses`·HKLM은 바꾸지 않는다. 종료·취소·시간 초과 시 자기 등록값을 정리하며 pipe가 없으면 접근을 거부한다. 공식 allow-all 예제 DLL을 사용하거나 동봉하지 않는다. 설계와 안전성 경계는 [ADR-0027](../../docs/adr/0027-scoped-hancom-path-check.md)에 있다.

한글 접근 연결이 거부되면 숨긴 작업 창에서 저장을 진행하지 않고 즉시 종료하여 한글에서 직접 변환하도록 안내한다. 한글 120초 응답 제한도 정리된 작업과 직접 변환 안내를 구분한다. 다른 Office의 문서 접근 승인창은 직접 확인한다. 앞서 저장한 결과는 유지한다.

이번 PC의 초기 합성 검증은 첫 HWP SaveAs의 접근 승인창에서 120초 제한으로 종료됐다. 제한 DLL 추가 뒤에는 `RegisterModule(FALSE)`로 합성 저장 전에 종료된다. 실제 Hwp는 x86이며 단독 DLL 로드·export 검사는 성공했지만, 한글의 거부 단계는 아직 확인하지 못했다. HWP→HWPX 저장·재열기·본문/서식 보존 성공은 미검증이다. 이 제한을 설치 확인이나 경계 회귀 통과로 대신하지 않는다. 증거와 공식 답변은 [후속 진단](../../docs/reviews/hancom-save-timeout-followup-2026-10-11.md)에 남긴다.
