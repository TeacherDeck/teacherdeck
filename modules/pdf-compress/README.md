# PDF 용량 줄이기

PDF를 선택하거나 끌어 놓으면 바로 압축한다. 저장 폴더는 처음 한 번 고르고, 이후 추가한 파일에도 재사용한다. 한 작업 목록에 1,000개까지 추가하며 순서대로 처리한다. 실패·미처리만 다시 실행할 수 있고 이전 결과와 저장 위치를 유지한다.

기본은 **문서 구조 유지**다. PDF의 글자·벡터·양식·링크·첨부·메타데이터와 페이지 내용 스트림을 보존하고, 지원하는 RGB JPEG 사진을 같은 화소 크기·품질82로 재압축하며 객체 저장 구조를 최적화한다. 특수 색상·투명도·디코드 지시나 EXIF·ICC·Adobe 메타데이터가 있는 이미지는 회전·색 변환을 피하기 위해 재인코딩하지 않는다. 서명 문서는 바이트 그대로 보존한다. 결과가 더 작을 때만 압축본을 저장하고, 같거나 크면 원본 바이트를 복사하여 `원본 복사`로 표시한다. 줄일 수 있는 정도는 문서의 이미지 형식과 기존 압축 상태에 따라 다르다.

고급 설정의 **이미지 PDF로 변환**은 모든 페이지를 JPEG 이미지로 바꾸는 별도 방식이다. 120 DPI·품질82가 기본이며 72~300 DPI·품질30~100을 고를 수 있다. 이 방식은 검색·복사·벡터·양식·링크·서명·첨부가 사라지므로 전환 사실을 확인해야 실행된다. 기본 방식과 구분하여 사용한다. 어느 방식이든 원본 파일을 바꾸지 않는다.

입력 한 개당 32MiB·100쪽까지, 이미지와 캔버스는 2,400만 화소까지, 출력은 128MiB까지 처리한다. 이미지 문서 방식은 결과를 다시 읽어 페이지 수와 크기를 비교한다. 기본 방식은 이미지 재인코딩과 PDF 저장 모두 Worker에서 실행한다. 취소·90초 시간 제한은 Worker를 종료하며, 이미 저장한 결과는 유지한다.

PDF.js 6.4.299와 pdf-lib 1.17.1, 로컬 Worker·자산을 사용한다. 동봉 LiberationSans 라이선스 예외 검토 전 배포는 보류한다. 설정만 storage 캡에 보관하며 파일 내용은 보관하지 않는다.

검증: 일반 RGB JPEG를 넣은 합성4쪽 PDF를 실제 Worker에서 6,526,735→886,246바이트로 압축하고 PDF.js로 재열어 글자4쪽·회전별 크기·링크1개·첨부1개·제목·양식 값을 확인했다. ICC가 있는 별도 합성 입력은 이미지 바이트를 유지하고 객체 구조만 줄여 6,527,209→6,525,503바이트가 됐다. 단위/SDK/UI 검증은 내용 스트림 보존, 특수 이미지 유지, 직접·간접 서명 보존, 배치 실패 후 계속 처리, 원본 바이트 보존, 취소, 선택·드롭 자동 실행과 폴더 선택1회를 포함한다. OS 파일 선택·저장은 검수에서 모의했다.
