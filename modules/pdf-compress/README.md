# PDF 용량 줄이기

파일을 끌어 놓으면 입력한 파일명·목록과 추가 상태를 바로 표시해요. 저장 폴더를 지정하지 않으면 각 원본 파일과 같은 폴더에 새 결과 파일을 저장해요. **다른 저장 폴더 선택**으로 지정하면 선택한 폴더에 직접 저장해요. 결과 하위 폴더를 자동으로 만들지 않으며 기존 파일을 덮어쓰지 않아요. 필요 앱 버전은 **0.8.0** (`fs ^1.4.0`)이에요.

PDF를 선택하거나 끌어 놓으면 바로 압축한다. 별도 지정이 없으면 각 원본의 폴더에 저장하고, 지정한 저장 폴더는 다음 파일에도 재사용한다. 한 작업 목록에 1,000개까지 추가하며 순서대로 처리한다. 실패·미처리만 다시 실행할 수 있고 이전 결과와 저장 위치를 유지한다. 폴더를 고르거나 파일을 처리하는 중의 추가 입력은 받지 않으며 끝난 뒤 다시 추가하도록 안내한다. 다른 저장 폴더 선택을 취소하면 기존 폴더와 미처리 목록은 그대로 유지한다.

기본은 **문서 구조 유지**다. PDF의 글자·벡터·양식·링크·첨부·메타데이터와 페이지 내용 스트림을 보존하고, 지원하는 RGB JPEG 사진을 같은 화소 크기·품질82로 재압축하며 객체 저장 구조를 최적화한다. 특수 색상·투명도·디코드 지시나 EXIF·ICC·Adobe 메타데이터가 있는 이미지는 회전·색 변환을 피하기 위해 재인코딩하지 않는다. 서명 문서는 바이트 그대로 보존한다. 결과가 더 작을 때만 압축본을 저장하고, 같거나 크면 원본 바이트를 복사하여 `원본 복사`로 표시한다. 줄일 수 있는 정도는 문서의 이미지 형식과 기존 압축 상태에 따라 다르다.

기본 방식은 저장 전에 각 스트림의 선언 길이(`/Length`, 간접 참조 포함)와 파싱된 바이트 수를 비교한다. 길이를 확인할 수 없거나 두 값이 다르면 원본 바이트를 복사한다. 본문 문자열에 `endstream`이 들어 있어 파서가 스트림을 짧게 읽은 문서도 이 방식으로 보존한다.

고급 설정의 **이미지 PDF로 변환**은 모든 페이지를 JPEG 이미지로 바꾸는 별도 방식이다. 120 DPI·품질82가 기본이며 72~300 DPI·품질30~100을 고를 수 있다. 이 방식은 검색·복사·벡터·양식·링크·서명·첨부가 사라지므로 전환 사실을 확인해야 실행된다. 기본 방식과 구분하여 사용한다. 어느 방식이든 원본 파일을 바꾸지 않는다.

입력 한 개당 32MiB·100쪽까지, 이미지와 캔버스는 2,400만 화소까지, 출력은 128MiB까지 처리한다. 이미지 문서 방식은 결과를 다시 읽어 페이지 수와 크기를 비교하며, 원본 이미지 크기 사전 검사도 Worker에서 실행한다. 기본 방식의 PDF 파싱·이미지 재인코딩·저장과 이미지 문서 방식의 PDF 출력도 Worker에서 실행한다. 각 사전 검사·압축·출력 Worker에는 90초 시간 제한이 있으며, 취소하거나 제한 시간이 지나면 해당 Worker를 종료한다. 이미 저장한 결과는 유지한다.

PDF.js 6.4.299와 pdf-lib 1.17.1, 로컬 Worker·자산을 사용한다. PDF 렌더링용 Liberation Sans 네 TTF는 [ADR-0018](../../docs/adr/0018-pdf-resource-notices.md)의 승인된 해시 고정 예외 범위로 동봉한다. 설정만 storage 캡에 보관하며 파일 내용은 보관하지 않는다. 저장된 설정을 읽는 동안 사용자가 바꾼 압축 방식·DPI·품질은 늦게 도착한 저장값으로 덮어쓰지 않는다.

검증: 일반 RGB JPEG를 넣은 합성4쪽 PDF를 실제 Worker에서 3,049,878→640,682바이트로 압축했다. PDF.js 독립 검사로 검색 텍스트4쪽·회전별 페이지 크기·양식 값·Link1개와 Widget1개·첨부 `synthetic.txt`의 20바이트 내용·제목이 전후 유지됨을 확인했다. 간접 참조 `/Length`와 본문 문자열의 `endstream`이 함께 있는 사례는 5,695→5,695바이트로 원본과 완전히 동일하게 유지하며 끝 문장도 보존했다.

24MiB 문자열을 담은 25,138바이트 PDF의 사전 검사는 실제 Worker에서 2,967ms가 걸렸다. 그동안 10ms 간격으로 예약한 화면 응답 확인 콜백은 198회 실행됐고 최대 간격은 17ms였다. 50ms 후 취소를 예약한 별도 실행은 54ms에 `CANCELLED`로 끝났다. 저장 품질30의 복원을 지연시킨 동안 사용자가 품질100을 고르면 화면·저장 설정·실행 모두100을 유지했다. 수치들은 검증 환경에서 얻은 예시다. OS 파일 선택·저장은 검수에서 모의했다.

단위/SDK/UI 검증은 내용 스트림 보존, 특수 이미지 유지, 직접·간접 서명 보존, 배치 실패 후 계속 처리, 원본 바이트 보존, 취소, 선택·드롭 자동 실행, 기본 저장의 대화상자 없음, 원본별 폴더와 지정 폴더 직접 저장을 포함한다.
