# 영상 다운로드

1. 공개 YouTube 영상 한 개의 `https` 주소를 넣어요. watch·youtu.be·shorts·embed·live의 단일 영상 주소를 받아요.
2. **저장 폴더 선택**을 눌러요. 폴더 선택을 취소하면 기존 선택을 유지해요.
3. **다운로드**를 눌러요. 실행 환경 준비·다운로드/합치기·파일 확인 단계를 보여 줘요. 처음에는 고정 Deno·FFmpeg 실행 환경을 인터넷에서 준비할 수 있어요.
4. **새 MP4 파일을 저장했어요**가 나오면 **저장 위치 열기**로 결과 위치를 열어요.

내 영상이나 내려받을 권한이 있는 공개 영상에 사용해 주세요. 로그인·쿠키·재생목록 전체·음성만 저장은 지원하지 않아요. 재생목록 정보가 붙어 있어도 지정한 영상 하나만 선택해요. 합본 MP4를 받거나 분리된 MP4 영상과 M4A 음성을 PC 안에서 FFmpeg로 재인코딩 없이 합쳐요. 특정 화질 선택을 보장하지 않아요. 공개 영상도 제공자의 제한이나 네트워크 환경 때문에 실패할 수 있어요.

## 진행·취소·재시도

앱 전체 동시 한 작업, 준비를 포함해 30분, 영상·음성 입력 합계와 최종 MP4 각각 최대 512MiB예요. 전체 크기가 아직 없으면 막대는 준비/진행 상태만 보여 줘요. 다운로드 바이트가 모두 도착해도 로컬 합치기와 최종 영상·음성 트랙 검사를 마쳐야 완료예요. 완료 전에 **취소**할 수 있으며 늦게 도착한 시작 응답에도 취소 요청을 전달해요. 취소 완료는 호스트의 상태로 확인하고 이미 게시한 파일을 삭제하지 않아요.

진행 상태 조회가 실패하면 작업이 계속될 수 있어요. 새 작업을 중복 시작하지 않고 **진행 다시 확인**이나 **취소**를 제공해요. 시작/작업 실패 후 주소나 폴더를 고쳐 다시 다운로드할 수 있어요. 다음 작업이 실패해도 이번 모듈 세션에서 앞서 완료한 마지막 파일의 **저장 위치 열기**를 유지해요.

다른 도구로 이동해도 숨겨진 모듈이 유지되는 동안 진행해요. 유지 슬롯 초과로 언로드되거나 앱이 종료되면 호스트가 작업을 취소해요. 모듈도 언마운트 시 취소를 요청해요. 폴더 핸들·작업·결과 위치 버튼은 현재 세션에서만 유효하며 앱 재시작 후 이어받기를 지원하지 않아요.

## 실행 경계

기존 `fs`와 승인된 `media-download` 1.0 캡을 사용해요. URL은 화면에서 피드백을 위해 검사하고 호스트가 독립적으로 다시 검사해요. 모듈은 외부 HTTP·프로세스·사용자 경로를 직접 사용하지 않아요. 선택한 폴더 안에 새 결과 하위 폴더를 만들고 원본 파일을 덮어쓰거나 삭제하지 않아요. 이름·경로·URL·도움 프로세스 로그를 콘솔에 기록하지 않아요.

호스트가 고정 패키지·실행 환경의 해시와 권한을 확인하고 bounded 작업으로 실행해요. 허용된 네트워크는 실행 환경 첫 준비와 지정한 공개 영상 다운로드예요. 상세 경계는 [ADR-0028](../../docs/adr/0028-bounded-media-download.md)과 [capabilities.md](../../docs/spec/capabilities.md)를 따라요.

로그인 요구·인증서·연결·지원 형식·크기 제한에는 호스트가 만든 고정 안내와 조치 방법을 보여 줘요. 오류 코드와 문구가 함께 허용 목록에 정확히 일치할 때만 표시하며 도움 프로세스나 제공자의 원문은 일반 안내로 바꿔요.

## 검증

합성 URL의 정규화·거부, 알 수 없는 크기의 진행 표시, 입력 오류의 호출 차단, 폴더 선택 취소, 정상 결과 위치 열기, 다음 조회 실패 후 기존 완료 파일 유지, 조회 재시도, 시작 응답 전 취소, 언로드 이후 늦은 응답 취소를 SDK mock host로 검사해요. 이 검사는 실제 YouTube 네트워크·Deno 준비·Windows 결과 파일 게시 성공의 근거가 아니며 해당 실기는 호스트 담당 검증과 구분해요.
