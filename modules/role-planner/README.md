# 역할·당번 나누기

첫 화면에서 명단·역할별 필요인원을 붙여넣고 적용한다. 전체 학생을 모두 배정할 필요가 없다. 고정·제외·정원 조건을 먼저 지키고, 남은 자리에 총 실제 수행횟수가 가장 적은 대상을 선정한다. 역할별횟수·업무 가중치는 첫 버전에서 균등 기준으로 사용하지 않는다.

고정과 제외가 충돌하거나 고정 인원이 역할 정원을 넘으면 조건을 자동으로 풀지 않고 안내한다. 직접 담당자를 바꾸거나 이미 배정된 학생과 교환할 때도 모든 고정·제외·정원을 검사한다. 편성·다시 배정·미리보기는 횟수를 바꾸지 않고 개별 수행 완료만1회 기록한다. 완료 기록이 있는 배정은 수정하지 못하도록 보호하며 완료를 되돌리거나 새 배정으로 이어간다. 새 배정은 총횟수와 교사 조건을 유지한다.

공통 명부 없이 임시 명단으로 사용할 수 있다. 공통 자료 연결은 별도 승인과 기반 구현 후 추가한다. 명단 수정 후 이전 수행 기록의 당시 이름·번호·역할은 그대로 유지한다. 변경은 storage에 저장한 뒤 화면에 적용하고 실패 시 이전 기록을 유지한다. 손상된 저장값은 빈 작업으로 자동 대체하지 않는다. 확인을 거친 정상 파일 가져오기·새 작업으로 복구할 수 있고 복구 저장 실패 시 잠금을 유지한다.

명단1,000명·역할100개·필요인원 합계1,000명·완료기록10,000건을 지원한다. 기록 파일은 이 도구의 JSON 형식이며 원본을 덮어쓰지 않고 새 결과 폴더에 저장한다. 파일 가져오기와 새 작업은 변경 전 확인한다. 학생 보기는 역할별 이름·번호·배정 이름만 보여주며 화면 복제에 사용한다. 별도 확장 창·학생 기기 접속은 제공하지 않는다.

순수 로직·SDK 저장·실제 화면 흐름 테스트를 갖추고, 통합 담당자가 실제 파일 입출력·키보드·DPI·테마·`pnpm verify`를 확인한다.

저장 형식은 문자열 사전·정수 튜플로 수행 기록을 보존하고 세대별 청크로 저장한다. 청크당240KiB 미만·한 작업 압축 자료2MiB·모듈 전체5MiB를 검사하고 마지막 참조 전환이 성공한 뒤 화면에 적용한다. 예전 단일 JSON도 읽으며, 한도를 넘는 기록을 조용히 버리지 않는다.

역할 배정은 모듈 내부 Worker에서 실행한다. 처리 중 배정 취소와 30초 중단을 제공하며 취소·실패는 저장된 이전 배정을 유지한다. 총횟수 맵과 후보 한 번 정렬로 배정 비용을 줄인다. 100명이 넘으면 학생 조건과 배정 결과를50명씩 표시하고 번호·이름으로 찾는다. 대명단의 담당자 교환은 결과 위의 바꿀 담당자·새 담당자 두 선택으로 처리해 후보 목록을 행마다 만들지 않는다. 작은 명단은 기존 행별 교환을 유지한다.
