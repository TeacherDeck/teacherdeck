# 파일명 정리

파일을 보며 새 이름을 만들고 새 결과 폴더에 복사하는 도구예요. 직접 패턴, 엑셀 연결, 문서 정보의 세 방식이 같은 목록과 미리보기를 사용해요. 방식을 바꿔도 직접 고친 이름과 문서 정보는 유지해요.

## 사용 순서

1. 파일을 끌어 넣거나 파일·폴더를 추가해요. 폴더는 최상위만 읽으며 하위 폴더는 직접 켜요. 이름·크기·수정일 정렬, 선택 행 이동·제거, 검색과 50행씩 보기가 있어요. 목록 제거는 파일 삭제가 아니에요.
2. `{원본}`, `{연번}`, `{yyyymmdd}`, 엑셀 열, 문서 연도·월·분류·학년을 패턴에 넣어요. 연번 시작과 자릿수, 기준 날짜를 고를 수 있고 패턴은 20개까지 로컬 저장해요. 확장자의 대소문자는 원본 그대로 붙여요. 직접 이름을 고칠 때는 확장자까지 입력해요.
3. 엑셀은 XLSX의 시트·헤더 행·재료 열과 연결 키를 골라요. 학번·번호·기존 이름은 정확히 일치할 때만 연결해요. 목록 순서 연결은 별도로 선택해요. 학번의 선행 0과 공백은 유지하며 번호 숫자 정규화는 직접 켠 경우만 해요. 빈 키·중복·같은 행에 여러 파일이 연결되면 자동 확정하지 않아요. 미연결 파일은 엑셀 행 또는 최종 이름을 직접 지정해요. 연결 키와 행, 미사용 행을 확인할 수 있어요.
4. 문서 정보는 PDF의 처음 3쪽, HWP5·HWPX의 처음 4개 본문 구역, UTF-8 TXT·CSV에서 상단 글을 읽어요. 연도·월·분류·학년은 후보이며 직접 확인해야 해요. 스캔 PDF는 OCR을 하지 않아요. 분석에 실패하면 파일명에서 얻은 후보임을 표시해요. 빈 재료와 잘못된 변수는 자동으로 삭제하지 않아요.
5. 최종 이름과 충돌을 확인한 뒤 **새 폴더에 복사**해요. 완료·실패·미처리를 구분하며 실패·미처리만 다시 복사할 수 있어요. 여러 번 저장한 결과 폴더도 각각 열 수 있어요.

## 원본 변경과 보호된 되돌리기

원본 이름 변경은 직접 선택해야 해요. 원본 폴더의 충돌 검사와 화면 요약 확인 뒤 호스트 확인창에서 한 번 더 확인해요. 같은 부모 폴더 안에서만 바꾸며 기존 파일을 덮어쓰지 않아요. 이름 교환과 대소문자 변경은 연결된 묶음으로 처리해요. 취소는 다음 묶음을 시작하지 않으며 완료한 변경은 이력에 남아요. 완료한 변경의 실패 항목만 새 미리보기로 옮길 수 있어요.

앱을 다시 열어도 원본 변경 이력을 조회할 수 있어요. 되돌리기는 실제 파일 ID·전체 SHA-256·크기·수정 시각과 원래 이름의 점유 상태를 확인해요. 수정·교체·이동된 결과나 충돌한 결과는 보호하며 자동 복구하지 않아요. 정상 이력의 중단된 묶음은 원래 이름으로 복구할 수 있는지 검사해요. 손상된 이력은 보존하고 변경 기능을 차단해요. 복사 결과를 지우는 되돌리기는 제공하지 않아요.

## 한도와 로컬 처리

- 한 작업 2,000파일, 파일마다 512MiB, 변경 계획 전체 2GiB까지예요. 폴더 열거는 깊이 32, 디렉터리 4,096개, 한 폴더 항목 8,192개까지이며 초과하면 부분 성공으로 표시하지 않아요.
- 분석 입력은 32MiB, 압축 해제 전체 64MiB, XML 하나 4MiB, XLSX 100시트·100,000셀·10,000자료 행·128재료 열까지예요. 암호·배포용 HWP, 구형 XLS, 외부 연결은 읽지 않아요. 이름은 Windows UTF-16 240단위 이하여야 해요.
- 계획·목록은 5분 후 만료해요. 이력은 도구별 20건, 이력 하나 16MiB·호스트 전체 64MiB예요. 진행·차단 이력은 자동 삭제하지 않으며 공간이 부족하면 새 변경을 거부해요.
- 모든 처리는 PC 안에서 이루어져요. 모듈은 경로 대신 핸들을 사용해요. 작업 이력의 경로·이름·검증값은 호스트 전용 로컬 데이터에만 있고 파일 본문은 저장하지 않아요. 일반 로그와 오류에는 파일명·경로·엑셀 값을 넣지 않아요.

필요 앱 버전은 **0.3.0**이에요(`fs ^1.3`, `file-ops ^1.0`, `storage ^1.0`). 계약과 Windows 보호 경계는 [파일 작업 규격](../../docs/spec/file-operations.md), [ADR-0019](../../docs/adr/0019-protected-file-operations.md)을 따라요.

## 라이브러리와 동봉 자산

XLSX/HWPX/HWP 압축 처리는 `fflate 0.8.3`(MIT), PDF 읽기는 `pdfjs-dist 6.4.299`(Apache-2.0)을 사용해요. 로컬 PDF Worker와 CMap, 표준 글꼴, OpenJPEG/JBIG2/QCMS WASM·대체 스크립트, ICC 자산을 동봉해요. CMap·Foxit 글꼴은 BSD-3-Clause, ICC는 CC0이며 LiberationSans 1.07.4의 네 글꼴은 GPL-2.0 및 Liberation 글꼴 예외로 별도 승인됐어요. 각 원문과 출처·해시는 생성된 `src/generated/pdf-resources.json` 및 배포본 `pdf-assets/THIRD-PARTY.json`에 담으며 빌드에서 자산을 대조해요. CDN이나 외부 폰트 요청은 하지 않아요.

## 검증 범위

합성 XLSX/HWP/HWPX와 정확 매칭·수백 행·금지 이름·SDK 청크 복사·취소·재시도·화면 확인 흐름을 검사했어요. 실제 Windows 합성 파일로 이름 교환·대소문자·이름 길이·재시작 되돌리기·중단 복구·동일 바이트와 시각의 대체 파일·목적지 충돌·원본 잠금·캡 소유자·한도를 검사해요. 브라우저의 합성 SDK 호스트 확인과 실제 Tauri 네이티브 확인창 검수는 구분하며 최종 통합 검증은 루트 담당이 수행해요.
