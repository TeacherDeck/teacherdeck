# 자리 배치

번호·이름 명단을 입력하고 교실 구조와 꼭 지킬 조건을 정해 자리를 배치해요. 공통 명부가 아직 연결되지 않은 환경에서는 이번 작업 명단을 이 도구 안에만 보관해요.

TeacherDeck 0.3.0 이상에서는 공유 승인 후 설정의 공통 명부를 불러와요. 기다리는 동안 확정한 자리 이력은 최신 작업에 보존해요. 명단이 바뀌거나 다른 저장이 진행 중이면 응답을 적용하지 않고 다시 읽도록 안내해요. 기존 작업에서는 공통 명부 입력을 접어 배치를 먼저 살펴봐요.

1. 명단을 직접 붙여 넣거나 UTF-8 텍스트 파일을 읽고 적용해요. 한 줄에 번호와 이름을 넣어요.
2. 행·열과 앞줄 범위를 정하고 통로를 표시해요. `비워둘 자리 지정`을 켜서 사용할 수 없는 자리를 눌러요.
3. 학생별 고정·제외·앞줄 조건을 정해요. 학생 조건은 번호·이름으로 찾고 10명씩 확인해요. 가까이 앉지 않을 학생도 선택할 수 있어요.
4. 새 배치를 만들고 두 자리 클릭 또는 끌기·놓기로 직접 교환해요. 모든 직접 교환에도 같은 필수 조건을 적용해요. 교사 시점으로 돌려 볼 수 있어요.
5. 검토한 배치를 확정해요. 확정본을 골라 학생 보기, 복사용 텍스트, 학생용 파일로 공개해요. 교사 조건과 사유는 공개하지 않아요.

고정·제외가 충돌하거나 앞줄 자리가 부족하면 원인을 알려요. 조건을 자동으로 풀지 않아요. 분리 조건은 가로·세로·대각선 한 칸 이내를 피하며 통로가 있어도 가까운 자리로 계산해요. 지난 옆자리 반복은 통로를 건너지 않는 가로 이웃만 계산해요. 지난 자리·옆자리 반복 줄이기는 필수 조건 다음에 적용하는 선호 조건이에요. 반복이 전혀 없는 결과를 보장하지는 않아요.

최대 1000명, 행·열 각각 100 이내, 전체 1000자리까지 지원해요. 큰 교실은 가로·세로 스크롤로 살펴봐요. 분리 조건이 없는 배치는 좌석 큐로 처리해요. 분리 조건 탐색은 5000회 후보 확인에서 멈추며, 탐색 한도와 조건 불가능을 구분해요. 한도에 닿아도 입력 조건은 유지해요.

확정 기록은 최대 100개예요. 번호나 이름을 바꿔도 과거 확정본에는 당시 학생 이름과 교실 구조가 남아요. 같은 번호와 같은 이름일 때만 현재 작업 학생 식별자를 유지해요. 열 수를 바꿀 때는 고정·비워둘 자리의 좌표를 보존하며, 사라지는 조건은 먼저 직접 수정해야 해요.

`storage` 1.0, `fs` 1.0, `window` 1.0을 사용해요. 명단·기록은 PC 안에 저장해요. 기록 파일과 학생용 파일은 선택한 폴더 안에 새 출력 폴더를 만들어 저장하므로 원본을 덮어쓰지 않아요. 읽는 파일은 5MB 이하이며 저장 한도는 직렬화한 저장 조각 합계 2MB예요. 한도를 넘는 기록은 자르지 않아요. 먼저 파일로 보관한 뒤 새 작업을 시작해 주세요.

저장은 두 세대로 나누고 현재 기록을 가리키는 값을 마지막에 바꿔요. 각 저장 값은 256KiB 미만이며 전체 모듈 저장소를 5MB 안에서 사전 점검해요. 저장 조각·현재 기록 전환 실패는 이전 세대를 유지해요. 전환 후 응답만 실패하면 현재 세대를 다시 읽어 성공 여부를 판단해요. 판단할 수 없으면 편집을 잠그고 `저장 기록 다시 확인`으로 복구해요. 손상된 저장 자료는 확인 없는 초기화를 하지 않으며 기록 파일 가져오기 또는 새 작업 확인으로 복구해요.

원작 참고: 우리반스튜디오의 `generateSeats`, `seatErrors`, `swapSeats`, `commitSeats`, 공개·비교·교사 시점 흐름과 오늘의교실의 조건을 지키는 직접 이동 흐름을 읽고 재구현했어요. 우리반스튜디오 `src/core.js` SHA-256은 `bac0f25907f086511bd528fd9a6724557237a8b3a9093c1b8c77c89beb4c700a`예요. 원작의 자료 형식을 그대로 가져오는 도구는 아니며 배치 난수·최적화 결과가 같은 이식은 아니에요. 원작 시연 명단은 사용하지 않았어요.

검증은 `src/logic.test.ts`의 필수 조건·분리·교환·이력·500/1000명 성능, `src/state.test.ts`의 SDK 저장·실패·파일 취소, `src/App.test.tsx`의 명단부터 확정·공개·복구·대규모 조건 검색까지 실행해요. 화면의 실제 렌더 검수와 전체 `pnpm verify`는 통합 담당자가 수행해요.

window 1.1 이상에서는 **확장 학생 화면**에서 모니터를 선택해 확정본의 이름·번호·자리만 별도 학생 창에 표시한다. 보조 화면을 우선 선택하며 열기·갱신 버튼을 눌러야 변경을 반영한다. 미확정 배치는 공개하지 않고 기존 화면 복제용 학생 보기·파일 출력도 유지한다. 연결·배율 변경은 공개 자료를 비워 화면 재선택을 요청하며, 닫힌 창은 다시 열 수 있다. 학생 기기 접속은 제공하지 않는다.

확장 화면 검증: 공개 자료 화이트리스트·명시 갱신·revision·연결 해제·닫힘·늦은 응답 회귀를 합성 테스트로 검사한다. 실제 여러 모니터·Windows DPI·확장 창 배치는 별도 통합 검증 대상이다.
