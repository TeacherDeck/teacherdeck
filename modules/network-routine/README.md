# 네트워크 루틴

원본 `network_routine` 1.4.0의 시간표·Wi-Fi 판단, 야간 구간, 수동 선택 우선 구간과 여섯 자동 트리거를 하나의 화면으로 제공한다. 출처와 원본 SHA는 [원본 대조 기록](../../docs/reviews/network-routine-parity.md)에 있다.

어댑터를 선택하고 내부 주소/마스크 또는 DNS만 입력한다. 요일별 시간표, Wi-Fi 이름 우선/전용 판단을 설정한 뒤 저장한다. 실제 전환과 자동 작업 등록은 제한된 Windows 관리자 승인 작업자로 실행한다. 저장하지 않은 편집값은 자동 실행이나 수동 전환에 쓰지 않는다. 외부망 전환은 IP와 DNS를 DHCP로 복원한다. 수동 전환이 성공하면 같은 판단 구간에서 그 선택을 유지하고 구간이 바뀌면 자동 판단을 다시 사용한다.

자동화는 부팅·로그온·잠금 해제·콘솔 복귀·Wi-Fi 연결/해제·시간표 경계의 고정 작업만 사용한다. 원본 프로그램의 자동 작업을 발견하면 알림을 표시하며 지우지 않는다. 앱 업데이트/설치 위치/실행파일 해시가 달라지면 자동 루틴이 정상으로 표시되지 않고 다시 켜서 저장하도록 안내한다. 실행마다 소유 모듈의 현재 설치/권한과 revision을 재검사한다. OS 적용에 실패하거나 UAC를 취소하면 성공/수동 우선 상태를 기록하지 않는다.

새 런타임 의존성은 없다. 모듈은 `network` 1.0과 공개 SDK만 사용한다. Windows 위치 권한이 없거나 Wi-Fi 전용 판단이 모호하면 현재 네트워크를 유지한다. 관리자 권한이 없는 계정에서는 조회/편집을 사용할 수 있으며 실제 전환은 해당 PC의 승인 정책을 따른다.

순수 엔진 원본 차등 180개를 포함한 204개, cap 매핑, SDK mock 화면 검사로 검증한다. 실제 PC의 IP 변경, 자동 작업 등록/해제, 재부팅 시험은 개발 검증에서 하지 않는다. 별도의 허용된 시험 PC에서 OS 동작을 추가 검증해야 한다.

외부 모드 적용 뒤에는 주소 DHCP와 DNS 자동 설정을 함께 확인하고, 내부 주소를 지정하면 해당 주소의 마스크와 선택한 게이트웨이를 확인한다. 공개 조회에 없는 값을 같은 상태로 추정하지 않는다. 같은 작업의 겹친 실행은 Windows 작업 대기열로 처리하며, 다른 트리거가 잠금을 사용 중이면 최대 90초 기다린 뒤 최신 설정·시각·Wi-Fi를 읽는다. 대기 한도를 넘은 실행은 성공으로 기록하지 않는다. 실제 OS 변경 검증은 별도 허용된 시험 PC에서 진행한다.
